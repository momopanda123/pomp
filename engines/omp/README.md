# POMP의 omp 엔진

VSIX에는 [oh-my-pi](https://github.com/can1357/oh-my-pi) **v18.22.2** 소스(커밋 `e1ae2cc998efd1ca151b46ebefc0e0dab6c23c63`)에
[`pomp-v18.22.2.patch`](pomp-v18.22.2.patch)를 적용해 빌드한 Windows x64 `omp.exe`가 들어간다. 기존 POMP 패치는 새 Win32 창을 여는
`takeover` 클릭과, 다른 앱이 앞에 있을 때의 첫 `takeover`·`raise` 창 활성화를 고친다(Windows는 마지막 입력을 보낸 프로세스에만
포그라운드를 넘기므로, 활성화 직전 이동 거리 0인 마우스 입력 하나로 그 권한을 얻는다). 또 모델 공유용 auth gateway의 `/v1/models`
행마다 그 모델의 노력 단계(`reasoning_efforts`)를 넣는다. 공유 PC가 실행 중에 찾은 모델은 연결한 PC의 카탈로그에 없어서, 이 목록이
없으면 그 모델의 추론 단계를 고를 수 없다. 18.12.6 패치에 있던 Codex 하위 에이전트의 진행 중 메시지 처리는 상위가 고쳐서 뺐다(GPT
실시간 조정은 기본 꺼짐, 다음 도구 경계까지 기다림). 공식 릴리스 실행 파일을 대신 담으면 안 된다.
`engine.props`의 크기·SHA-256을 VSIX 빌드와 POMP 시작 시 모두 검증한다. MIT `LICENSE.upstream`과 함께, 태그에서 만든 고지
파일 `THIRD-PARTY-NOTICES.txt`(`omp --license`가 출력하는 내용: OMP 라이선스, CLI와 네이티브 애드온의 고지)도 별도 해시로
검증해 패키지에 넣는다. 18.13부터 릴리스에 고지 파일이 따로 없다. 정책은 `docs/architecture.md` §4 "엔진 버전" 참조.

깨끗한 작업 트리에서 `build/build-omp.ps1`을 실행하려면 Git, Bun 1.4.4+, Rust/Cargo(MSVC x64), Visual Studio C++
빌드 도구가 필요하다. 스크립트가 고정 커밋을 가져와 패치를 적용하고 네이티브 애드온과 실행 파일을 만든 뒤
`artifacts/engines/omp/18.22.2/`에 보관한다. `build/build.ps1`도 캐시가 없거나 해시가 다르면 이 스크립트를 실행한다.
버전을 올릴 때는 소스 커밋·패치·빌드 스크립트·`engine.props`의 크기/해시/출처를 함께 갱신하고 실제 동작을 검증한다.

18.21.0에서는 격리된 홈의 `--version`·`--smoke-test`와 내장 고지 일치를 확인했다. POMP 확장 명령 23개를 로드한
로컬 테스트 공급자 RPC 두 턴에서 `agent_end`·`prompt_result`·`session_settled`와 유휴 상태를 확인했다.
MCP 권한 우회 거부·오래된 편집 기준 보호·명령 취소 후 재사용·연결 종료 정리 검사 4개와 공유 모델 추론 단계 검사를 통과했다.
이 초기 엔진 검증에는 실계정 모델 요청이나 VS 설치·로그인을 사용하지 않았다. GPT-6.2 수정 후 실계정 검증은 아래에 별도로 기록한다.

기존 18.20.0 엔진 업데이트 검증에서는 상위 CI처럼 `HOME`·`USERPROFILE`·`LOCALAPPDATA`·`XDG_DATA_HOME`을 임시 폴더로 격리한
`omp --smoke-test`를 통과했다. POMP 확장을 로드한 격리 RPC에서도 `pomp-*` 명령 23개, 읽기·승인 후 bash 실행,
생각 수준 선택, 미지원 모델의 빠른 모드 거부, 네 상태의 계획 저장, `/context`의 지시 파일 행과 사용량 출력을 확인했다.
공유 모델 목록의 노력 단계와 실행 파일 내 고지도 확인했다. 계획·컨텍스트 호스트 검사 61개와 계획 UI 검사 3개를 통과했고,
실제 웹 화면에서 작업 추가·저장을 확인했다. 당시 VS 설치·로그인이나 실제 공급자 호출은 다시 시험하지 않았다.

POMP는 엔진이 광고하는 경우에만 쓰는 선택 기능(`pompControlVersion`, `pomp_terminal` 등)을 지원하지만,
이 패치는 해당 기능을 추가하지 않으므로 번들 엔진에서는 꺼져 있다.

## 18.22.2로 올릴 때

- GPT-6.2 Astra·Sol 지원과 Codex 클라이언트 버전 갱신이 상위에 포함되어 별도 백포트 패치를 제거했다. 기본·오프라인 Codex 버전은 `0.169.0`이며 상위 구현이 실행 중 최신 버전을 조회한다.
- 바이너리 분석은 `ida`·`ghidra` 대신 `dsm` 네임스페이스를 쓴다. MCP의 이전 `ida.enabled=false` 설정은 `disassembler.backend=none`으로 바꿨다. 실행 파일 메타데이터만 읽고 분석 백엔드 실행·자동 다운로드는 허용하지 않는다.
- 상위 RPC의 로그인 위험 확인 전달과 사용량 초과 후 `agent_end` 지연 수정이 포함된다. POMP의 RPC 계약은 유지한다.
- `antigravity-cli` 공급자의 카탈로그에 `paste-code`를 선언한다. RPC는 로그인 경고에 사용자가 동의한 뒤 `open_url`과 코드 입력 요청을 보낸다. 패치를 적용한 빌드는 카탈로그를 재생성한다. 다른 공급자의 비밀 입력 정책은 바꾸지 않는다.
- 격리된 프로필에서 18.22.2 실행 파일의 `--version`·`--smoke-test`·`--license`를 검증했다. 로컬 공급자와 연결한 RPC v2에서 POMP 명령 24개가 등록됐고, 두 턴 모두 확장 오류 없이 응답한 뒤 유휴 상태로 돌아왔다. 실계정 모델은 호출하지 않았다.
- [상위 18.22.2 릴리스](https://github.com/can1357/oh-my-pi/releases/tag/v18.22.2)와 [변경 기록](https://github.com/can1357/oh-my-pi/blob/v18.22.2/packages/coding-agent/CHANGELOG.md)에 전체 변경 사항이 있다.

## POMP 0.6.3의 GPT-6.2 지원

- 당시 검증된 18.21.0을 유지하고 상위 [커밋 `2dedb850`](https://github.com/can1357/oh-my-pi/commit/2dedb850ac86e73aadc385e5b9cf08eac096e475)의 GPT-6.2 Astra·Sol 지원을 백포트했다. 당시에는 18.22.0의 별도 기능 변경을 포함하지 않았다. 현재 18.22.2 빌드는 상위 지원을 직접 사용한다.
- 초기 백포트에서 누락된 선행 [커밋 `f54745ac`](https://github.com/can1357/oh-my-pi/commit/f54745ac235b89ce2775616a7f44275bbdf7b300)의 Codex 클라이언트 버전 갱신도 반영했다. 기존 `0.159.0`은 두 모델의 서버 최소 버전 `0.166.0`보다 낮아 모델 목록에서 제외됐다. 공통 `CODEX_CLIENT_VERSION`을 `0.169.0`으로 고정해 모델 조회·응답 요청·캐시 키가 함께 갱신되며, 기존 캐시를 수동 삭제하거나 다른 모델로 대체하지 않는다.
- OpenAI API 카탈로그에 `gpt-6.2-astra`·`gpt-6.2-sol` 두 행만 추가했다. 다른 모델 행은 보존하며, 컨텍스트 1,050,000·최대 출력 128,000 토큰과 272,000 입력 토큰 초과 가격 구간을 반영한다.
- Codex는 서버가 실제 제공한 모델과 `-wm` 경로에 가격·유료 플랜 자격·Fast 2배/Ultrafast 6배 사용량 배율을 적용한다. 일반 컨텍스트는 그대로 두고 확장 컨텍스트의 최대값을 922,000으로 보완하며, 서버가 더 큰 최대값을 제공하면 그 값을 유지한다.
- API Ultrafast 3배는 상위 커밋의 2027-02-28까지 설정이다. 2027-03-01 이후 6배 변경은 추가 엔진 업데이트가 필요하다. 실제 사용 가능 모델·한도·청구는 공급자와 계정 정책을 따른다.
- 당시 KDL 호환 규칙과 컴파일 결과를 함께 백포트하고 실행 파일의 크기·해시를 다시 고정했다. 이 별도 패치는 18.22.2 업데이트에서 제거했다.
- 검증: 최소 클라이언트 버전으로 모델 제공을 제한하는 서버의 회귀 사례를 포함해 Codex 테스트 25개(96개 검증)가 통과했다. 초기 백포트의 별도 스모크로 가격 경계·서비스 티어 하향 응답·유료 플랜 규칙·922,000 최대값과 더 큰 서버 한도의 우선순위를 확인했다.
- 초기 백포트 검증에서는 당시 실행 파일의 `--version`·`--smoke-test`·`--license`와 POMP 명령 23개의 등록을 확인했다. 격리 프로필·로컬 모의 Responses API로 Astra 모델 선택, 확장 컨텍스트 1,050,000, high 추론, Fast priority 요청, 스트리밍 응답과 RPC settled 상태를 검증했다. 이 단계에는 실계정 요청을 포함하지 않았다.
- 클라이언트 버전 수정 후 재빌드한 실행 파일에서 실제 Codex 계정의 모델 목록에 두 모델이 표시됨을 확인했다. `openai-codex/gpt-6.2-astra`와 `openai-codex/gpt-6.2-sol`을 각각 지정한 최소 프롬프트가 모두 `OK`를 반환하고 정상 종료했다. 도구·확장·컨텍스트 파일·세션 저장을 끈 검증이며, VS 설치·재로그인은 수행하지 않았다.

## 18.21.0으로 올릴 때

- 상위 `AgentSession` SDK는 실행 종료와 백그라운드 대기를 구분하도록 수명 주기 API를 바꿨다. RPC와 확장 스트림은 기존 루프별 `agent_end`를 유지한다. POMP가 읽는 RPC `hasPendingAsyncWork`·`isSettled`도 유지되므로 SDK API를 직접 호출하는 것으로 바꾸지 않는다.
- 알려지지 않은 커스텀·검색 모델의 추론 지원은 첫 요청 시 별도 탐색 요청으로 확인하고 결과를 기억한다. 따라서 사용자 대화 턴 수보다 공급자 요청 수가 많을 수 있다.
- 파일 변경 이력 기록과 셸 URL 쓰기 처리의 상위 변경에 맞춰 로컬 패치를 재적용했다. 편집 취소는 파일 스냅샷을 읽은 뒤 실제 변경 직전에 확인하며, 격리 셸에서는 내부 URL 파일시스템을 연결하지 않는다.
- [상위 18.21.0 릴리스](https://github.com/can1357/oh-my-pi/releases/tag/v18.21.0)에 전체 변경 사항이 있다.

## 18.20.0으로 올릴 때

- 작업 계획은 `pending`, `in_progress`, `completed`, `abandoned` 네 상태만 쓴다. 상위 엔진이 없앤 `blocked` 상태와 차단 사유 편집은 POMP에서도 제거했다. 기존 차단 작업은 엔진이 대화에서 복원할 때 대기 상태로 바꾼다.
- 사용자 `secrets.yml`의 정규식은 이제 Rust `regex` 문법이다. 전후방 탐색·역참조는 지원하지 않으며, 잘못된 규칙은 시작을 중단한다. 예를 들어 `(?<=password=)\S+`는 `password=(?P<secret>\S+)`로 바꾼다.
- 이전 대화의 `$$NAME_HASH:CASE$$` 비밀값 자리표시는 새 엔진에서 그대로인 문자열이다. 비밀값 치환이 필요한 작업은 새 대화에서 시작한다.
- 자세한 변경 사항은 [상위 18.20.0 변경 기록](https://github.com/can1357/oh-my-pi/blob/v18.20.0/packages/coding-agent/CHANGELOG.md)을 참고한다.
