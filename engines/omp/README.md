# POMP의 omp 엔진

VSIX에는 [oh-my-pi](https://github.com/can1357/oh-my-pi) **v18.20.0** 소스(커밋 `c308970263ae13744ea15ab67302e3dac840e266`)에
[`pomp-v18.20.0.patch`](pomp-v18.20.0.patch)를 적용해 빌드한 Windows x64 `omp.exe`가 들어간다. 패치는 새 Win32 창을 여는
`takeover` 클릭과, 다른 앱이 앞에 있을 때의 첫 `takeover`·`raise` 창 활성화를 고친다(Windows는 마지막 입력을 보낸 프로세스에만
포그라운드를 넘기므로, 활성화 직전 이동 거리 0인 마우스 입력 하나로 그 권한을 얻는다). 또 모델 공유용 auth gateway의 `/v1/models`
행마다 그 모델의 노력 단계(`reasoning_efforts`)를 넣는다. 공유 PC가 실행 중에 찾은 모델은 연결한 PC의 카탈로그에 없어서, 이 목록이
없으면 그 모델의 추론 단계를 고를 수 없다. 18.12.6 패치에 있던 Codex 하위 에이전트의 진행 중 메시지 처리는 상위가 고쳐서 뺐다(GPT
실시간 조정은 기본 꺼짐, 다음 도구 경계까지 기다림). 공식 릴리스 실행 파일을 대신 담으면 안 된다.
`engine.props`의 크기·SHA-256을 VSIX 빌드와 POMP 시작 시 모두 검증한다. MIT `LICENSE.upstream`과 함께, 태그에서 만든 고지
파일 `THIRD-PARTY-NOTICES.txt`(`omp --license`가 출력하는 내용: OMP 라이선스, CLI와 네이티브 애드온의 고지)도 별도 해시로
검증해 패키지에 넣는다. 18.13부터 릴리스에 고지 파일이 따로 없다. 정책은 `docs/architecture.md` §4 "엔진 버전" 참조.

깨끗한 작업 트리에서 `build/build-omp.ps1`을 실행하려면 Git, Bun 1.4.4+, Rust/Cargo(MSVC x64), Visual Studio C++
빌드 도구가 필요하다. 스크립트가 고정 커밋을 가져와 패치를 적용하고 네이티브 애드온과 실행 파일을 만든 뒤
`artifacts/engines/omp/18.20.0/`에 보관한다. `build/build.ps1`도 캐시가 없거나 해시가 다르면 이 스크립트를 실행한다.
버전을 올릴 때는 소스 커밋·패치·빌드 스크립트·`engine.props`의 크기/해시/출처를 함께 갱신하고 실제 동작을 검증한다.

기존 18.20.0 엔진 업데이트 검증에서는 상위 CI처럼 `HOME`·`USERPROFILE`·`LOCALAPPDATA`·`XDG_DATA_HOME`을 임시 폴더로 격리한
`omp --smoke-test`를 통과했다. POMP 확장을 로드한 격리 RPC에서도 `pomp-*` 명령 23개, 읽기·승인 후 bash 실행,
생각 수준 선택, 미지원 모델의 빠른 모드 거부, 네 상태의 계획 저장, `/context`의 지시 파일 행과 사용량 출력을 확인했다.
공유 모델 목록의 노력 단계와 실행 파일 내 고지도 확인했다. 계획·컨텍스트 호스트 검사 61개와 계획 UI 검사 3개를 통과했고,
실제 웹 화면에서 작업 추가·저장을 확인했다. 이번 업데이트에서는 VS 설치·로그인이나 실제 공급자 호출은 다시 시험하지 않았다.

POMP는 엔진이 광고하는 경우에만 쓰는 선택 기능(`pompControlVersion`, `pomp_terminal` 등)을 지원하지만,
이 패치는 해당 기능을 추가하지 않으므로 번들 엔진에서는 꺼져 있다.

## 18.20.0으로 올릴 때

- 작업 계획은 `pending`, `in_progress`, `completed`, `abandoned` 네 상태만 쓴다. 상위 엔진이 없앤 `blocked` 상태와 차단 사유 편집은 POMP에서도 제거했다. 기존 차단 작업은 엔진이 대화에서 복원할 때 대기 상태로 바꾼다.
- 사용자 `secrets.yml`의 정규식은 이제 Rust `regex` 문법이다. 전후방 탐색·역참조는 지원하지 않으며, 잘못된 규칙은 시작을 중단한다. 예를 들어 `(?<=password=)\S+`는 `password=(?P<secret>\S+)`로 바꾼다.
- 이전 대화의 `$$NAME_HASH:CASE$$` 비밀값 자리표시는 새 엔진에서 그대로인 문자열이다. 비밀값 치환이 필요한 작업은 새 대화에서 시작한다.
- 자세한 변경 사항은 [상위 18.20.0 변경 기록](https://github.com/can1357/oh-my-pi/blob/v18.20.0/packages/coding-agent/CHANGELOG.md)을 참고한다.

## 공식 Antigravity 앱·CLI에 OMP 도구 연결

기존 POMP 프로바이더·OAuth 경로를 바꾸지 않는 **별도 로컬 MCP 서버**다. 추론과 모델 호출은 공식 Antigravity 앱 또는 `agy` 대화형 CLI가 담당하고,
공식 클라이언트가 stdio MCP로 OMP의 실제 파일·셸 도구를 호출한다. POMP 채팅의 새 프로바이더나 `agy -p` 대리 실행 기능이 아니다.
서버 자체는 모델 요청, OAuth 로그인·토큰 갱신, MCP sampling을 하지 않는다. 기존 계정·프로바이더 설정도 수정하지 않는다.

패치의 `mcp-server` 진입점은 일반 프로필·에이전트 초기화 전에 분기한다. 빌드 시 `src/Pomp.McpServer/*.ts`를 엔진의
`packages/coding-agent/src/pomp-mcp/`에 넣으며, 기존 네이티브 도구를 격리된 설정과 편집 스냅샷으로 실행한다.

### 연결

POMP의 **도구 → MCP → Antigravity · POMP 도구 → 자동 설정**을 사용한다.

- 공식 앱 또는 `agy` CLI 설치를 감지한다. CLI는 기본 설치 폴더와 PATH에서도 찾으므로 데스크톱 앱이 없어도 된다.
- 화면의 작업 폴더와 파일 편집·OS 명령 실행 권한을 확인한다. 검증된 POMP 번들 엔진만 등록한다.
- 앱·CLI 공용 `~/.gemini/config/mcp_config.json`에 작업 폴더별 `pomp_<해시>` 항목을 병합한다. 다른 서버·설정·비밀 값은 보존하며, 빈 파일은 초기 설정으로 처리한다.
- 반복 실행은 동일 설정을 다시 쓰지 않는다. 잘못된 JSON, 중복 키, 다른 서버와의 충돌, 확인 후 파일·작업 폴더 변경은 덮어쓰지 않고 거절한다.
- POMP 프로바이더 로그인 전이나 채팅 응답 중에도 사용할 수 있다. 앱·CLI·엔진을 대신 실행하거나 재시작하지 않는다.
- **설정됨 · 연결 미확인**은 파일 저장 상태다. 공식 앱의 MCP 관리 또는 `agy`의 `/mcp`에서 연결을 확인한다. 새 서버가 목록에 없으면 CLI를 다시 실행한다.

수동 연결 JSON이 필요한 경우:

저장소 루트에서 다음 PowerShell 명령으로 **현재 실행 파일과 작업 폴더에 맞는 연결 JSON**을 출력한다.

```powershell
.\artifacts\engines\omp\18.20.0\omp.exe mcp-server --cwd "C:\Project\my-project" --allow-write --allow-exec --print-config
```

`--cwd`에는 실제로 존재하는 절대 경로를 지정한다. `--print-config`는 설정을 출력할 뿐 앱 설정 파일을 수정하거나 서버를 시작하지 않는다.
VSIX에 포함된 `omp.exe`도 같은 명령을 지원한다. `--help`로 옵션을 볼 수 있다.

1. Antigravity 앱의 **Customizations → Installed → MCP Servers → Copy Config File Path**로 설정 파일 위치를 찾는다.
   IDE 버전에서는 **MCP Servers → Manage MCP Servers → View raw config**를 사용한다.
2. 출력된 JSON의 `mcpServers.pomp` 항목만 기존 설정에 병합한다. 다른 MCP 서버를 지우거나 설정 파일 전체를 덮어쓰지 않는다.
3. 서버를 새로고침/재시작한 뒤 공식 앱 또는 `agy` 대화형 CLI에서 도구 사용을 승인한다. 공식 클라이언트가 `omp.exe`를 자식 프로세스로 실행하므로 별도 서버 실행이나 포트 개방은 필요 없다.

[공식 Antigravity MCP 문서](https://antigravity.google/docs/mcp)는 앱·CLI 공용 전역 설정과 CLI의 `<workspace>/.agents/mcp_config.json`, `command`·`args` 기반 stdio 연결을 안내한다.
생성된 설정은 도구 호출 제한 시간을 600초로 지정한다.

### 권한과 지원 범위

- 기본값: `read`, `glob`, `grep`. `--allow-write`는 `edit`, `write`를, `--allow-exec`는 `bash`를 추가한다.
  비활성 도구는 직접 `tools/call`로 요청해도 실행되지 않는다.
- `edit`는 `{ "patch": "..." }`로 OMP 원래 해시라인 패치를 받는다. 먼저 `read`가 돌려준 스냅샷을 사용하며, 그 뒤 바뀐 파일을 오래된 기준으로 덮어쓰지 않는다.
- 로컬 파일, 디렉터리, 문서/PDF 텍스트, 래스터/SVG 이미지를 지원한다. 잘린 출력은 해당 서버 연결이 만든 `artifact://` ID로 다시 읽는다.
- 외부/내부 URL, UNC 경로, 읽기 쿼리 선택자, 이미지에 대한 모델 질문, 브라우저 기반 PDF 페이지 캡처, 영상·외부 HEIF/AVIF 변환은 제공하지 않는다.
  오디오는 자동 전사하지 않는다. 프로젝트 플러그인, 다른 MCP 서버, LSP 및 모델 기반 편집 복구도 자동 시작하지 않는다.
- 셸 호출은 요청 단위로 결과를 기다린다. OMP의 `async`·이름 있는 서비스·PTY 인터페이스는 노출하지 않으며 셸 프로필·direnv를 자동 로드하지 않는다.
  취소 알림은 실행 중인 호출에 전달하고, 연결 종료 시 대기/실행 중인 호출과 소유한 셸·임시 출력을 정리한다.
  이미 완료된 파일 변경은 취소로 되돌리지 않는다.
- **`--cwd`는 기준 폴더이지 보안 샌드박스가 아니다.** 파일 도구는 OS 권한 내의 다른 로컬 경로에도 접근할 수 있다.
  `--allow-exec`는 파일 변경·네트워크 접근·외부 프로그램 실행을 포함한 OS 사용자 권한을 부여하며, 명령이 명시적으로 분리 실행한 외부 프로세스까지 격리하지 않는다.
  신뢰하는 클라이언트에서 필요한 권한만 켠다.

### 계정 제한에 관한 경계

공식 MCP·ACP 지원은 **계정 제한이 절대 없다는 보장**이 아니다. OMP MCP 서버 자체에는 추론 기능이 없으며,
OAuth 프록시·예약 추론 봇을 제공하지 않는다. 아래 POMP 채팅 연결은 공식 `agy acp` 프로토콜을 사용한다.
허용한 셸에서 다시 `agy -p` 또는 모델 프록시를 실행하면 이 연결의 경계를 벗어난다. 기존 OAuth 프로바이더를 계속 쓰는 경로의 위험도 이 기능이 제거하지 않는다.

실행 파일로 권한 우회 거부, 오래된 편집 기준 보호, 명령 취소 후 재사용, 연결 종료 시 자식 프로세스 정리 검사 4개를 통과했다.
기존 네이티브 셸 호환 검사 3개와 독립 OMP MCP 클라이언트의 실제 파일·편집·검색·명령·이미지 호출, 설정 생성 및 일반 프로필 CLI도 확인했다.
원클릭 설정의 설치 감지·기존 항목 보존·오래된 스냅샷 거절·CLI 전용 설치·엔진 정지/응답 중 동작 검사 28개를 통과했다.
실제 `agy` 1.5.9에서 자동 생성된 전역 설정 인식과 POMP의 도구 6개 연결을 확인했다.
실계정 자동 검증은 사용자 요청에 따라 도구 승인 대기에서 중단했다. 실제 모델의 파일 수정·셸 실행은 아직 검증하지 않았으며, 계정 정책 집행이나 제한 위험을 보장하는 검사도 아니다.

## POMP 채팅에서 공식 Antigravity ACP 사용

채팅 상단의 **OMP / Antigravity ACP** 선택에서 **Antigravity ACP**를 고른다. 실제 프로젝트 폴더, 공식 `agy` CLI와 검증된 번들 엔진이 필요하다. 기존 OMP 프로바이더·계정과 별도이며 첫 OMP 로그인 전에도 선택할 수 있다.

- POMP가 `agy acp`를 stdio로 실행하고 자신을 `pomp` 클라이언트로 식별한다. `agy -p`, 키보드 자동 입력, 다른 IDE 신원 사용, OAuth 토큰 가져오기는 하지 않는다.
- 각 ACP 세션의 `mcpServers`에 `omp.exe mcp-server --cwd <프로젝트> --allow-write --allow-exec`를 전달한다. `read`, `glob`, `grep`, `edit`, `write`, `bash`를 유지하며 전역 MCP 설정을 바꿀 필요가 없다.
- 로그인 방법·모델·추론 수준·모드는 공식 CLI가 실제 제공한 값을 표시한다. 승인은 CLI가 보낸 요청 내용과 선택지 그대로 처리한다. OMP의 저장된 승인 규칙을 대신 적용하지 않는다.
- 일반 추가 입력은 대기열에서 기다리고 명시적 **steer**만 진행 중 프롬프트에 보낸다. 모든 진행 중 프롬프트 응답이 끝나야 다음 대기 항목을 보낸다. 중지·연결 종료·실패 시 대기열은 일시정지하며 자동 재전송하지 않는다.
- 대화별 입력·첨부·계획·승인을 분리한다. 계획은 읽기 전용이며 변경은 대화로 요청한다. 지원하는 기록 조회·복원·탭 닫기만 제공하고, 복원 실패를 새 대화로 바꾸지 않는다. 현재 CLI에는 기록 삭제·이름 변경·압축 API가 없어 해당 동작을 제공하지 않는다.
- 편집기 컨텍스트와 파일 링크를 보낼 수 있다. 이미지 입력은 CLI가 지원할 때 PNG/JPEG/GIF/WebP 합계 5 MiB까지다. 이미지 출력은 현재 채팅 렌더러에서 텍스트 표시다. OMP 네이티브 에이전트·팀·인라인 AI 기능은 OMP 연결에서 사용한다.
- **descriptor configured**는 세션에 도구 실행 정보를 전달했다는 뜻이지 실제 도구 호출 성공 표시가 아니다. 파일·셸 권한과 샌드박스가 아닌 작업 폴더의 의미는 위와 같다.

[공식 ACP 연결 안내](https://antigravity.google/docs/ide/extensions/acp), [CLI ACP 안내](https://antigravity.google/docs/cli/acp).
모델 목록에 표시되는 것과 실제 사용 권한·추론 성공은 다르다. 공식 문서는 일반 ACP 클라이언트와 일부 지정 IDE의 모델 제공 범위를 구분하며, POMP는 지정 IDE로 위장하지 않는다.

실제 `agy` 1.5.9와 POMP 호스트·웹 화면으로 세션 생성, 공식 구성 옵션 조회와 추론 수준 변경/복원을 확인했다.
실계정 모델 프롬프트는 자동 전송하지 않았다. 실제 모델을 통한 OMP 도구 실행·취소는 사용자가 대화에서 직접 승인하여 확인해야 하며, 이 확인으로 계정 제재 가능성이 없다고 보장할 수는 없다.
