# 설정 안내

POMP의 설정은 Visual Studio의 **도구 > 옵션 > Pomp > 일반**에 있다(영어 페이지 이름은 **General**). 옵션 화면의 분류와 항목 이름은 POMP 언어(한국어·영어)를 따르며, 아래 제목은
한국어 이름(영어 이름, 분류)이다. 옵션 화면과 POMP 창에는 설명 문구를 두지 않으며,
각 설정의 목적·기본값·적용 범위·다시 시작 여부는 이 문서에 정리한다.

## 규칙

### 규칙 파일 열기 (`Open rule file in VS editor`, Rules)

- 목적: 기존 .mdc 규칙 파일을 VS 편집기로 여는 선택기예요. 파일을 만들거나 고치지 않아요.
- 기본값: 비어 있음
- 적용 범위: 동작
- 다시 시작: 옵션을 적용하면 바로 반영된다.
- 비용·보안: 저장된 규칙은 다음 프롬프트부터 다시 평가돼요. 권한 정책 편집기가 아니에요.

## 에이전트

### 승인 모드 (`Approval mode`, Agent)

- 목적: 기본 도구의 승인 방식이에요. VS 도구 승인은 같은 모드를 따르되, 저장된 허용(도구 › 권한 › 허용한 작업)은 별도로 동작해요.
  - Always ask(항상 묻기): 승인이 필요한 VS 도구는 매번 물어요.
  - Auto-write(쓰기 자동): VS의 파일·프로젝트·중단점·북마크 변경은 자동 승인하고, 프로세스 실행·테스트·디버거·Git·패키지 변경은 물어요.
  - Auto-all(모두 자동): VS 도구를 모두 자동 승인해요. 강제로 묻는 것(위험한 명령, 공급자 안전 확인)은 그대로 물어요.
- 기본값: Always ask (쓰기·실행 시 묻기)
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).
- 채팅 입력창의 권한 모드 칩도 같은 설정을 바꿔요. 이때 다시 시작되고 대화는 복원된다.

### 모델 (`Model`, Agent)

- 목적: 시작할 때 쓸 모델(모델 ID·역할)이에요. 비워 두면 기본값을 써요.
- 기본값: 비어 있음 (기본값)
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).

### 추론 수준 (`Thinking level`, Agent)

- 목적: 시작할 때 쓸 추론 수준(예: low, medium, high)이에요. 비워 두면 기본값을 써요.
- 기본값: 비어 있음 (기본값)
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).

### 네트워크 도구 차단 (`Block network tools`, Agent)

- 목적: 네트워크 도구(웹 검색·http(s) 읽기·GitHub·브라우저)를 막아요.
- 기본값: 꺼짐
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).
- 비용·보안: 차단 여부와 관계없이 모든 네트워크 도구 호출은 기록돼요. 셸·MCP·모델 공급자 네트워크까지 막는 방화벽은 아니에요.

### 편집 뒤 확인 (`Verify after edits`, Agent)

- 목적: 소스 편집 뒤 빌드·테스트 확인 없이 끝나려 하면 한 번만 빌드·테스트하고 결과를 보고하게 해요.
- 기본값: 켜짐
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).
- 비용·보안: 꺼도 "완료 전 증거" 안내는 그대로 적용돼요. POMP Workflow 실행 중에는 개입하지 않아요.

## 고급

### 에이전트 실행 파일 경로 (`Agent executable path`, Advanced)

- 목적: 실행할 에이전트 프로그램의 전체 경로예요. 비워 두면 POMP에 포함된 것을 써요.
- 기본값: 비어 있음 (POMP에 포함된 것)
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).

### 추가 실행 인자 (`Extra launch arguments`, Advanced)

- 목적: 실행할 때 그대로 붙는 추가 인자예요.
- 기본값: 비어 있음
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).
- 비용·보안: API 키 같은 비밀을 넣지 마세요. VS 설정에 평문으로 저장돼요.

### 에이전트 질문을 채팅에 표시 (`Show agent questions in chat`, Advanced)

- 목적: 에이전트가 묻는 질문(ask 같은 도구 UI)을 채팅으로 보내요.
- 기본값: 꺼짐
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).

### POMP 확장 불러오기 (`Load POMP extensions`, Advanced)

- 목적: POMP의 확장 묶음(편집기 문맥·pre-edit 검사·스킬·프로젝트 권한 가드)을 불러와요.
- 기본값: 켜짐
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).
- 비용·보안: .pomp/permissions.json이 있는 작업 영역에서 끄면 시작이 막혀요.

### 발견된 확장 불러오기 (`Load discovered extensions`, Advanced)

- 목적: 프로필·설치된 플러그인·솔루션의 에이전트 설정 폴더에서 발견되는 확장·훅도 불러와요.
- 기본값: 꺼짐
- 적용 범위: 실행 설정
- 다시 시작: 바꾸면 다시 시작을 요청한다(진행 중인 작업이 끝난 뒤 적용).
- 비용·보안: 샌드박스 없이 실행돼요. 신뢰하는 솔루션에서만 켜세요.

## 편집기

### Live 편집기 표시

| 설정 (속성 이름) | 기본값 | 하는 일 |
|---|---|---|
| Live 수정 따라가기 (`LiveFollowEnabled`) | 꺼짐 | 적용된 POMP 수정 위치를 따라가며 변경 표시를 켠다. 북마크와 독립이다. |
| Live 변경 북마크 (`LiveBookmarksEnabled`) | 꺼짐 | 실제 VS 책갈피 창에 대화별 `POMP · <대화 제목>` 폴더를 만들고 요청·파일별 `pomp:` 북마크를 남긴다. 끄면 새 북마크만 멈추고 이미 만든 북마크는 지우지 않는다. |
| Live 변경 줄 배경색 (`LiveChangeBackground`) | 켜짐 | 추가·수정된 줄 전체에 옅은 초록 배경을 칠한다. 삭제는 남은 줄이 없어 배경이 없다. |
| Live 변경 +/− 표시 (`LiveChangeSymbols`) | 켜짐 | 변경마다 첫 줄 끝에 초록 `+`(추가·수정) 또는 빨강 `−`(삭제) 단추를 붙인다. 누르면 이전·이후 비교 창과 **원복**이 열린다(끄면 비교·원복 단추도 없다). 줄 배경색을 끈 상태에서는 여러 줄 변경의 둘째 줄부터 줄 끝에 `+`를 더 붙여 바뀐 줄을 알린다. |
| Live 변경 +/− 표시 위치 (`LiveChangeMarkPosition`) | 코드 오른쪽 | `+`/`−` 단추를 둘 곳. **코드 오른쪽**: 변경 첫 줄의 코드 끝 뒤(가로 스크롤을 따라간다). **코드 왼쪽**: 줄 번호 오른쪽에 표시 칸을 하나 두고 그 안에 둔다(그 칸은 이 설정일 때만 생긴다). |
| Live 변경 비교 창 배치 (`LiveCompareLayout`) | 세로 (위아래로) | `+`/`−`를 눌러 여는 비교 창에서 이전·이후를 **세로 (위아래로)** 또는 **가로 (좌우로 나란히)** 놓는다. 어느 쪽이든 이전·이후는 각자 테두리와 색 제목줄(빨강 이전, 초록 이후)이 있는 따로 된 칸이다. |
| Live 변경 내용 표시 (`LiveChangesVisible`) | 켜짐 | 위 두 표시와 스크롤바 표시를 한꺼번에 보이거나 숨긴다(편집기 우클릭 › POMP › **변경 내용 표시**와 같은 설정). 숨기기는 변경 기록이나 흔적 삭제가 아니며 다시 켜면 그대로 보인다. |
| Live 변경 내용 유지 (`LiveChangeRetention`) | 마지막 수정 요청만 | 변경 표시가 언제까지 남는지. **마지막 수정 요청만**: 같은 대화에서 다음 요청이 코드를 고치는 순간 이전 요청의 표시가 모든 파일에서 사라진다(코드를 고치지 않은 질문은 표시를 지우지 않는다). **파일을 저장할 때까지**: 표시가 쌓이다가 그 파일을 저장하면 그 파일의 표시가 사라진다(빌드처럼 모든 파일을 저장하는 동작도 포함). **대화 동안 모두**: 대화가 끝날 때까지 쌓인다(이전 동작). 어느 경우든 표시는 대화별이라 `/new`나 대화 전환 때는 그 대화의 표시로 바뀌고, VS를 끄면 모두 사라진다. 지운 표시는 실행 취소로 되살아나지 않는다. |
| Live 변경 기록 수(파일당) (`LiveHistoryLimit`) | 1000 | 파일마다 기억하는 Live 변경 기록(편집 버전) 수. 실행 취소·다시 실행으로 그 버전에 돌아가면 그때의 변경 표시를 되살린다. 넘치면 가장 오래된 기록부터 버리며, 그보다 더 뒤로 실행 취소하면 지금 표시를 옮겨서 보인다. 10–100000(범위 밖 값은 적용할 때 맞춘다). 줄이면 다음 편집 때 바로 정리되고, 늘리면 VS 메모리를 더 쓴다. |

채팅 입력창 위 도구 묶음의 **Live · 북마크** 아이콘과 같은 저장된 설정이다. 에디터 우클릭 › POMP › **변경 내용 표시**(체크 항목)는 `LiveChangesVisible`을 바꾼다(단축키 기본값 없음).
같은 메뉴의 **변경 내용 지우기**는 지금 대화의 변경 표시를 모든 파일에서 바로 지운다. 코드는 그대로이고 지운 표시는 되살릴 수 없다(그 변경의 원복 단추도 함께 사라진다).
같은 메뉴의 **POMP 책갈피 정리**는 현재 VS 실행 중에 POMP가 만든 책갈피만 지우고 결과(개수 또는 오류)를 상태 표시줄에 알린다. 사용자 책갈피와 변경 기록은 건드리지 않으며 북마크 토글과 무관하게 실행할 수 있다.
Options 적용이나 채팅·메뉴 조작은 즉시 동기화되며 엔진을 다시 시작하지 않고 모델도 호출하지 않는다. 자동완성·코드 캡션 설정과 독립이다.
Live 변경 기록은 VS 메모리에만 있으며 디스크에 저장하지 않는다.
북마크 폴더는 대화마다 하나다. 이름은 대화 제목이고, 제목이 아직 없으면 폴더를 만든 시각(`POMP · 대화 MM-dd HH:mm`)을 쓰며 제목이 생기거나 바뀌면 POMP가 만든 폴더 이름을 고친다.
폴더 안에는 요청(호스트가 수락한 채팅 메시지)마다 파일별 첫 변경 줄에 북마크 하나를 둔다. 같은 대화의 같은 줄에는 두 번 만들지 않는다. 요청 출처가 불확실한 수정은 북마크를 만들지 않는다.
북마크 생성은 책갈피 창이나 채팅으로 키보드 포커스를 옮기지 않는다.
POMP 북마크는 토글 끄기·대화 전환·VS 종료 때 지우지 않는다. 정리는 현재 VS 실행 중에 만든 POMP 북마크를 COM 마커 단위로 제거한 뒤,
비게 된 POMP 폴더를 책갈피 창의 삭제 명령으로 지운다(그 폴더를 선택한 경우에만 실행하고 원래 선택을 되돌리며, 창을 활성화하지 않는다).
사용자가 폴더에 추가하거나 옮긴 항목이 있으면 그 폴더는 남기고, 사용자 책갈피·폴더는 지우지 않는다. 이전 VS 실행에서 만든 POMP 책갈피는 책갈피 창에서 직접 지운다.
폴더 이름이 바뀌어도 목록에서의 위치는 그대로다. VS를 다시 시작한 뒤 같은 대화를 이어 가면 같은 이름의 새 폴더가 생길 수 있다.

### 자동 인라인 완성 켜기 (`Enable automatic inline completions`, Editor)

- 목적: 입력이 멈추면 주변 코드를 설정된 모델에 보내 자동 완성을 받아요.
- 기본값: 꺼짐
- 적용 범위: 편집기 기능
- 다시 시작: 옵션을 적용하면 바로 반영된다.
- 비용·보안: 공급자 비용이 생길 수 있어요.

### 보조 모델 (`Helper model`, Editor)

- 목적: 자동완성·질문의 수정 제안·코드 캡션·지식 변환·입력 예측 문장에 쓰는 모델이에요(채팅 모델과 별개).
- 선택: 계정 탭의 **빠른 모델 / 채팅 모델과 같게 / 모델 직접 선택**에서 고른다.
- 기본값: 비어 있음 (빠른 모델)
- 적용 범위: 보조 기능
- 다시 시작: 옵션을 적용하면 바로 반영된다.
- 비용·보안: 잘못 고르면 조용히 다른 모델로 넘어가지 않고 실패해요.

### POMP 코드 캡션 표시 (`Show POMP code captions`, Editor)

- 목적: 보이는 선언 아래에 작은 POMP 요약 행을 달아요.
- 기본값: 꺼짐
- 적용 범위: 편집기 기능
- 다시 시작: 옵션을 적용하면 바로 반영된다.
- 비용·보안: 클릭할 때만 모델을 호출해 비용이 생길 수 있어요. 먼저 POMP를 여세요.

### 캡션에 기본 CodeLens 사용 (`Use native CodeLens for POMP captions`, Editor)

- 목적: POMP 장식 대신 IDE CodeLens 서비스로 캡션을 표시해요(C#/VB).

### 편집기 문맥이 담는 양 (Chat)

편집기 컨텍스트 포함이 켜진 메시지 앞에 붙는 `<vs_context>` 묶음의 크기예요. omp가 아니라 POMP가 정하는 값이고, 옵션을 적용하면 다음 메시지부터
바로 쓰여요(다시 시작 없음). 범위 밖 값은 적용할 때 가장 가까운 끝값으로 맞춰요. 늘리면 메시지마다 그만큼 토큰이 더 들고, 0으로 두면 그 부분을 빼요.

| 설정 (속성 이름) | 기본값 | 범위 | 하는 일 |
|---|---|---|---|
| 편집기 문맥 커서 위아래 줄 수 (`EditorContextLines`) | 30 | 0–1000 | 커서 줄 위아래로 함께 보내는 줄 수(0이면 커서 줄만) |
| 편집기 문맥 큰 파일 기준 줄 수 (`EditorContextLargeFileThreshold`) | 10000 | 100–10000000 | 이 줄 수 이상인 파일은 아래 "큰 파일" 줄 수를 쓴다 |
| 편집기 문맥 큰 파일 커서 위아래 줄 수 (`EditorContextLargeFileLines`) | 100 | 0–1000 | 큰 파일에서 커서 줄 위아래로 보내는 줄 수 |
| 편집기 문맥 선택 글 최대 글자 수 (`EditorContextSelectedChars`) | 2000 | 0–20000 | 선택한 글을 이 글자 수까지 보낸다(0이면 선택 범위만 알리고 글은 빼요) |
| 편집기 문맥 한 줄 최대 글자 수 (`EditorContextLineChars`) | 300 | 20–10000 | 주변 코드의 한 줄이 이보다 길면 잘라요 |
| 편집기 문맥 주변 코드 최대 글자 수 (`EditorContextWindowChars`) | 8000 | 0–100000 | 주변 코드 전체의 글자 수 한도. 넘으면 거기서 자르고 잘렸다고 적어요(0이면 주변 코드를 빼요) |
| 편집기 문맥 오류 최대 개수 (`EditorContextErrors`) | 10 | 0–100 | 함께 보내는 오류 목록의 오류 수(경고·메시지는 보내지 않아요, 0이면 빼요) |
| 편집기 문맥 VS 응답 대기(초) (`EditorContextTimeoutSeconds`) | 2 | 1–10 | 활성 문서·솔루션·오류 목록·편집기 내용을 VS에서 읽을 때 각각 기다리는 최대 시간. 넘으면 그 부분 없이 보낸다 |

메시지 전체(편집기 문맥 포함)는 엔진이 받는 한 줄 한도(약 1 MiB)를 넘을 수 없어요. 값을 크게 올려 넘으면 그 메시지는 보내지 않고 오류를 보여 줘요.

## 단축키

채팅 창과 POMP의 Visual Studio 명령(편집기 동작·POMP 열기·새 대화·포커스 전환)의 키보드 단축키예요. 모든 키는 여기서만 정하고,
VS 명령 키는 옵션을 적용하면 VS 키보드 바인딩에 그대로 들어간다(도구 › 옵션 › 환경 › 키보드에서 `Pomp.`로 검색하면 같은 값이 보인다).
키 조합은 `Ctrl`, `Alt`, `Shift`를 원하는 만큼(순서 무관)에 키 하나를 `+`로 이어 쓴다(예: `Ctrl+Alt+T`).
키는 글자·숫자·`F1`~`F12`·이름 있는 키(`Enter`, `Esc`, `Space`, `Tab`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown`, `Up`, `Down`, `Left`, `Right`) 중 하나이고, 대소문자와 `+` 앞뒤 공백은 가리지 않는다.
비워 두면 그 단축키는 없는 것으로 보고, 형식이 잘못되면 기본값을 쓴다. 보내기를 뺀 나머지 단축키에는 `Ctrl`이나 `Alt`가 들어가야 하고(`F1`~`F12`만 단독으로 가능),
그렇지 않은 값(예: `Enter`, `A`, `Shift+D`)은 입력 중에 눌리는 키라서 기본값으로 돌아간다. 모든 단축키는 옵션을 적용하면 바로 반영된다.

### 보내기 (`Send`, Shortcuts)

- 목적: 입력창 메시지를 보내는 키예요. `Enter`는 Enter로 보내고 Shift+Enter로 줄을 바꾸며, `Ctrl+Enter`는 Ctrl+Enter로 보내고 Enter로 줄을 바꿔요. 이 두 값만 쓸 수 있고 다른 값은 기본값으로 돌아가요.
- 기본값: `Enter`
- 적용 범위: 채팅 창
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 보낼 대상 고르기 (`Pick send target`, Shortcuts)

- 기본값: `Ctrl+Alt+T`
- 적용 범위: 채팅 창
- 다시 시작: 옵션을 적용하면 바로 반영된다.

- 다시 시작: 옵션을 적용하면 바로 반영된다.

- 다시 시작: 옵션을 적용하면 IDE 바인딩과 채팅 단축키에 바로 반영된다(아이콘 툴팁은 이름만 보여요). 빈 값은 단축키 없음이에요.

### POMP 북마크 전환 (`Toggle POMP bookmarks`, Shortcuts)

- 목적: 채팅 컨텍스트 줄의 북마크 아이콘과 같이 POMP 변경 북마크를 켜거나 꺼요. 메뉴에는 없어요. Live와 독립적이며 모델을 호출하지 않아요.
- 기본값: `Alt+K`
- 적용 범위: Visual Studio 전역과 채팅 창. 채팅에서 실행하면 입력창에 포커스를 두며, 다른 검색·편집 입력란의 키는 가로채지 않아요.
- 다시 시작: 옵션을 적용하면 IDE 바인딩과 채팅 단축키에 바로 반영된다(아이콘 툴팁은 이름만 보여요). 빈 값은 단축키 없음이에요.

### 권한 모드 (`Permission mode`, Shortcuts)

- 목적: 입력창의 권한 모드 선택을 열어요.
- 기본값: `Alt+Q`
- 적용 범위: 채팅 창
- 다시 시작: 옵션을 적용하면 바로 반영된다. 모드를 실제로 바꾸면 다시 시작된다(승인 모드 항목 참고).

### 허용 (`Allow`, Shortcuts)

- 목적: 대기 중인 요청 카드를 한 번 허용하거나 확인해요.
- 기본값: `Alt+A`
- 적용 범위: 채팅 창
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 거부 (`Deny`, Shortcuts)

- 목적: 대기 중인 요청 카드를 거부하거나 취소해요.
- 기본값: `Alt+D`
- 적용 범위: 채팅 창
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 권한 보기 (`Permissions view`, Shortcuts)

- 목적: 도구 화면의 권한 항목을 열어요.
- 기본값: `Ctrl+Alt+P`
- 적용 범위: 채팅 창
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### POMP 열기 (`Open POMP`, Shortcuts)

- 목적: POMP 창을 열고 입력창에 포커스를 둬요.
- 기본값: `Shift+Alt+Q`
- 적용 범위: VS 전체
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 새 대화 (`New conversation`, Shortcuts)

- 목적: 새 대화를 시작해요.
- 기본값: `Shift+Alt+N`
- 적용 범위: VS 전체
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 이 코드 설명 (`Explain this code`, Shortcuts)

- 목적: 선택한 코드를 설명해 달라고 채팅으로 보내요. 선택이 없으면 커서를 감싸는 멤버(없으면 커서 줄)를 먼저 선택해요([화면 안내 §2](screen-guide.md#2-편집기-우클릭-메뉴) 질문 범위).
- 기본값: `Shift+Alt+E`
- 적용 범위: 텍스트 편집기
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 이 코드 리뷰 (`Review this code`, Shortcuts)

- 목적: 선택한 코드를 리뷰해 달라고 채팅으로 보내요.
- 기본값: `Shift+Alt+R`
- 적용 범위: 텍스트 편집기
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 이 코드 고치기 (`Fix this code`, Shortcuts)

- 목적: 선택한 코드를 고쳐 달라고 채팅으로 보내요.
- 기본값: `Shift+Alt+F`
- 적용 범위: 텍스트 편집기
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 테스트 작성 (`Write tests`, Shortcuts)

- 목적: 선택한 코드의 테스트를 작성해 달라고 채팅으로 보내요.
- 기본값: `Shift+Alt+U`
- 적용 범위: 텍스트 편집기
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 컨텍스트 바구니에 추가 (`Add to context basket`, Shortcuts)

- 목적: 현재 파일을 다음 메시지의 컨텍스트 바구니에 넣어요.
- 기본값: `Shift+Alt+I`
- 적용 범위: 텍스트 편집기
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### POMP에게 질문 (`Ask POMP`, Shortcuts)

- 목적: 선택 영역에 대해 질문하거나 바꿀 지시를 입력하는 질문 창을 열어요.
- 기본값: `Alt+M`
- 적용 범위: 텍스트 편집기
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 지식에 추가 (`Add to knowledge`, Shortcuts)

- 목적: 선택한 줄(선택이 없으면 커서 줄)을 담아 POMP 창의 지식에 추가 양식을 열어요. 이름으로 지식을 고르거나 새 지식을 만들어요.
- 기본값: `Alt+/`
- 적용 범위: 텍스트 편집기
- 다시 시작: 옵션을 적용하면 바로 반영된다.

### 편집기·채팅 포커스 전환 (`Toggle editor and chat focus`, Shortcuts)

- 목적: 편집기와 채팅 입력창 사이에서 포커스를 옮겨요. 채팅 창 안에서도 같은 조합이 통한다.
- 기본값: `Alt+J`
- 적용 범위: VS 전체와 채팅 창
- 다시 시작: 옵션을 적용하면 바로 반영된다.
