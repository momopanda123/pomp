# 설정 안내

POMP 설정은 Visual Studio의 **도구 > 옵션 > Pomp > 일반**에 있다. 영어 화면에서는 페이지 이름이 **General**이다.

옵션 화면의 분류와 항목 이름은 POMP 언어를 따른다. 이 문서는 한국어 이름 옆에 영어 이름을 함께 적는다.
옵션 화면과 POMP 창에는 설명 문구가 없다. 각 설정의 뜻과 기본값은 이 문서에서 확인한다.

## 적용 시점

바뀐 값이 적용되는 때는 분류마다 다르다.

| 구분 | 적용 시점 | 분류 |
|---|---|---|
| 바로 적용 | 옵션을 적용하면 바로 반영된다. | 규칙, 편집기, 코드 검색, 권한, 채팅, 지식, 단축키 |
| 다시 시작 | 바꾸면 POMP가 다시 시작을 요청한다. 진행 중인 작업이 끝난 뒤 적용된다. | 에이전트, 고급, 컴퓨터 사용 |

## 규칙

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 규칙 파일 열기 (`Open rule file in VS editor`) | 비어 있음 | 기존 .mdc 규칙 파일을 골라 VS 편집기로 연다. |

이 설정은 파일을 만들거나 고치지 않는다. 권한 정책 편집기도 아니다.
저장한 규칙은 다음 프롬프트부터 다시 평가된다.

## 에이전트

이 분류의 설정은 바꾸면 다시 시작을 요청한다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 승인 모드 (`Approval mode`) | Always ask (항상 묻기) | 기본 도구와 VS 도구의 승인 방식을 정한다. |
| 모델 (`Model`) | 비어 있음 | 시작할 때 쓸 모델 ID나 역할이다. 비워 두면 기본값을 쓴다. |
| 추론 수준 (`Thinking level`) | 비어 있음 | 시작할 때 쓸 추론 수준이다. 예: low, medium, high. 비워 두면 기본값을 쓴다. |
| 네트워크 도구 차단 (`Block network tools`) | 꺼짐 | 웹 검색, http(s) 읽기, GitHub, 브라우저 도구를 막는다. |
| 편집 뒤 확인 (`Verify after edits`) | 켜짐 | 소스를 고친 뒤 빌드·테스트 확인 없이 끝내려 하면 한 번 빌드·테스트하고 결과를 보고하게 한다. |

### 승인 모드 선택지

| 선택지 | 동작 |
|---|---|
| Always ask (항상 묻기) | 승인이 필요한 VS 도구를 매번 묻는다. |
| Auto-write (쓰기 자동) | VS의 파일·프로젝트·중단점·북마크 변경은 자동 승인한다. 프로세스 실행, 테스트, 디버거, Git, 패키지 변경은 묻는다. |
| Auto-all (모두 자동) | VS 도구를 모두 자동 승인한다. 위험한 명령과 공급자 안전 확인은 그래도 묻는다. |

저장된 허용은 승인 모드와 별도로 동작한다. 저장된 허용은 도구 › 권한 › 허용한 작업에서 본다.

채팅 입력창의 권한 모드 칩도 같은 설정을 바꾼다. 이때 POMP가 다시 시작되고 대화는 복원된다.

### 네트워크 도구 차단

차단 여부와 관계없이 모든 네트워크 도구 호출은 기록된다.
이 설정은 방화벽이 아니다. 셸, MCP, 모델 공급자의 네트워크는 막지 않는다.

### 편집 뒤 확인

이 설정을 꺼도 "완료 전 증거" 안내는 그대로 적용된다. POMP Workflow 실행 중에는 개입하지 않는다.

## 고급

이 분류의 설정은 바꾸면 다시 시작을 요청한다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 에이전트 실행 파일 경로 (`Agent executable path`) | 비어 있음 | 실행할 에이전트 프로그램의 전체 경로다. 비워 두면 POMP에 포함된 것을 쓴다. |
| 추가 실행 인자 (`Extra launch arguments`) | 비어 있음 | 에이전트를 실행할 때 그대로 붙는 인자다. |
| 에이전트 질문을 채팅에 표시 (`Show agent questions in chat`) | 꺼짐 | 에이전트가 ask 같은 도구로 묻는 질문을 채팅으로 보낸다. |
| POMP 확장 불러오기 (`Load POMP extensions`) | 켜짐 | POMP 확장 묶음을 불러온다. 편집기 문맥, pre-edit 검사, 스킬, 프로젝트 권한 가드가 들어 있다. |
| 발견된 확장 불러오기 (`Load discovered extensions`) | 꺼짐 | 프로필, 설치된 플러그인, 솔루션의 에이전트 설정 폴더에서 발견한 확장과 훅도 불러온다. |

주의할 점은 다음과 같다.

- 추가 실행 인자에 API 키 같은 비밀을 넣지 않는다. 이 값은 VS 설정에 평문으로 저장된다.
- `.pomp/permissions.json`이 있는 작업 영역에서 POMP 확장 불러오기를 끄면 시작이 막힌다.
- 발견된 확장은 샌드박스 없이 실행된다. 신뢰하는 솔루션에서만 켠다.

## 편집기

이 분류의 설정은 옵션을 적용하면 바로 반영된다.

### Live 변경 표시

POMP가 코드를 고치면 편집기에 변경 표시를 남길 수 있다. 아래 설정이 그 표시를 정한다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| Live 수정 따라가기 | 꺼짐 | 적용된 POMP 수정 위치를 따라가며 변경 표시를 켠다. 북마크와 독립이다. |
| Live 변경 북마크 | 꺼짐 | VS 책갈피 창에 대화별 폴더를 만들고 요청·파일별 `pomp:` 북마크를 남긴다. |
| Live 변경 줄 배경색 | 켜짐 | 추가·수정된 줄 전체에 옅은 초록 배경을 칠한다. 삭제에는 남은 줄이 없어 배경이 없다. |
| Live 변경 +/− 표시 | 켜짐 | 변경 첫 줄 끝에 초록 `+` 또는 빨강 `−` 단추를 붙인다. `+`는 추가·수정, `−`는 삭제다. |
| Live 변경 +/− 표시 위치 | 코드 오른쪽 | `+`/`−` 단추를 둘 곳이다. **코드 오른쪽** 또는 **코드 왼쪽**을 고른다. |
| Live 변경 비교 창 배치 | 세로 (위아래로) | 비교 창에서 이전과 이후를 놓는 방향이다. **세로 (위아래로)** 또는 **가로 (좌우로 나란히)** 중에서 고른다. |
| Live 변경 내용 표시 | 켜짐 | 줄 배경색, +/− 표시, 스크롤바 표시를 한꺼번에 보이거나 숨긴다. |
| Live 변경 내용 유지 | 마지막 수정 요청만 | 변경 표시가 언제까지 남는지 정한다. |
| Live 변경 기록 수(파일당) | 1000 | 파일마다 기억하는 변경 기록 수다. 10–100000 사이 값을 쓴다. |

이 설정들은 엔진을 다시 시작하지 않고 모델도 호출하지 않는다. 자동완성, 코드 캡션 설정과는 독립이다.

#### +/− 단추와 비교 창

`+`/`−` 단추를 누르면 이전·이후 비교 창과 **원복**이 열린다. +/− 표시를 끄면 비교와 원복 단추도 없다.

줄 배경색을 끈 상태에서는 여러 줄 변경의 둘째 줄부터 줄 끝에 `+`가 더 붙는다. 어느 줄이 바뀌었는지 알리기 위해서다.

| 표시 위치 | 단추 자리 |
|---|---|
| 코드 오른쪽 | 변경 첫 줄의 코드 끝 뒤에 둔다. 가로 스크롤을 따라간다. |
| 코드 왼쪽 | 줄 번호 오른쪽에 표시 칸을 하나 두고 그 안에 둔다. 이 칸은 이 설정일 때만 생긴다. |

비교 창에서 이전과 이후는 따로 된 칸이다. 이전 칸은 빨강 제목줄, 이후 칸은 초록 제목줄을 가진다.

#### 표시를 숨기거나 지우기

**Live 변경 내용 표시**를 끄면 표시만 숨는다. 변경 기록은 지워지지 않으며, 다시 켜면 그대로 보인다.

#### 변경 표시가 남는 기간

| Live 변경 내용 유지 | 표시가 사라지는 때 |
|---|---|
| 마지막 수정 요청만 | 같은 대화에서 다음 요청이 코드를 고치면 이전 요청의 표시가 모든 파일에서 사라진다. 코드를 고치지 않은 질문은 표시를 지우지 않는다. |
| 파일을 저장할 때까지 | 표시가 쌓이다가 그 파일을 저장하면 그 파일의 표시가 사라진다. 빌드처럼 모든 파일을 저장하는 동작도 포함된다. |
| 대화 동안 모두 | 대화가 끝날 때까지 표시가 쌓인다. |

어느 경우든 표시는 대화별이다. `/new`를 쓰거나 대화를 바꾸면 그 대화의 표시로 바뀐다.
VS를 끄면 표시가 모두 사라진다. 지운 표시는 실행 취소로 되살아나지 않는다.

#### 변경 기록 수

실행 취소나 다시 실행으로 기록된 버전에 돌아가면 그때의 변경 표시가 되살아난다.
기록이 한도를 넘으면 가장 오래된 기록부터 버린다. 그보다 더 뒤로 실행 취소하면 지금 표시를 옮겨서 보여 준다.

범위 밖 값은 적용할 때 범위 안으로 맞춘다. 값을 늘리면 VS 메모리를 더 쓴다.
변경 기록은 VS 메모리에만 있고 디스크에 저장하지 않는다.

#### 다른 곳에서 바꾸기

- 채팅 입력창 위 도구 묶음의 **Live** 아이콘과 **북마크** 아이콘은 같은 설정을 바꾼다.
- 편집기 우클릭 › POMP › **변경 내용 표시**는 Live 변경 내용 표시 설정을 바꾼다. 기본 단축키는 없다.
- 같은 메뉴의 **변경 내용 지우기**는 지금 대화의 변경 표시를 모든 파일에서 바로 지운다. 코드는 그대로다. 지운 표시와 그 변경의 원복 단추는 되살릴 수 없다.
- 같은 메뉴의 **POMP 책갈피 정리**는 아래 POMP 북마크에서 설명한다.

#### POMP 북마크

북마크 폴더는 대화마다 하나이고, 이름은 `POMP · <대화 제목>`이다.
제목이 아직 없으면 폴더를 만든 시각을 써서 `POMP · 대화 MM-dd HH:mm`이 된다. 제목이 생기거나 바뀌면 POMP가 폴더 이름을 고친다. 목록에서의 위치는 그대로다.

폴더 안에는 요청마다 파일별 첫 변경 줄에 북마크를 하나 둔다. 같은 대화의 같은 줄에는 두 번 만들지 않는다.
어느 요청에서 나온 수정인지 확실하지 않으면 북마크를 만들지 않는다. 북마크를 만들어도 키보드 포커스는 옮겨 가지 않는다.

Live 변경 북마크를 끄면 새 북마크만 멈춘다. 이미 만든 북마크는 토글 끄기, 대화 전환, VS 종료 때 지우지 않는다.

**POMP 책갈피 정리**는 현재 VS 실행 중에 POMP가 만든 책갈피만 지운다. 비게 된 POMP 폴더도 함께 지운다.
결과는 개수나 오류로 상태 표시줄에 나온다. 북마크 토글이 꺼져 있어도 실행할 수 있다.

- 사용자 책갈피와 사용자 폴더, 변경 기록은 건드리지 않는다.
- 사용자가 POMP 폴더에 추가하거나 옮긴 항목이 있으면 그 폴더는 남긴다.
- 이전 VS 실행에서 만든 POMP 책갈피는 책갈피 창에서 직접 지운다.
- VS를 다시 시작한 뒤 같은 대화를 이어 가면 같은 이름의 새 폴더가 생길 수 있다.

### 자동완성과 코드 캡션

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 자동 인라인 완성 켜기 (`Enable automatic inline completions`) | 꺼짐 | 입력이 멈추면 주변 코드를 설정된 모델에 보내 자동 완성을 받는다. |
| 자동완성 제한 시간(초) (`Inline completion time limit (seconds)`) | 10 | 자동완성 요청 하나를 기다리는 최대 시간이다. 2–60초. 넘으면 그 요청은 제안 없이 끝난다. 추론을 끌 수 없는 모델(Muse Spark 등)은 답에 몇 초가 더 걸린다. |
| 보조 모델 (`Helper model`) | 비어 있음 (빠른 모델) | 자동완성, 질문의 수정 제안, 코드 캡션, 지식 변환, 입력 예측 문장에 쓰는 모델이다. 채팅 모델과 별개다. |
| POMP 코드 캡션 표시 (`Show POMP code captions`) | 꺼짐 | 열린 폴더 안 파일의 보이는 선언 아래에 작은 POMP 요약 행을 단다. C#·VB는 Roslyn으로, C·C++·TypeScript·JavaScript·Python·Java·Kotlin·Go·Rust·PHP·Ruby·Swift·Scala·Dart·Groovy·Lua·Perl·R·PowerShell·셸·F#·SQL·Objective-C는 POMP의 어휘 스캐너로, 그 밖의 언어는 편집기 블록 구조의 형식·멤버 블록으로 선언을 찾는다. |
| 캡션에 기본 CodeLens 사용 (`Use native CodeLens for POMP captions`) | 꺼짐 | C#·VB 파일에서는 POMP 장식 대신 IDE CodeLens 서비스로 캡션을 표시한다. 다른 언어 파일에는 POMP 장식이 그대로 보인다. VS의 C++ CodeLens는 단위 테스트에만 붙기 때문이다. |

- 자동 인라인 완성은 공급자 비용이 생길 수 있다.
- 보조 모델은 계정 탭에서 **빠른 모델**, **채팅 모델과 같게**, **모델 직접 선택** 중에 고른다.
- 보조 모델을 잘못 고르면 다른 모델로 조용히 넘어가지 않고 실패한다.
- 코드 캡션은 클릭할 때만 모델을 호출하며, 그때 비용이 생길 수 있다. 먼저 POMP 창을 연다.
- 기본 CodeLens를 쓰려면 코드 캡션 표시가 켜져 있고 VS CodeLens가 있어야 한다.

## 코드 검색

이 분류의 설정은 옵션을 적용하면 바로 반영된다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 로컬 임베딩 켜기 (`Enable local embeddings`) | 꺼짐 | 잘라낸 소스와 검색어를 로컬 임베딩 서버에 보내고, 받은 벡터를 POMP 데이터에 저장한다. |
| 로컬 임베딩 주소 (`Local embedding endpoint`) | `http://127.0.0.1:11434/v1/embeddings` | OpenAI 호환 `/v1/embeddings` 주소다. 리터럴 loopback 주소만 쓸 수 있다. |
| 로컬 임베딩 모델 (`Local embedding model`) | 비어 있음 | 로컬 서버에 이미 있는 임베딩 모델 이름이다. 자동으로 내려받지 않는다. |

코드 검색 인덱스는 자동으로 유지된다. 켜기, 주소, 모델이 바뀌면 벡터를 다시 만들거나 진행 중인 작업을 멈춘다.
어휘 검색 인덱스는 이와 별도로 자동 갱신된다.

- 신뢰하는 로컬 서버와 이미 설치된 모델을 쓴다. 서버 설정에 따라 데이터가 외부로 나갈 수 있다.
- POMP는 클라우드 대체, 자격 증명, 모델 다운로드를 제공하지 않는다.
- 주소에는 호스트명, 자격 증명, 리디렉션, 프록시를 쓸 수 없다. 켜기 전에는 서버를 호출하지 않는다.
- 같은 이름 모델의 가중치를 바꿨으면 로컬 임베딩을 껐다 켠다. 그래야 새 벡터를 만든다.

## 권한

이 분류의 설정은 옵션을 적용하면 바로 반영된다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 실험적 AppContainer 실행기 켜기 (`Enable experimental AppContainer runner`) | 꺼짐 | 실험적 AppContainer 실행기를 켠다. |
| 대화형 터미널 켜기 (`Enable interactive terminal`) | 꺼짐 | 작업 탭 › 진행 맨 아래에 대화형 터미널 카드를 켠다. |
| 항상 허용된 권한 (`Always-allowed permissions`) | 비어 있음 | 다시 묻지 않는 허용 키 목록이다. VS 도구와 기본 도구별로 쌓인다. 항목을 지우면 철회된다. |

### AppContainer 실행기

Windows에서 검증되지 않은 기능이다. requireSandbox를 만족하지 않는다.

### 대화형 터미널

카드는 옵션이 켜져 있고 엔진이 지원할 때만 보인다. 함께 들어 있는 엔진은 지원하지 않으므로, 옵션을 켜도 카드가 보이지 않는다.
터미널은 사용자 권한으로 돌아가며 샌드박스가 아니다.

모델이 요청해 승인받은 명령 작업은 이 옵션과 관계없다. 그 상태, 출력, 취소는 채팅의 해당 도구 카드에 나온다.

### 항상 허용된 권한

허용 키는 승인 창에서만 등록된다. 프로젝트 정책의 거부가 이 허용보다 우선한다.

## 컴퓨터 사용

이 분류의 설정은 바꾸면 다시 시작을 요청한다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 컴퓨터 사용 (`Computer use`) | PerConversation (대화마다 켜기) | 화면과 입력을 제어하는 방식이다. |
| 브라우저 제어 (`Browser control`) | 꺼짐 | 에이전트가 브라우저 기능으로 웹 페이지를 열고 조작하게 한다. |
| 화면 보기도 매번 확인 (`Ask before screenshots too`) | 꺼짐 | 화면 보기도 매번 묻는다. 화면 보기는 캡처, 창 목록, 접근성 읽기를 말한다. |

### 대화마다 켜기

PerConversation이면 대화마다 꺼진 채로 시작한다.
그 대화에서만 켜려면 채팅 창의 도구 › 대화 설정 › 화면 입력 제어에서 **사용** 스위치를 켠다. `/computer` 슬래시 명령도 이 스위치를 바꾼다.
입력창에는 화면 아이콘이 없다.

### 안전

- 화면 보기는 기본으로 묻지 않고, 그 내용은 모델 공급자에게 전송된다.
- 클릭, 입력, 클립보드 쓰기는 매번 묻는다.
- 하위 에이전트는 컴퓨터 사용을 쓸 수 없다.
- 브라우저 제어는 **네트워크 도구 차단**이 켜진 동안 동작하지 않는다.
- 브라우저 제어가 켜진 동안 하위 에이전트는 Eval을 쓸 수 없다.

## 채팅

이 분류의 설정은 옵션을 적용하면 바로 반영된다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| 언어 (`Language`) | 자동 | POMP 창과 POMP 메시지의 언어다. 자동이면 VS 표시 언어를 따른다. 이미 표시된 글은 바뀌지 않는다. |
| 편집기 문맥 기본 포함 (`Include editor context by default`) | 켜짐 | 매 프롬프트 앞에 활성 편집기, 솔루션, 오류 목록 요약을 붙인다. 채팅의 토글로 바꾸면 그쪽을 따른다. |
| 입력 예측 문장 (`Composer predictions`) | 꺼짐 | 입력창에 쓰던 글 뒤로 이어질 문장을 흐린 글씨로 보여 준다. |
| 입력 단어 완성 (`Word completion`) | 켜짐 | 입력창에서 쓰던 단어의 나머지를 흐린 글씨로 보여 준다. 모델을 부르지 않는다. |

### 편집기 문맥이 담는 양

편집기 문맥을 포함한 메시지에 붙는 내용의 크기를 정한다. 값은 다음 메시지부터 쓰인다.

| 설정 | 기본값 | 범위 | 하는 일 |
|---|---|---|---|
| 편집기 문맥 커서 위아래 줄 수 | 30 | 0–1000 | 커서 줄 위아래로 함께 보내는 줄 수다. 0이면 커서 줄만 보낸다. |
| 편집기 문맥 큰 파일 기준 줄 수 | 10000 | 100–10000000 | 이 줄 수 이상인 파일은 큰 파일 줄 수를 쓴다. |
| 편집기 문맥 큰 파일 커서 위아래 줄 수 | 100 | 0–1000 | 큰 파일에서 커서 줄 위아래로 보내는 줄 수다. |
| 편집기 문맥 선택 글 최대 글자 수 | 2000 | 0–20000 | 선택한 글을 이 글자 수까지 보낸다. 0이면 선택 범위만 알리고 글은 뺀다. |
| 편집기 문맥 한 줄 최대 글자 수 | 300 | 20–10000 | 주변 코드의 한 줄이 이보다 길면 자른다. |
| 편집기 문맥 주변 코드 최대 글자 수 | 8000 | 0–100000 | 주변 코드 전체의 글자 수 한도다. 넘으면 자르고 잘렸다고 적는다. 0이면 주변 코드를 뺀다. |
| 편집기 문맥 오류 최대 개수 | 10 | 0–100 | 함께 보내는 오류 수다. 경고와 메시지는 보내지 않는다. 0이면 뺀다. |
| 편집기 문맥 VS 응답 대기(초) | 2 | 1–10 | VS에서 각 정보를 읽을 때 기다리는 최대 시간이다. 넘으면 그 부분 없이 보낸다. |

범위 밖 값은 적용할 때 가장 가까운 끝값으로 맞춘다. 0으로 두면 그 부분을 뺀다.
값을 늘리면 메시지마다 그만큼 토큰이 더 든다.

편집기 문맥을 포함한 메시지 전체는 약 1 MiB를 넘을 수 없다. 값을 너무 크게 올려 이 한도를 넘으면 메시지를 보내지 않고 오류를 보여 준다.

### 입력 예측 문장

`Tab`을 누르면 예측 문장이 그대로 입력된다. `Esc`를 누르거나, 다른 글을 입력하거나, 커서를 옮기면 사라진다.

입력을 멈출 때마다 쓰던 글을 보조 모델에 보낸다. 보조 모델은 계정 탭에서 고른다. 예측 한 번이 모델 요청 한 번이다.

### 입력 단어 완성

단어를 두 글자 이상 쓰면 커서 뒤에 그 단어의 나머지가 흐리게 보인다. 한글 단어도 된다.
`Tab`을 누르면 나머지가 입력된다. `Esc`를 누르면 사라지고, 다른 글을 입력하거나 커서를 옮기면 바뀌거나 사라진다.

단어는 이 PC에서 이 작업 영역에 보낸 입력, 지금 대화의 글, 대화와 @ 파일 찾기에서 본 파일 경로에서 찾는다. 모델 요청도, 파일 검색도 새로 하지 않는다.
앞부분이 맞는 단어 중 자주 나온 단어, `Tab`으로 받은 단어, 최근에 나온 단어를 먼저 보여 준다. 대소문자는 쓴 그대로 두고 나머지만 채운다.
`Tab`으로 받은 단어는 작업 영역마다 기억한다.

입력 예측 문장이 함께 보일 때는 `Tab`이 단어 완성을 먼저 받는다.

다음 경우에는 보이지 않는다.

- 한글 등을 조합하는 중
- `/` 명령이나 `@` 목록이 열린 동안
- `` ` `` 코드 안, `@` 참조나 주소 안
- 같은 줄에서 커서 뒤에 글이 있을 때

## 단축키

채팅 창과 POMP의 VS 명령에 쓰는 키보드 단축키다. 모든 단축키는 여기서만 정하고, 옵션을 적용하면 바로 반영된다.

VS 명령의 키는 VS 키보드 바인딩에도 그대로 들어간다. 도구 › 옵션 › 환경 › 키보드에서 `Pomp.`로 검색하면 같은 값이 보인다.

### 키 쓰는 법

- `Ctrl`, `Alt`, `Shift`를 원하는 만큼 쓰고 키 하나를 `+`로 잇는다. 예: `Ctrl+Alt+T`. 순서는 상관없다.
- 키는 글자, 숫자, `F1`–`F12`, 이름 있는 키 중 하나다.
- 이름 있는 키: `Enter`, `Esc`, `Space`, `Tab`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown`, `Up`, `Down`, `Left`, `Right`.
- `,` `.` `;` `'` 도 키로 쓸 수 있다.
- 대소문자와 `+` 앞뒤 공백은 가리지 않는다.
- 비워 두면 그 단축키는 없다. 형식이 잘못되면 기본값을 쓴다.
- 보내기를 뺀 단축키에는 `Ctrl`이나 `Alt`가 들어가야 한다. `F1`–`F12`만 단독으로 쓸 수 있다.
- `Enter`, `A`, `Shift+D`처럼 입력 중에 눌리는 키는 기본값으로 돌아간다.

### 채팅 창

| 단축키 | 기본값 | 하는 일 |
|---|---|---|
| 보내기 (`Send`) | `Enter` | 입력창 메시지를 보낸다. |
| 보낼 대상 고르기 (`Pick send target`) | `Ctrl+Alt+T` | 메시지 하나를 보낼 동료나 에이전트를 고르는 창을 연다. |
| 이전 보낼 대상 (`Previous send target`) | `Alt+,` | 보낼 대상 목록의 이전 항목을 대상으로 정한다. |
| 다음 보낼 대상 (`Next send target`) | `Alt+.` | 보낼 대상 목록의 다음 항목을 대상으로 정한다. |
| 컨텍스트 바구니 (`Context basket`) | `Alt+;` | 입력창 위 컨텍스트 바구니를 열고 첫 파일에 커서를 둔다. |
| 편집기 컨텍스트 포함 (`Include editor context`) | `Alt+'` | 입력창 위 편집기 컨텍스트 포함을 켜거나 끈다. |
| 권한 모드 (`Permission mode`) | `Alt+Q` | 입력창의 권한 모드 선택을 연다. |
| 허용 (`Allow`) | `Alt+A` | 대기 중인 요청 카드를 한 번 허용하거나 확인한다. |
| 거부 (`Deny`) | `Alt+D` | 대기 중인 요청 카드를 거부하거나 취소한다. |
| 권한 보기 (`Permissions view`) | `Ctrl+Alt+P` | 도구 화면의 권한 항목을 연다. |

- 보내기에는 `Enter`와 `Ctrl+Enter`만 쓸 수 있다. 다른 값은 기본값으로 돌아간다.
  - `Enter`: Enter로 보내고 Shift+Enter로 줄을 바꾼다.
  - `Ctrl+Enter`: Ctrl+Enter로 보내고 Enter로 줄을 바꾼다.
- 보낼 대상 목록은 팀, 에이전트, 실행 중인 구성원 순이고 각각 이름순이다. 목록 양 끝을 지나면 지금 대화 상대로 돌아간다.
- 컨텍스트 바구니에서는 위·아래 방향키로 파일 사이를 옮기고, 쪽도 넘어간다. `Space`로 체크하거나 푼다.
  `Esc`나 같은 단축키를 다시 누르면 닫히고 입력창으로 돌아간다.
- 권한 모드를 실제로 바꾸면 POMP가 다시 시작된다. [승인 모드 선택지](#승인-모드-선택지)를 참고한다.

### VS 전체

| 단축키 | 기본값 | 하는 일 |
|---|---|---|
| POMP 열기 (`Open POMP`) | `Shift+Alt+Q` | POMP 창을 열고 입력창에 포커스를 둔다. |
| 새 대화 (`New conversation`) | `Shift+Alt+N` | 새 대화를 시작한다. |
| 편집기·채팅 포커스 전환 (`Toggle editor and chat focus`) | `Alt+J` | 편집기와 채팅 입력창 사이에서 포커스를 옮긴다. 채팅 창 안에서도 통한다. |
| Live 변경 따라가기 전환 (`Toggle Live edit following`) | `Alt+L` | 적용된 변경 따라가기를 켜거나 끈다. 채팅의 Live 아이콘과 같다. |
| POMP 북마크 전환 (`Toggle POMP bookmarks`) | `Alt+K` | POMP 변경 북마크를 켜거나 끈다. 채팅의 북마크 아이콘과 같다. |

Live 변경 따라가기 전환과 POMP 북마크 전환은 메뉴에 없다. 모델을 호출하지 않으며, 두 설정은 서로 독립이다.
채팅 창에서도 쓸 수 있다. 채팅에서 누르면 입력창에 포커스를 두고, 다른 검색·편집 입력란의 키는 가로채지 않는다.

### 텍스트 편집기

| 단축키 | 기본값 | 하는 일 |
|---|---|---|
| 이 코드 설명 (`Explain this code`) | `Shift+Alt+E` | 선택한 코드를 설명해 달라고 채팅으로 보낸다. |
| 이 코드 리뷰 (`Review this code`) | `Shift+Alt+R` | 선택한 코드를 리뷰해 달라고 채팅으로 보낸다. |
| 이 코드 고치기 (`Fix this code`) | `Shift+Alt+F` | 선택한 코드를 고쳐 달라고 채팅으로 보낸다. |
| 테스트 작성 (`Write tests`) | `Shift+Alt+U` | 선택한 코드의 테스트를 작성해 달라고 채팅으로 보낸다. |
| 컨텍스트 바구니에 추가 (`Add to context basket`) | `Shift+Alt+I` | 현재 파일을 다음 메시지의 컨텍스트 바구니에 넣는다. |
| POMP에게 질문 (`Ask POMP`) | `Alt+M` | 선택 영역에 대해 질문하거나 바꿀 지시를 입력하는 질문 창을 연다. |
| 지식에 추가 (`Add to knowledge`) | `Alt+/` | 선택한 줄을 담아 POMP 창에 지식 추가 양식을 연다. 선택이 없으면 커서 줄을 담는다. |

- 이 코드 설명은 선택이 없으면 커서를 감싸는 멤버를 먼저 선택한다. 멤버가 없으면 커서 줄을 선택한다.
  질문 범위는 [화면 안내의 편집기 우클릭 메뉴](screen-guide.md#2-편집기-우클릭-메뉴)를 참고한다.
- 지식 추가 양식에서는 이름으로 지식을 고르거나 새 지식을 만든다.
