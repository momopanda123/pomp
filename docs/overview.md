# POMP 개요

POMP는 Visual Studio 도구 창에서 AI 에이전트와 함께 코딩하는 확장이다. 질문에 답하는 채팅에 그치지 않고, 에이전트가 VS의 편집기·
솔루션·빌드·디버거를 직접 도구로 써서 일을 하고, 사용자는 바뀔 내용을 확인해 승인한다.

## 어떻게 동작하나

```
 Visual Studio
 ┌──────────────────────────────────────────────────────────────┐
 │  편집기 · 솔루션 · 오류 목록 · 빌드 · 테스트 · 디버거 · Git     │
 │        ▲  VS 도구 (읽기는 바로, 변경·실행은 승인 뒤)            │
 │        │                                                     │
 │  POMP 도구 창 (WebView2 채팅 화면)                            │
 │        │                                                     │
 └────────┼─────────────────────────────────────────────────────┘
          ▼
   모델 공급자 (구독 계정 로그인 또는 API 키)
```

- **POMP**는 VS 안에서 실행되며 에이전트가 요청한 VS 작업을 수행하고 사용자에게 승인을 받는다.
- **에이전트**는 대화·계획·도구 호출을 맡는다. POMP가 시험한 구성이 VSIX에 그대로 들어 있고, 시작할 때 크기와 SHA-256으로
  무결성을 확인한다.
- **채팅 화면**은 오프라인 번들 웹 화면(WebView2)이다. VS 테마 색을 그대로 쓰고, 화면 언어는 VS 표시 언어를 따른다(옵션에서 한국어·
  English 고정 가능).
- 코드와 질문은 사용자가 연결한 **모델 공급자**로만 간다. POMP 자체는 어떤 서버에도 데이터를 보내지 않는다.

## 할 수 있는 일

| 영역 | 내용 |
|---|---|
| 편집기 | 현재 문서·선택 영역 읽기, 저장하지 않은 버퍼 읽기, 해시로 확인한 줄 편집(파일별 Undo 1단계, 자동 저장 안 함), 큰 파일의 심볼 개요 |
| 솔루션 | 프로젝트·파일 탐색, 프로젝트 파일 추가·이름 변경, MSBuild 속성 조회 (파일 삭제·이동은 기본 도구의 승인을 거친다) |
| 빌드·진단 | 솔루션/구성 빌드, 오류 목록, 출력 창 |
| 테스트 | 테스트 탐색과 실행 (둘 다 승인) |
| 디버거 | 디버그 상태·호출 스택, 중단점 추가·제거·켜기·끄기(조건·적중 횟수·추적점), 시작·계속·일시 중지·중지·단계 실행 |
| NuGet | 설치된 패키지 조회, 한 프로젝트의 설치·업데이트·제거 (승인) |
| Git | 상태와 Diff, 커밋·푸시 (승인) |
| 책갈피 | 조회·추가 |
| 스킬 · MCP | 스킬 켜고 끄기와 추가·편집·삭제(POMP에 들어 있는 스킬은 켜고 끄기만), MCP 서버 켜고 끄기·연결 테스트·추가·편집·삭제, 고정된 버전으로 준비된 MCP 서버(GitHub·Context7) 설치 |
| 그 밖 | 파일·코드 검색, 셸·터미널 작업(승인), 웹 검색·URL 읽기, MCP 서버 도구, 스킬 |

## 핵심 개념

- **대화** — 채팅 탭의 대화 하나가 세션 하나다. 상단 ▾에서 이전 대화를 다시 열거나 삭제하고, `+`나 `Shift+Alt+N`으로 새 대화를 시작한다.
  삭제는 확인 후 대화 파일을 휴지통으로 옮긴다. 현재 대화를 지우면 먼저 새 대화가 시작된다.
- **편집기 컨텍스트** — 편집기에서 보낸 요청에는 파일과 줄 범위가 함께 간다. 질문 카드 아래 칩(예: `OrderService.cs · 20–43행`)으로 보인다.
  입력창 왼쪽 아이콘으로 끄거나, 클립 아이콘의 컨텍스트 바구니에 파일·폴더·심볼을 담아 다음 메시지에 붙인다(개수 제한 없음).
- **승인** — 변경·실행 전에 승인 카드가 뜬다. 한 번 허용, 거부, 이 세션 동안 허용, 항상 허용 중에서 고른다. VS 도구의 요청을
  거부할 때는 이유를 남겨 에이전트에게 전달할 수 있다.
- **에이전트(역할)** — 맡은 일·지시·모델·추론 단계·도구 범위를 가진 역할이다. POMP에 들어 있는 역할(예: Scout, Reviewer)과 직접 만든
  역할(이 프로젝트 또는 내 모든 프로젝트)이 있다. 역할마다 다른 공급자의 모델을 지정할 수 있다.
- **대화 상대 탭** — 채팅 안에서 에이전트나 팀을 탭으로 열어 그 상대와만 대화한다. 기본(POMP) 탭은 모든 대화를 보여 준다.
  에이전트는 다시 다른 에이전트에게 일을 맡길 수 있다(하위 에이전트, 기본 깊이 2단계).
- **팀** — 둘 이상의 역할을 묶어 목표와 진행 방식(리더 판단·동시에·순서대로)을 정한 실행 단위다. 채팅 작업 카드와 상대 탭에서 구성원
  상태를 보고 하나씩 중지한다. 역할·팀 정의, 대화를 지켜보는 조언자, 이벤트 규칙·프로젝트 훅은 에이전트 탭의 **역할 · 팀 · 조언자 · 자동화**에서 다룬다.
- **지식** — 사용자가 이름과 색을 붙인 참고 자료 묶음이다(도구 탭 › 지식). 편집기 줄을 우클릭으로 넣으면 그 줄이 지식 색으로 칠해진다.
  원문 그대로 또는 정리한 변환본으로 쓰며, 컨텍스트 바구니에서 체크한 지식은 그 대화에 계속 붙고 역할·팀에 체크한 지식은 그 역할·팀에 늘 붙는다.
- **작업** — **진행**은 계획·워크플로·자동 계속, **변경**은 대기 중 제안·격리 결과와 적용됨 기록·되돌리기, **코드 점검**은 에이전트 지적과
  VS 컴파일러 오류·경고다. 항목을 골라 현재 보낼 대상에 해결 요청 하나로 보낸다(편집기 컨텍스트 없음, 최대 50개·12,000자).
  변경 칩 숫자는 대기 항목만 센다. 승인된 명령 작업은 채팅의 해당 도구 카드에 상태·출력·취소가 나온다.
- **도구** — **대화 설정 · 권한 · 스킬 · MCP · 규칙 · 워크플로 · 지식**. 규칙의 첫 구역 **지금 적용 중**은 다음 프롬프트에
  적용할 규칙이다. 스킬은 행의 **채팅에서 사용**으로 입력창에 넣고, 코드 검색 인덱스는 POMP가 자동으로 유지한다.
- **화면 선택** — 하위 화면 칩은 항목 수를 보이고 0도 흐린 채 누를 수 있다. 직접 고르지 않았고 현재 화면이 비었으면 항목이 있는 첫
  화면을 연다. 목록은 열 이름이 있는 표(스위치·배지·줄 끝 아이콘, 검색과 20개씩 페이지)이고, 빈 목록은 열 이름과 빈 줄만 보이며 안내 문구는 없다.
  만들기 버튼은 카드 머리에 있다. 파일 기반 목록·변경 기록에는 새로 고침이 있다.
- **보조 모델** — 계정 탭에서 **빠른 모델 / 채팅 모델과 같게 / 모델 직접 선택**. 자동완성·질문 수정 제안·코드 캡션·지식 변환·입력 예측
  문장에 쓴다. 공급자는 회사·서비스 이름과 **구독 / API 키** 배지로만 보인다. 계정 사용량 구간 이름은 **5시간 / 주간**이며 공급자가 보고하지 않은 구간은 숨긴다.

## 안전 모델

- **기본은 매번 묻기.** 승인 모드의 기본값은 `Always ask`다. 읽기는 바로, 파일·프로젝트 변경과 실행은 승인 뒤에만 한다.
- **보이는 그대로 적용.** 승인 카드의 Diff와 실제로 적용할 편집은 같은 준비 결과에서 나온다. 승인을 기다리는 동안 파일이 바뀌면
  적용하지 않고 다시 읽게 한다. 편집은 편집기 버퍼에만 들어가고 POMP가 디스크에 저장하지 않는다.
- **허용 범위를 알려 준다.** "항상 허용"·"이 세션 동안 허용"은 그 도구의 모든 요청에 적용되며, 카드가 그 범위를 문장으로 보여 준다.
  하위 에이전트 실행을 허용하면 그 에이전트는 끝날 때까지 도구별로 다시 묻지 않는다.
- **프로젝트 정책(선택).** 솔루션 폴더의 `.pomp/permissions.json`으로 프로젝트를 더 좁게 제한할 수 있다. 파일이 있으면 기본 거부로
  동작한다. 예제는 POMP 저장소의 `examples` 폴더에 있다.
- **확장은 기본 차단.** 사용자 프로필이나 솔루션의 확장·훅은 기본으로 불러오지 않는다(옵션으로 켤 수 있음).
- **샌드박스가 아니다.** 경로 검사는 솔루션 폴더 밖과 reparse point를 막지만, 셸·MCP 도구까지 가두는 OS 샌드박스는 없다. 신뢰할 수
  없는 저장소의 도구 규칙·MCP 설정 같은 실행 설정은 먼저 검토한다. POMP는 시작 전에 신뢰 카드에서 검토할 파일을 보여 준다.
- **네트워크 도구.** 웹 검색·URL 읽기·GitHub·브라우저 도구는 기본으로 허용되며 모든 호출을 기록한다. 옵션 **네트워크 도구 차단**으로 끌 수
  있다.

## 데이터와 개인정보

- 프로젝트에 대한 POMP 내용은 모두 그 프로젝트의 `.pomp\` 폴더에 있다: 프로젝트 범위로 만든 에이전트·팀·규칙·워크플로·스킬·훅·권한 정책은
  `.pomp\` 바로 아래, 대화·컨텍스트 프리셋·지식·체크포인트 같은 POMP 자체 데이터는 `.pomp\local\`(자체 `.gitignore`로 커밋에서 빠짐).
  `.pomp` 폴더를 지우면 그 프로젝트의 POMP 내용이 초기화된다. 작업 영역 신뢰와 항상 허용한 도구 승인은 보안상 프로젝트 밖에 남는다.
- 그 밖의 런타임 데이터는 `%LOCALAPPDATA%\Pomp\`에 있다: 로그(`logs\pomp-vs.log`), 에이전트 설정 오버레이, WebView2 데이터, 솔루션이 없을 때의
  작업 폴더.
- 계정 탭에서 저장한 API 키는 현재 Windows 사용자용 DPAPI로 암호화해 `%LOCALAPPDATA%\Pomp\credentials\`에 저장하고, 다음 시작 때
  환경 변수로만 전달한다. 키 원문은 화면·로그에 나오지 않는다.
- 사용 통계(도구별 승인 수, 편집 정확도, 채팅 로드 시간, 재시작)는 `%LOCALAPPDATA%\Pomp\usage-metrics.json`에만 남는다.

## 알려진 한계

- 다시 시작하면 같은 작업 영역의 직전 대화를 확인해 복원한다. 복원할 수 없으면 기록은 남기고 재시도·다른 대화·새 대화를 고른다.
- 대화를 다시 열 때 그 대화에 저장된 모델이 모델 목록에 없으면(목록에서 빠짐, 공급자 로그아웃) 지금 모델로 열고 채팅에 알린다. 옵션의 모델이 목록에 없으면 기본 모델로 시작하고 알린다.
- 자동완성·코드 캡션·입력 예측 문장·POMP 워크플로 자동 계속·실험적 AppContainer 실행기는 기본 꺼짐이다. 모델 기능을 켜면 호출 비용이
  생길 수 있다. 대화형 터미널 카드는 옵션·엔진 지원이 모두 필요하며 함께 들어 있는 엔진에서는 보이지 않는다.
- 실제 검증은 VS 2019 16.11과 VS 2026 18.10 실험 인스턴스에서 했다. VS 2022는 직접 실행해 보지 않았다(VS 2026과 같은 패키지).
