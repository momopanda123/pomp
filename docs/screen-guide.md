# POMP 화면 가이드

실제 Visual Studio 2019에서 POMP를 쓰는 장면으로 각 화면과 버튼을 설명한다. 처음 쓰는 순서는 [빠른 시작](quick-start.md).

## 1. 전체 모습

![Visual Studio 안의 POMP](media/vs-overview.png)

- 왼쪽은 평소의 코드 편집기, 오른쪽이 **POMP 도구 창**이다. 다른 도구 창처럼 원하는 위치에 붙이거나 띄울 수 있다.
- 편집기의 선언 위에 보이는 작은 줄(**AI 설명 · 채팅**)은 선택 기능인 코드 캡션이다(기본 꺼짐, POMP 메뉴에서 켬). 누를 때만 모델을 부른다.
- POMP 창 맨 위 탭 막대: **채팅 · 작업 · 에이전트 · 도구 · 계정**. 오른쪽의 점은 연결 상태(초록 = 연결됨, 노랑 = 시작 중 또는
  공급자 연결 필요, 빨강 = 실패 — 누르면 다시 연결), `⋯`는 로그 보기·다시 시작, `⚙`는 도구 > 옵션 > Pomp.
- 창이 좁으면(300px 미만) 탭은 아이콘만 보이고 이름은 툴팁으로 나온다.
- 작업·에이전트·도구의 하위 화면 칩에는 항목 수가 붙는다. 0개인 칩은 흐리게 보이지만 눌러 열 수 있다. 아직 이 대화에서
  화면을 직접 고르지 않았고 현재 화면이 비어 있으면 항목이 있는 첫 화면을 연다. 직접 고른 화면은 이 대화에서 유지한다.
  각 구역은 카드이고, 목록은 열 이름이 있는 표다. 켜기·끄기는 스위치, 상태는 색 배지, 줄의 편집·삭제·열기 같은 동작은 줄 끝 아이콘(이름은 툴팁)이다.
  길어질 수 있는 목록은 검색과 20개씩 페이지가 있다. 빈 목록은 열 이름과 빈 줄만 보이며 빈 상태 안내를 두지 않는다. **+ 새 역할**·**+ 새 규칙** 같은
  추가 버튼은 카드 머리에 있다. 파일 목록과 적용된 변경 기록처럼 화면 밖에서 바뀔 수 있는 자료에는 새로 고침이 있다.

## 2. 편집기 우클릭 메뉴

![편집기 우클릭 메뉴](media/editor-menu.png)

코드 편집기에서 우클릭하면 VS 기본 항목(빠른 작업·이름 바꾸기·Using 제거 및 정렬) 아래에 POMP 항목 두 개가 있다.

| 항목 | 단축키 | 하는 일 |
|---|---|---|
| POMP에게 질문 | `Alt+M` | 질문 창을 연다. 선택 영역에 대해 채팅으로 질문하고, 같은 창에서 그 자리의 수정 제안도 받을 수 있다(고칠 수 없는 파일에서는 수정 제안이 꺼진다) |
| POMP ▸ 이 코드 설명 / 리뷰 / 고치기 | `Shift+Alt+E` / `R` / `F` | 선택한 코드를 채팅으로 보내 바로 요청한다 |
| POMP ▸ 테스트 작성 | `Shift+Alt+U` | 선택한 코드의 테스트를 작성하게 한다 |
| POMP ▸ 파일을 채팅 컨텍스트에 추가 | `Shift+Alt+I` | 현재 파일을 다음 메시지에 붙인다 |
| POMP ▸ 지식에 추가 | `Alt+/` | 선택한 줄(선택이 없으면 커서 줄)을 담아 도구 탭 › 지식의 **지식에 추가** 양식을 연다. 이름을 입력하면 그 글자가 들어간 지식이 최대 8개 보이고(비어 있으면 최근 지식), 고르거나 같은 이름을 입력하면 그 지식에 조각으로 들어간다. 없는 이름이면 색·범위를 정해 새 지식이 된다. 넣은 줄은 그 지식의 색으로 줄 배경이 칠해진다([§8](#8-도구-탭)) |
| POMP ▸ 에이전트·팀에게 ▸ (이름) | — | 작업 영역의 에이전트·팀이 그대로 목록에 나온다(역할·팀을 만들고 지우면 바로 바뀜; 없으면 "(없음)"; 15개가 넘으면 앞의 14개와 **모두 보기** — 채팅의 보낼 대상 목록이 열린다(10개가 넘으면 검색 칸이 있다)). 고르면 채팅 입력창이 그 상대를 보낼 대상(`→ 이름` 칩)으로 잡고 편집기 컨텍스트를 켠 채 열린다 |
| POMP ▸ POMP 열기 / 새 대화 / 포커스 전환 | `Shift+Alt+Q` / `Shift+Alt+N` / `Alt+J` | 채팅 창 조작. 표의 키는 모두 도구 › 옵션 › Pomp › 일반 › 단축키에서 바꾼다 |
| POMP ▸ 인라인 자동완성 / 코드 캡션 | — | 켜기·끄기 (둘 다 기본 꺼짐, 켜면 모델 비용이 생길 수 있다. 그림은 둘 다 켠 상태) |

질문 창은 VS 테마 색으로 그려지며 테두리는 테마의 도구 창 테두리 색 1px뿐이다(이전의 두꺼운 흰 대화 상자 프레임은 없앴다).
버튼은 채팅으로 질문 → 채팅 입력창으로 → 코드 수정 제안 → 취소 순서이고 단축키를 표시하지 않는다. `Enter`는 채팅으로 질문,
`Shift+Enter`는 채팅 입력창으로 옮기기, `Ctrl+Enter`는 수정 제안, `Esc`는 취소다. 수정 제안은 작업 탭 › 변경의 **변경 제안**으로 가고 승인해야
코드가 바뀐다. 인라인 자동완성은 입력을 멈추면 흐린 제안이 보이고 `Tab` 수락, `Ctrl+→` 한 단어 수락, `Esc` 닫기다.

## 3. 채팅 탭

![채팅 탭](media/chat-explain.png)

위에서부터:

1. **대화 머리** — 대화 이름(누르면 이름 바꾸기), `▾` 전체 대화 목록(검색·전환·미리보기·삭제 — 삭제는 한 번 더 확인하고 대화 파일을 휴지통으로 옮긴다. 지금 대화를 지우면 새 대화가 먼저 시작된다), `+` 새 대화.
2. **대화 상대 탭** — `기본 (POMP)`과 그 오른쪽에 연 에이전트·팀 탭. 활성 탭이 지금 대화하는 상대다. `+`로 추가, `×`로 닫는다.
3. **질문 카드** — 보낸 메시지. 아래 칩(`OrderService.cs · 20–43행`)은 함께 보낸 편집기 위치다(툴팁에 전체 경로).
4. **생각** — 모델의 추론 과정(접혀 있음). 도구 호출은 한 줄 카드로 나오고 `>`로 펼친다. 모델이 요청해 승인받은 명령 작업은
   그 호출의 도구 카드 안에 상태·**출력**·**취소**가 나온다. 에이전트·팀 작업 카드에는 구성원별 상태와 **중지**가 나온다.
5. **답변** — 마크다운으로 표시된다. 위로 스크롤하면 오른쪽 아래에 맨 아래로 가는 화살표 버튼이 나타난다. 200만 자를 넘는 답변은
   뒷부분을 자르고 잘렸다고 알린다.
6. **컨텍스트 묶음**(입력창 위) — 왼쪽부터 `@` 멘션, 클립 첨부, `/` 명령 버튼, 그다음 클립 아이콘 옆 숫자는 다음 메시지에 붙일
   컨텍스트 바구니의 항목 수, 그 옆 아이콘은 편집기 컨텍스트 포함 켜기·끄기, 막대는 컨텍스트 창 사용량(`5% · 12.3k / 272k`,
   70%에서 노랑, 90%에서 빨강). 막대는 출처별 색 구간으로 나뉜다(순서 고정: 시스템 프롬프트 · 도구 · MCP 도구 ·
   규칙·컨텍스트 파일 · 스킬 · 대화), 그 뒤 빗금 구간은 다음 메시지에 붙을 바구니(편집기 컨텍스트·첨부 목록)의 예상치다. 막대를
   누르면(`Enter`/`Space`) 출처별 토큰 수와 비율 목록이 열린다(목록 위 가는 막대는 창 크기와 무관한 사용분의 구성 비율). POMP가
   실제로 센 값이고, MCP와 바구니만 추정(`≈`)이다(대화 토큰을 세지 않는 모델에서는 대화 행도 사용량에서 나머지를 뺀 추정 `≈`). 출처별 값을 얻지 못하면 막대는 한 색으로만 채워진다.
   매 응답이 끝날 때 다시 잰다. `/` 버튼 목록에서 명령을 고르면 맨 앞의 명령만 바뀌고 쓰던 글은 그대로 남는다.
   바구니는 `Alt+;`로 열면 첫 파일에 커서가 가고, 위·아래 방향키로 옮기며 `Space`로 체크한다(`Esc`는 입력창으로). 편집기 컨텍스트 포함은
   `Alt+'`로 켜고 끈다(둘 다 옵션에서 바꿀 수 있다).
7. **입력창** — `Enter` 전송, `Shift+Enter` 줄바꿈(옵션 `단축키 > 보내기`를 `Ctrl+Enter`로 바꾸면 `Ctrl+Enter` 전송, `Enter` 줄바꿈). 빈 입력창에서
   `↑`는 이전에 보낸 입력을, `↓`는 그다음 것을 불러오고, 마지막을 지나면 다시 빈 입력창이 된다(쓰던 글은 바꾸지 않는다). 탐색기·솔루션 탐색기에서 복사한 파일이나 캡처·그림을 붙여넣으면(`Ctrl+V`) 글 대신 바구니에 들어간다(그림은 작업 영역의 `.pomplocalclipboard`에 PNG로 저장된다).
   옵션 **입력 예측 문장**을 켜면 입력을 멈췄을 때 이어질 문장이 커서 뒤에 흐리게 보이고 `Tab`으로 받는다(`Esc`나 다른 입력으로 사라짐).
   오른쪽 `↑`가 전송, 응답 중에는 `■` 중지와 대기열 추가.
8. **입력 막대** — 맨 앞 **권한 모드** 칩(`항상 묻기` · `쓰기 자동` · `모두 자동`; 누르면 고르고, `모두 자동`은 확인 질문을 거친다.
   바꾸면 다시 시작되고 대화는 복구된다 — 응답 중에는 바꿀 수 없다. 모드가 뜻하는 범위는 [설정 안내](settings.md)의
   승인 모드), 사람 아이콘 옆 `POMP`(보낼 대상 칩; 이번 메시지를 받을 상대로, 기본 탭에서만 다른 에이전트·팀으로 바꿀 수 있다), 모델 칩, 뇌 아이콘 추론 단계,
   번개 fast 모드. 고른 대상이 사라지면(역할·팀 삭제, 구성원 종료) 대상을 풀고 입력창 위에 해제됐다고 알린다(글을 고치거나
   대상을 다시 고르면 사라진다). 대상 목록은 `Ctrl+Alt+T`로 열고, `Alt+,` / `Alt+.`는 목록의 이전·다음 대상으로 바로 바꾼다(양 끝을 지나면 대화 상대로). 권한 모드 목록은 `Alt+Q`로 연다(옵션에서 바꿀 수 있다). 화면 입력
   제어(화면 조작)는 **도구 › 대화 설정**에 있다.
9. **사용량 막대**(맨 아래) — 한 공급자의 사용량 한도(5시간·주간)를 한 줄로 보인다. 공급자가 여럿이면 이름과 양옆 `‹` `›`가 생기고 현재 모델의
   공급자부터 시작하며, 화살표로 다른 공급자로 넘긴다(모델을 바꾸면 그 공급자로 돌아온다). 한 줄에 들어가는 만큼의 한도를 보이고 나머지는 `+N`으로
   센다. 공급자가 보고하지 않은 시간 구간은 표시하지 않는다. 누르면 구독별 사용량 전체, `↻`로 새로 고침.
   한도의 초기화 시각이 되면 그 자리에서 새 구간(0%)으로 바뀌고, 응답 중이 아니면 새 사용량을 바로 받아 온다.

**우클릭 메뉴** — 채팅 창에서는 웹 페이지용 메뉴(뒤로·새로 고침·저장·인쇄·검사)가 나오지 않는다. 메시지에서는 **메시지 복사**와
(선택한 글이 있으면) **선택 영역 복사**, 코드 블록에서는 **코드 복사**와 (가능할 때) **검토로 보내기**, 첨부 칩과 컨텍스트 바구니
항목에서는 **경로 복사**(바구니는 **제거**도)가 나온다. 지난 대화를 열어 복원한 메시지에도 같은 메뉴가 나온다. 입력창에서는
잘라내기·복사·붙여넣기 같은 편집 메뉴만 나온다. 키보드에서는 `Shift+F10` 또는 메뉴 키로 열고 방향키·`Enter`·`Esc`로 쓴다.

### 채팅 명령

입력창에 `/`를 치거나 `/` 버튼을 누르면 명령 목록이 열린다. 같은 일을 하는 명령은 하나만, 쉬운 이름 하나로 나온다.

1. **채팅 화면이 직접 처리하는 명령** — `/new` 새 대화 · `/sessions` 대화 목록 · `/rename` 이름 바꾸기 · `/model` · `/thinking` · `/effort`(추론 단계 고르기)
   · `/permissions`(입력 막대의 권한 모드 목록 열기) · `/compact [지침]`
   (대화 압축) · `/accounts` · `/login` · `/usage` · `/work` · `/agents` · `/computer` · `/agent 이름 메시지`
   · `/team 이름 메시지` · `/goal 목표` · `/help`.
2. **POMP의 명령** — `/workflow 작업`(단계별 워크플로 시작) · `/plan 작업` · `/map [초점]`(코드베이스 구조 지도 설명) · `/review [초점]`(소스 검토) ·
   `/max`(컨텍스트 100만 토큰 모델 고르기) · `/rules` · `/resources` · `/guard`(저장 안 한 VS 변경 가드) · `/vs-status`(VS 연결 상태) ·
   `/skill 이름` · `/command 이름` · `/recipe 이름`(`.pomp`의 스킬·명령·레시피 불러오기).
   직접 만든 명령이 같은 이름이면 그쪽이 이름을 지킨다.
   `/workflow` · `/plan` · `/map` · `/review` · `/skill` · `/command` · `/recipe`, 스킬, 직접 만든 프롬프트 파일 명령은 바구니에서 체크한 파일을
   함께 받아 그 파일들만 다룬다(보내면 바구니가 비워진다). 그 밖의 명령은 바구니를 쓰지 않고 그대로 둔다.
3. **그 밖의 명령** — `/context`(컨텍스트 사용량) · `/fast`(빠른 모드) · `/tools`(사용할 수 있는 도구) · `/mcp`(MCP 서버 관리), 그리고 직접 만든 명령·MCP 프롬프트가
   이름만으로 나온다.
4. **스킬** — 목록 맨 아래 **스킬** 머리 아래에 켜 둔 스킬(기본·사용자·프로젝트)이 `/이름`으로 나온다. 같은
   이름의 명령이 있으면 명령이 이기고 스킬은 `/skill:이름`으로 남는다. 도구 › 스킬에서 끈 스킬은 나오지 않는다.

**`/plan 작업`** — 계획만 세운다. 이번 응답에서 모델은 읽기·검색·웹 조회와 계획 도구(작업 탭 › 진행에 나오는 계획)만 쓸 수 있고, 파일 편집·명령 실행·
하위 에이전트 시작·VS 편집 도구는 거부된다. 응답이 끝나면 풀리고, 모델이 스스로 풀 수 없다. 계획은 작업 탭 › 진행 › 작업 계획에서 고치고
**이어가기**로 실행하며, `/goal`이나 자동 계속으로 이어 갈 수도 있다. 작업 없이 `/plan`만 치면 입력창에 오류가 보인다. 모델에게 "계획만
세워 줘"라고 말로 시켜도 모델이 같은 가드를 걸 수 있다.

**`/goal 목표`** — 워크플로를 시작하고 그 워크플로에 **자동 계속**을 켠다(최대 6회, 선택 토큰 예산). 실행마다 모델 사용 비용이 들므로 먼저
채팅 안에 **목표 실행** 카드가 나온다 — 목표 글(고칠 수 있음), **토큰 예산**(비우면 없음), 질문 "이 목표를 자동으로 이어서 실행할까요?",
**시작** / **취소**(`Enter` 시작, `Esc` 취소, 목표 글 안의 `Shift+Enter`는 줄바꿈). 카드가 나온 뒤 잠깐은 키가 듣지 않고, 응답 중에는 **시작**이
눌리지 않는다. 시작하면 채팅에 `/goal 목표`가 보이고, 워크플로가 만들어지면 자동 계속이 켜졌다는 알림이 나온다. 진행 중인 워크플로가 있거나 응답 중이거나
워크플로 명령을 쓸 수 없으면 시작하지 않고 카드에 이유를 보인다. 토큰은 목표를 시작한 때부터 센다(첫 실행도 목표에 든다). 모델에게 "이 목표를 알아서
계속해 줘"라고 말로 시켜도 같은 카드가 나오며, 카드에서 시작하기 전에는 아무것도 시작하지 않는다. 에이전트·팀 탭에서는 쓸 수 없다.

### 케이스별 피드백

모델이 여러 방법·시나리오·테스트 케이스를 케이스로 나눠 보여 주면, **그 답변 안에 케이스 카드**가 차례로 나온다. 채팅에서
`/case-review`로 "케이스로 나눠 보여 줘"를 시킬 수도 있다.

- 카드마다 제목, 설명, (있으면) 작업 영역 안의 이미지나 다이어그램, **의견** 입력란이 있다. 이미지는 작업 영역 안의 파일만 POMP가 읽어 보여 주고
  인터넷에서 가져오지 않는다. 불러오는 동안 "이미지를 불러오는 중"이 보이고, 읽지 못하면 이유와 **다시 시도**가 나온다.
  다이어그램(Mermaid)은 화면 안에서만 그리고, 그릴 수 없으면 원문을 보여 준다.
- 의견을 적은 케이스만 보낸다. 답변 맨 아래 **의견 N개 보내기**가 적은 의견을 메시지 하나로 묶어 그 대화의 대기열에 넣는다. 의견을 비운 케이스는
  보내지 않으며, 모델은 그것을 승인으로 보지 않는다. 보낸 메시지는 채팅에 "케이스 의견 N개"와 케이스 제목·의견으로 보이고, 대기열과 대화 목록
  미리보기에는 한 줄 요약으로 보인다.
- 적는 중인 의견은 잠시 뒤 저절로 초안으로 저장돼, 대화를 다시 열어도 남아 있다. 보낸 뒤에는 카드가 읽기 전용이 된다.
- 보내기는 파일 변경이나 명령 실행 승인이 아니다. 보낸 결과를 확인하지 못하면 중복을 막기 위해 다시 보내지 않으니 채팅과 대기열을 확인한다.

### 다시 연결할 때

동일 작업 영역에서 다시 시작하면 직전 대화의 ID와 파일을 확인해 복원을 시도한다.
확인이 끝나기 전에는 전송할 수 없다. 실패해도 표시된 기록은 지우지 않으며 **복원 재시도 / 다른 기록 열기 / 새 대화** 중에서 선택할 수 있다.
화면 기록 보존과 대화 복원은 별개다. 실행 중이던 작업·승인·훅·일시정지된 대기열을 자동 재개하지 않는다.

### 작업 영역 신뢰

시작할 때 그대로 실행하거나 따르는 설정이 저장소에 있으면, 시작하기 전에 채팅 화면에 **이 저장소의 에이전트 설정을
신뢰할까요?** 카드가 나온다(탭 막대의 연결 점은 "신뢰 확인 필요").

- 목록에는 파일마다 종류가 붙는다: 에이전트 설정(도구 자동 승인 등을 바꿀 수 있음), MCP 서버(서버 수), 도구 코드, 언어 서버(설정 파일과
  `node_modules/.bin` 등 저장소 안 실행 파일), 플러그인, 바깥 파일 포함(작업 영역 밖 파일을 `@경로`로 끌어오는 `AGENTS.md` 같은 파일과
  그 대상). "발견된 확장 불러오기"를 켰다면 확장 코드도 나온다. 역할·규칙·스킬처럼 지시문만 담은 파일은 묻지 않는다.
- 줄마다 **파일 열기**로 VS에서 내용을 확인한다. **신뢰하고 시작**은 보이는 목록 그대로를 이 폴더에 대해서만 기억하고 시작한다.
  **시작 안 함**은 시작하지 않고 카드를 남겨 둔다(나중에 신뢰할 수 있다).
- 파일이 바뀌거나 새로 생기면(git pull, 에이전트의 수정 포함) 다음 시작 때 다시 묻는다. 목록을 보는 사이 바뀌었으면 신뢰하지 않고
  바뀐 목록을 보여 준다. 도구 › MCP에서 직접 바꾼 MCP 서버는 이미 준 신뢰를 그대로 유지한다.
- 해제는 도구 › 권한 › **신뢰한 저장소**에서 한다. 지금 쓰는 저장소를 해제하면 다시 시작되며 카드가 다시 나온다.
- 저장소 폴더가 아니라 POMP 데이터 폴더에서 시작하므로 저장소의 `.env` 파일은 설정에 쓰이지 않는다.

## 4. 승인 카드

![승인 카드](media/approval-card.png)

에이전트가 무언가를 바꾸거나 실행하려 하면 대화 맨 아래에 승인 카드가 나온다(다른 탭을 보고 있으면 채팅 탭에 점이 붙는다). 카드가
있는 동안에도 대화·입력창·다른 탭은 그대로 쓸 수 있고, 답하면 카드는 제목과 결과(허용함·거부함·만료됨 등) 한 줄로 대화에 남는다.
`Enter`가 허용(한 번), `Esc`가 거부다. 포커스가 카드에 있을 때뿐 아니라 빈 입력창이나 대화의 빈 곳에 있어도 그렇다(입력창에 쓰던 글이
있으면 그 글의 키로 남는다). 어디서나 `Alt+A`/`Alt+D`로도 답할 수 있다(조합은 옵션에서 바꾼다). 카드는 화면에 들어오는 대로 포커스를
가져간다. 카드가 나타난 뒤 0.5초 동안은 어떤 입력도 답으로 받지 않고, 대화를 위로 올려 둬서 카드가 화면 밖에 있으면 포커스를 가져가지도
`Enter`·`Esc`를 받지도 않는다(`Alt+A`/`Alt+D`만 통한다). 확장이 묻는 질문(선택·확인·입력)도 같은 자리에 카드로 나온다(`Esc` 취소,
`Enter`는 확인·선택한 항목, 글을 입력하는 질문은 입력칸으로 커서만 옮긴다).

- **제목과 배지** — 무엇을 하려는지(여기서는 "하위 에이전트에게 작업 맡기기"), 종류 배지(`에이전트 실행`), 누가 묻는지(`기본 도구`)와
  도구 이름(`task`).
- **요약** — 맡길 에이전트(여기서는 `검토`), 작업 미리보기, 작업 수. 파일 변경이면 Diff가 나온다(넓은 창은 나란히, 좁은 창은 한 줄씩).
- **주의 문장** — 하위 에이전트 실행처럼 위험한 승인에만 한 줄: 허용하면 끝날 때까지 도구별로 다시 묻지 않는다.
- **전체 요청 내용 보기** — 모델이 보낸 원래 요청 전체.
- **버튼** — 허용(한 번) · 거부 · 항상 허용 · 이 세션 동안 허용. "항상 허용"은 이 작업 영역에서, "이 세션 동안 허용"은 이 세션 동안
  그 도구의 모든 요청에 적용된다. VS 도구의 카드에는 거부 이유 입력란도 있다.
- **매번 확인하는 요청** — 명령 실행, Git 쓰기, 패키지 변경, 디버거(`debug` 포함), 테스트 실행, 하위 에이전트(`task`), 컴퓨터·브라우저
  사용, 프로젝트 정책·에이전트 설정 파일(`mcp.json`, `AGENTS.md`, `node_modules/.bin` 등) 수정은 기억하지 않는다. 이런 카드에는
  허용(한 번)과 거부만 있다.
- 솔루션·폴더를 바꾸면 "이 세션 동안 허용"이 지워지고, 새 작업 영역에서 다시 연결될 때까지 들어온 요청은 거부된다.

화면에는 설명 문구를 두지 않는다: 단축키(승인 `Alt+A`/`Alt+D`, 입력창 `Enter`/`Shift+Enter`, 대상 고르기 `Ctrl+Alt+T` 등)와 동작 설명은
이 안내서와 [설정 안내](settings.md)에만 있고, 조합은 도구 > 옵션 > Pomp > 일반 > 단축키에서 바꾼다. 승인을 기다리는 동안에는 보낼 수
없지만 다음 메시지 초안은 미리 써 둘 수 있다. 권한 모드가 `쓰기 자동`이면 VS 도구의 파일·프로젝트·중단점·북마크 변경은 묻지 않고,
`모두 자동`이면 강제로 묻는 것(위험 명령의 사유, 공급자 안전 확인)과 화면·브라우저 조작만 묻는다.

## 5. 에이전트 대화 상대 탭

![에이전트 위임](media/partner-delegation.png)

- `검토` 탭은 검토 에이전트에게 간 대화를 보여 준다. 질문 카드 위의 `→ 검토`가 받은 상대다.
- 에이전트 탭에 보낸 메시지는 POMP가 그 에이전트를 하위 에이전트로 실행해 전달한다. 화면의 `task`(검토 에이전트 실행 — 앞의 승인
  카드가 이것)와 `wait`(결과 대기)가 그 과정이다. `task` 아래 작업 카드에 구성원 상태(`완료 · 4 개 도구 · 25.9s`)와 최근 도구가 보인다.
  검토 에이전트는 다시 scout에게 확인을 맡겼고(승인을 다시 묻지 않음, 에이전트 작업 카드에 구성원으로 보인다), 결과를 받아 한 문장으로 답했다.
- 입력 막대의 대상 칩은 `검토`로 고정된다. 다른 상대에게 보내려면 그 상대의 탭으로 가거나 기본(POMP) 탭에서 대상을 고른다.
- 탭을 오가도 에이전트별 맥락은 이어진다(연결이나 대화가 바뀌면 새로 시작).
- 그 상대의 작업 카드에서도 구성원별 상태·도구 수·시간·최근 도구와 **중지**를 본다. **중지**는 같은 줄에서 한 번 더 확인한 뒤
  그 구성원만 멈춘다. 다른 구성원과 메인 대화는 계속되고, 메인 대화는 취소된 결과를 받는다. 채팅 입력창의 중지는 전체 응답을 멈춘다.

## 6. 에이전트 탭

하위 화면은 **역할 · 팀 · 조언자 · 자동화**다. 실행 진행과 구성원별 중지는 채팅의 작업 카드와 에이전트·팀 대화 상대 탭에서 본다.

### 역할

- **역할** 카드 하나에 모든 역할이 표로 나온다. 위에 검색과 범위 거르기(**전체 · 프로젝트 · 사용자**, 칸마다 개수)가 있고 20개씩 페이지로 나뉜다.
- 맨 위 줄은 **POMP**, 대화창에서 사용자와 직접 일하는 에이전트 자신이다. **전체**에만 나오고 삭제할 수 없다. 배지는 **채팅 모델**,
  지시가 있으면 그 범위(프로젝트 · 사용자), **모든 도구**다. 그림을 누르면 다른 역할처럼 그림 편집 창이 열리고(내 모든 프로젝트에 같은 그림),
  **편집**은 POMP 지시 편집 창을 연다: 저장 범위(이 프로젝트 · 내 모든 프로젝트)와 지시 사항. 지시는 엔진이 POMP의 시스템 프롬프트 끝에 붙이는
  `APPEND_SYSTEM.md`(이 프로젝트: 저장소 루트의 `.omp/APPEND_SYSTEM.md`, 내 모든 프로젝트: POMP 사용자 설정 폴더의 `APPEND_SYSTEM.md`)에 저장되고,
  비우고 저장하면 그 파일이 지워진다. 프로젝트 지시가 있으면 사용자 지시는 쓰이지 않는다(편집 창에서 **가려짐**). 엔진은 시작할 때 지시를 읽으므로,
  바꾼 뒤에는 표 위에 **POMP 지시가 아직 적용되지 않았어요.**와 **다시 시작** 단추가 나오고, 다시 시작하면 사라진다.
- 줄마다 역할 그림(기본은 이름 첫 글자 동그라미), 표시 이름과 식별자, 설명 한 줄, 배지가 있다. 표시 이름은 역할 파일(POMP에 들어 있는 역할은 그 역할 자체)이 정한 그대로다. 배지는 모델(**채팅 모델** · **빠른 모델** · 모델 이름),
  범위(프로젝트 · 사용자; POMP에 들어 있는 역할은 범위 배지 없음), 도구 범위(**모든 도구** · **읽기 도구** · **직접 지정 도구**)이고, 해당할 때 **가려짐**(같은 이름의
  역할이 앞서 쓰여 이 역할은 쓰이지 않음: 사용자 → 프로젝트 → POMP에 들어 있는 역할 순), **VS에서 편집**(화면의 편집 창이 다시 쓸 수 없는 파일), **파일 오류**(설명 자리에 오류 내용),
  **모델 없음**(지정한 모델의 공급자가 연결되지 않아 지금은 채팅 모델로 실행)이 붙는다.
- 역할 그림을 누르면 그림 편집 창이 열린다: 모양(**원 · 둥근 사각형 · 사각형 · 육각형**), 색(**자동**, 고정 색 동그라미, 끝의 **+** 동그라미로
  여는 색 고르기 — 채도·밝기 영역, 색상 막대, HEX 칸; 고른 색은 + 앞에 동그라미로 남는다), 이미지(**이미지 선택**·제거), **기본값으로 · 취소 · 저장**.
- 줄 끝 아이콘 — 편집 창으로 고칠 수 있는 역할은 **메시지 · 편집 · 삭제**, POMP에 들어 있는 역할은 **메시지 · 복제 · 편집**, 편집 창이 다룰 수 없는
  파일(여러 줄 설정이 있는 파일)은 **메시지 · VS에서 열기 · 삭제**, 형식 오류 파일은 **VS에서 열기 · 삭제**다.
  **메시지**는 그 역할의 대화 상대 탭을 연다. **삭제**는 한 번 더 확인한다.
- **+ 새 역할** 편집 창 — 설계자·구현자·리뷰어·테스터·문서 작성자·탐색자 템플릿에서 시작할 수 있고, 저장 범위(이 프로젝트 · 내 모든 프로젝트),
  표시 이름, 식별자 이름, 맡은 일, 설명, 지시 사항, 모델(채팅 모델과 같게 / 빠른 모델 / 특정 모델 선택), 추론 단계, 도구 범위(모든 도구 / 읽기 도구)를 정한다.
- **복제**는 POMP에 들어 있는 역할의 이름·설명·모델·추론 단계·도구 범위를 채운 새 역할(`이름-copy`) 편집 창을 연다. 지시문은 복사되지 않으니
  직접 적는다.
- POMP에 들어 있는 역할의 **편집**은 그 역할의 설명·지시문·모델·추론 단계·도구를 채운 편집 창을 연다(식별자는 바꿀 수 없다). 저장하면 고른 범위에
  같은 이름의 역할 파일이 생기고 그 역할 대신 쓰인다(원래 줄에는 **가려짐**). 그 파일을 삭제하면 원래 역할로 돌아간다. 도구를 직접 지정한 역할은
  도구 범위에 **직접 지정 도구**가 있고, 그대로 두면 그 도구 목록이 유지된다.
- 역할 편집 창의 **지식**에서 고른 지식은 그 역할이 구성원으로 일할 때 늘 함께 간다. 저장할 때 적용되고, 지식 자체는 도구 탭 › 지식에서
  관리한다([§8](#8-도구-탭)).

### 팀

- **팀** 카드 머리의 **가져오기** · **+ 새 팀**, 검색, 20개씩 페이지. 줄마다 팀 이름과 식별자, 목표(없으면 구성원 순서), 배지(진행 방식:
  리더 판단 · 동시에 · 순서대로, 범위, **격리**, **가려짐**, **구성원 N명 없음**, **파일 오류**), 구성원 동그라미(찾을 수 없는 구성원은 점선 경고 표시)가 있다.
- 줄 끝 아이콘은 **메시지**(실행할 수 있는 팀만, 그 팀의 대화 상대 탭을 연다) · **편집** · **내보내기** · **삭제**(한 번 더 확인)다.
- 팀 편집 창 — 저장 범위, 표시 이름, 팀 식별자, 팀 목표, 구성원 2명 이상(위로·아래로·빼기, 많으면 쪽 넘김; 그 아래 역할 표에서 검색해 **+**로 추가, 8개씩 페이지), 진행 방식, 지시 사항, 스위치 **구성원 외 에이전트 호출 차단**과
  **격리된 복사본에서 실행**, 지식.
- **격리된 복사본에서 실행**을 켜면 구성원이 따로 만든 복사본에서 일한다(Git 저장소 필요, 팀 줄에 **격리** 배지). 결과는 바로 파일에 쓰이지 않고
  작업 탭 › 변경 › 대기 중의 **격리 실행 결과**에서 기다린다. 격리 팀은 매번 새로 시작한다.
- **내보내기**는 팀과 팀이 쓰는 사용자 정의 역할을 글 하나(JSON)로 보여 준다. **복사**하거나 **편집기에서 열기**로 VS에서 열어 저장하고 **닫기**로 닫는다.
  **가져오기**에 그 글을 붙여 넣고 가져올 범위(이 프로젝트 · 내 모든 프로젝트)를 고른 뒤 **미리보기**를 누르면 팀과 역할마다 상태 배지
  (새로 만듦 · 이미 있음 · 이름 겹침 · 이 PC에 있음)가 표로 나온다. 이름이 겹치거나 같은 팀이 이미 있으면 가져올 수 없고, 새 파일만 만든다.
- 팀 편집 창의 **지식**에서 고른 지식은 그 팀에 메시지를 보낼 때 늘 함께 간다. 저장할 때 적용된다.

### 조언자

조언자는 대화 옆에서 주 에이전트의 작업을 지켜보고 의견을 내는 에이전트다. 정의는 저장소 루트의 `WATCHDOG.yml`(이 프로젝트)과
POMP 사용자 설정 폴더의 `WATCHDOG.yml`(사용자)에 있다(`.yaml`도 읽는다).

- **이 대화** — 머리에 상태 배지(꺼짐 · 모델 없음 · 사용 중 N · 일시 정지 · 상태 미확인)가 있고, 표에는 정의된 조언자마다 한 줄씩 조언자 · 모델과
  줄 끝의 **기록**과 **사용** 스위치가 있다(8개씩 페이지, 8개가 넘으면 검색). 이름 아래 작은 글씨는 그 조언자가 쓴 컨텍스트 비율과 비용이다.
  - **사용** — 그 조언자를 이 대화에서만 켜고 끈다(정의 파일은 바뀌지 않는다). 아무 조언자도 돌지 않을 때 하나를 켜면 그 조언자만 돌고,
    마지막 하나를 끄면 이 대화의 조언자가 모두 멈춘다. 편집 창에서 **일시 정지**해 둔 조언자는 새 대화에서 꺼진 채 시작한다.
  - **기록** — 표 아래에 그 조언자가 이 대화에서 낸 의견 표(의견 · 시각, 최근 것이 위)를 연다. 의견마다 무게 배지(**사소함 · 우려 · 차단**)가 있고, 두 줄까지
    보이며 누르면 전체가 펼쳐진다. 검색 · 다시 읽기 · **원문 열기** · 닫기가 있다. **원문 열기**는 그 조언자가 본 대화 기록 원문을 VS 문서 탭으로 연다
    (엔진은 돌고 있는 조언자의 원문만 갖고 있어서 돌 때만 누를 수 있다).
  - 조언자가 낸 의견은 채팅에도 그 자리에 **조언자 의견** 카드(조언자 이름 · 무게 배지 · 의견)로 나온다. 지난 대화를 다시 열어도 나온다.
- **조언자** — **프로젝트 / 사용자** 전환으로 범위를 고르고, 머리의 새로 고침과 **+ 새 조언자**를 쓴다. 표는 이름 · 모델 · 검토 시점 ·
  편집 · 삭제(카드 아래에서 한 번 더 확인)이고, 범위 전환 옆의 검색과 8개씩 페이지가 있다. 조언자 수 제한은 없고 파일은 256 KiB까지다. 엔진은 이름의 영문·숫자
  부분으로 조언자를 구별하므로, 그 부분이 같은 이름(한글만 있는 이름끼리 포함)은 함께 쓸 수 없고 편집 창이 겹치는 조언자를 알려 준다. 일시 정지해 둔 조언자는 이름 아래에 **일시 정지** 배지가 붙는다. 정의 파일에 조언자가 없으면
  엔진이 쓰는 `default` 조언자 줄이 보이고, 이 줄도 편집할 수 있다. 바꾼 설정은 고른 범위의 파일에 `default` 조언자로 저장되고, 그 줄을
  삭제하거나 바꾼 것 없이 저장하면 엔진의 처음 `default` 조언자로 돌아간다. `default` 조언자만 쓰이는 중에 **+ 새 조언자**로 추가하면 그 조언자도
  `default` 줄로 함께 저장되어 둘 다 동작한다. `default` 조언자를 빼려면 그 줄을 삭제한다.
  카드 아래에 그 범위의 파일 이름과 **VS에서 열기**가 있다.
- 조언자 편집 — 이름, 모델(비우면 기본), 추론 단계, 밀린 검토 대기, 검토 시점(**턴마다 / 작업이 끝날 때**), 검토 간격, 도구(**기본 / 없음 / 직접 선택**,
  직접 선택이면 도구마다 체크), 지시, 메모 한도, **일시 정지**(켜 두면 이 조언자만 동작하지 않는다). 조언자가 쓰는 도구도 일반 승인 절차를 거친다.
- **공통 지시** — 고른 범위의 모든 조언자에 함께 가는 지시와 공통 메모 한도. **취소 / 저장**.
- 저장하면 바로 적용된다. 다른 파일을 끌어오는 `@` 표기가 든 파일은 저장만 하고 **다음 대화부터 적용** 배지를 보인다. 편집하는 사이 파일이
  바뀌었으면 저장하지 않고 **다시 읽기**를 보인다.

### 자동화

이벤트가 났을 때 할 일을 **자동화 규칙** 카드 한 곳에서 정하고, 실행 결과는 **실행 기록** 카드에서 본다.

**자동화 규칙** — 이벤트 규칙(알림·채팅으로 전달)과 프로젝트 훅(PowerShell 스크립트)을 한 표로 다룬다.

- 머리의 **이 대화에서 사용** 스위치가 이 대화에서 전달 규칙이 실제로 메시지를 보내는 것과 훅이 이벤트를 듣는 것을 함께 켜고 끈다(대화마다 따로,
  대화가 바뀌거나 다시 연결되면 꺼진다). 전달은 대화당 10번까지이고, 한도에 닿으면 머리에 **전달 한도 도달** 배지가 붙는다. 머리에는 새로 고침과
  **+ 새 규칙**도 있다.
- 표는 검색과 20개씩 페이지가 있고, 줄마다 이름 · **신호** 배지(에이전트 끝남 · 에이전트 실패 · 팀 끝남 · 팀 실패 · 피드백 대기 · 파일 저장됨 ·
  빌드 성공 · 빌드 실패, 훅은 파일 저장 · 빌드) · **할 일** 배지(**알림 · 채팅 · 스크립트**) · **사용** 스위치 · 편집 · VS에서 열기(훅) · 삭제(카드 아래에서
  한 번 더 확인)다. 형식이 맞지 않는 훅 파일은 **파일 오류** 배지와 함께 VS에서 열기·삭제만 된다.
- **+ 새 규칙** 양식에서는 **할 일**을 먼저 고른다. **알림**과 **채팅**은 이벤트 규칙으로, **스크립트**는 훅 파일로 저장되고 아래 칸이 그에 맞게 바뀐다.
  - 알림·채팅 — 이벤트, 출처(모두 · 에이전트 · 팀, 에이전트·팀이면 출처 이름), 파일 저장이면 **저장 경로**(glob, 예: `src/**/*.cs`, 비우면 모든 파일,
    bin·obj·.git 제외). 채팅은 대상(메인 대화 · 에이전트 · 팀)과 **보낼 메시지**가 필요하고, 팀 결과를 같은 팀에 되보내는 규칙은 만들 수 없다.
    파일 저장·빌드 이벤트는 출처가 "모두"로 고정되고, 대화가 쉬는 중일 때만 처리하며 규칙마다 60초에 한 번까지만 실행해서 에이전트가 고친 파일의
    저장으로 다시 도는 일이 없다. 메시지에는 작업 영역 기준 경로나 빌드 결과만 담기고 파일 내용은 담기지 않는다. 자세한 안전장치는
    [에이전트·팀 문서 §10](agent-teams.md).
  - 스크립트 — `<작업 영역>/.pomp/hooks/*.md`에 저장하는 PowerShell 훅. 이벤트(파일 저장 · 빌드), 시간 제한(초), 대상 파일(파일 저장만,
    예: `src/**/*.cs`), 설명, PowerShell 스크립트(`$POMP_FILE`·`$POMP_EVENT`·`$POMP_EVENT_DETAIL`을 쓸 수 있다).
  - 공통으로 이름과 **사용** 스위치가 있다.
- 훅은 유효한 프로젝트 정책이 있어야 실행되고(없으면 표 위에 경고와 도구 › 권한으로 가는 **권한 보기**가 보인다), **이 대화에서 사용**을 켜야 하며,
  실행할 때마다 승인을 받는다.

**실행 기록** — 규칙이 실행된 기록과 훅 실행 기록을 최근 순으로 한 표(시각 · 규칙과 신호·경로 · 결과 배지)로 보여 준다(20개씩 페이지). 훅이 도는 동안
머리에 **실행 중지**가 보인다.

## 7. 작업 탭

![작업 탭 진행 화면](media/work-progress.png)

하위 화면은 **진행 · 변경 · 코드 점검**이다. 변경 칩의 숫자는 대기 중인 제안과 격리 결과만 센다. 적용된 기록은 이 숫자에 들어가지 않는다.

- **진행**
  - **작업 계획** — 진행 막대와 계획 전체(작업 수 제한 없음)를 20개씩 페이지로 보는 표. **작업 / 단계** 전환과 검색이 있다. 작업 표(상태 아이콘 ·
    작업 · 단계 · 상태 배지, 막힌 작업은 막힌 이유를 함께 보인다)의 줄마다 **작업 편집**(내용 · 상태(대기·진행 중·완료·막힘·중단함) · 막힌 이유)과
    **작업 삭제**(한 번 더 확인)가 있고, 단계 표(단계 · 작업 수)의 줄마다 **단계 이름 변경**·**단계 삭제**가 있다. 머리의 **이어가기**·**중단**·
    **작업 추가**(기존 단계나 새 단계에 작업을 더한다). 단계의 마지막 작업을 지우면 단계도 지워진다. 에이전트가 쉬고 있을 때만 저장되고, 그 사이 에이전트가 계획을 바꿨으면 저장이 거부된다. 저장은 지금의 계획만 바꾸며 모델 요청을
    보내지 않는다. 재시작·대화 전환·컨텍스트 압축 뒤에는 대화에 기록된 마지막 계획으로 돌아가고, 미완료 항목이 남으면 다음 실행이 끝날 때
    계속 진행을 요청할 수 있다.
  - **워크플로** — 진행 중인 워크플로가 없으면 도구 › 워크플로에 저장한 워크플로 표(이름 · 단계 수 · 범위, 검색, 20개씩 페이지)가 보이고, 줄의 **시작**을 누르면
    그 작업과 단계로 새 워크플로를 시작하고 채팅에 이어서 진행하라는 메시지를 보낸다. **새 작업**은 작업 내용과 단계(한 줄에 하나)를 적어
    바로 시작한다. 진행 중이면 상태 배지(계획 중·조사 중·수정 중·검토 대기·확인 중), 단계 표, 바뀐 파일 표와 **일시정지/재개**·**편집**·**취소**,
    **채팅에서 이어하기**가 보인다. 채팅의 `/workflow 작업`으로도 시작할 수 있고, `/goal 목표`는 워크플로를 시작하면서 자동 계속까지 켠다
    ([채팅 명령](#채팅-명령)).
  - **자동 계속** — 머리의 **사용** 스위치(기본 꺼짐, 진행 중인 워크플로가 있을 때만 켤 수 있다, 후속 실행 최대 6회 — 실행마다 모델 사용 비용이 든다).
    켜기 전에 **토큰 예산**(비우면 없음, 10,000~50,000,000)을 적을 수 있고, 켜 두면 머리에 `남은 실행 N회`, 아래에 사용량 막대가 보인다.
    6회와 예산 중 먼저 닿는 쪽에서 멈추고, 예산을 이미 넘긴 뒤에는 실행을 시작하지 않는다(진행 중인 응답을 끊지는 않는다). 센 값은 켠 뒤
    이 대화의 모델 호출 토큰(입력 + 출력 + 캐시 쓰기, 캐시 읽기는 제외 — 구성원 토큰과 같은 기준)이고 하위 에이전트 실행은 들어가지 않는다.
- **변경** — 위쪽 전환에서 **대기 중**과 **적용됨**을 고른다.
  - **대기 중 › 변경 제안** — 파일 표(파일 · 종류(새 파일/수정/삭제) · 줄 수). 파일 줄을 펼치면 변경 덩어리마다 체크 상자(F7 / Shift+F7로 이동),
    변경 전·후 비교(**위아래 / 나란히**), 연필(**이 변경 편집**)이 있다. 파일 줄의 체크 상자는 그 파일의 덩어리를 모두 고르거나 뺀다.
    **파일 검색**, **VS에서 비교**, 머리의 **컴파일 검사**(아래 **소스 생성기 허용**을 켜면 다음 검사에서 소스 생성기를 허용), **적용 N**(고른 덩어리 수),
    **제안 버리기**(같은 자리에서 한 번 더 확인)가 있다. 에이전트가 작업 중이면 머리에 **작업 중**이 보인다. 제안의 줄바꿈은 파일의 규칙(CRLF/LF)에
    맞춰지므로 실제로 바뀐 줄만 변경 덩어리가 된다. **적용**은 승인을 거쳐 파일을 쓰고 적용 전 내용을 기록에 남긴다. 저장하지 않은 편집,
    UTF-8이 아닌 파일, 내용이 달라진 파일, 작업 영역 밖 파일이 있으면 적용하지 않고 이유를 보인다.
    제안이 없을 때 머리의 **편집기 변경 가져오기**는 VS에서 직접 고친 파일(git의 마지막 커밋과 다른 파일, 커밋 기록이 없으면 저장된 파일과 다른
    편집 — 저장 안 한 편집은 **저장 안 함** 배지) 목록을 검색·페이지로 보이고, 최대 10개를 골라 **제안 만들기**를 누르면 그 변경으로 제안을 만든다.
    이 제안의 **선택만 남기기 N**은 고른 덩어리만 편집기에 남기고 나머지 변경을 빼며 기록에 남긴다. **제안 버리기**는 편집기를 바꾸지 않는다.
    적용이 끝난 제안은 그 결과(완료 · 메시지 · **적용됨 보기**)를 다음 제안이 올 때까지 이 자리에 보인다.
  - **대기 중 › 격리 실행 결과** — 격리 팀 구성원의 결과가 구성원마다 한 줄로 모인다(상태 · 줄 수, 펼치면 파일 · 새 파일/수정/삭제 · 줄 수).
    줄의 **적용**·**패치 열기**(VS에서 패치를 연다)·**결과 버리기**(한 번 더 확인; 목록에서만 지우고 패치 파일은 남는다). 적용 중에는 버릴 수 없다.
  - **적용됨 › 적용 기록** — 변경 제안과 격리 실행 결과로 파일에 적용한 기록 전체(체크 상자 · 시각 · 파일 · 상태, 20개씩 페이지, **파일 검색**).
    채팅의 승인 카드로 편집기 버퍼에 바로 넣은 편집은 저장 전 편집이라 여기에 남지 않고 편집기의 실행 취소로 되돌린다. 기록은 개수로 지우지 않고
    체크포인트 용량(500 MB)을 넘을 때만 오래된 것부터 지운다. 줄의 **되돌리기 검토**는 되돌리는 변경을 대기 중 제안으로 만든다(그 뒤에 파일이
    또 바뀌었으면 막는다). 여러 줄을 골라 막대의 **되돌리기 검토 N**(같은 파일을 바꾼 기록끼리, 10개 넘는 파일은 함께 되돌릴 수 없다)과
    **삭제 N**을 쓸 수 있다. **기록 삭제**·**삭제 N**은 같은 자리에서 한 번 더 확인한다. 적용 중인 항목은 지울 수 없고(적용이 끊긴 채 1시간이 지난 항목은 지울 수 있다), 지운 기록은 되돌리기에
    쓸 수 없다.
- **코드 점검** — 에이전트의 리뷰 지적과 Visual Studio 컴파일러 오류·경고를 한 표(체크 상자 · 종류 · 코드 또는 에이전트 · 설명과 파일:줄)로 본다.
  컴파일러 항목은 오류·경고 아이콘과 오류 코드(예: `CS0103`)로, 에이전트 지적은 보고한 에이전트의 그림(에이전트 탭에서 정한 색·이미지)과
  역할 이름으로 보인다. 대화의 POMP가 보고했으면 역할 표의 POMP 그림과 이름으로 보인다. 그 열의 이름은 보이는 줄에 따라 **코드**(컴파일러 항목만),
  **에이전트**(에이전트 지적만), **코드 · 에이전트**(둘 다)다.
  **전체 / 오류 / 경고 / 에이전트**로 거르고(20개씩 페이지), 항목을 골라 **에이전트에게 해결 요청**을 누르면 지금 보낼 대상에게 메시지 하나로
  보낸다. 편집기 컨텍스트는 붙이지 않으며 최대 50개·요청 전체 12,000자까지다. 줄의 **코드 열기**는 그 위치를 열고, **삭제**는 에이전트 지적만
  목록에서 지운다. 설명을 누르면 그 줄이 펼쳐져 잘리지 않은 전체 설명, 위치(파일:줄:열, 프로젝트), 에이전트 지적이면 근거로 인용한 코드가
  보이고, 다시 누르면 접힌다. 머리의 새로 고침은 VS 오류 목록을 다시 읽는다.

진행 맨 아래의 **대화형 터미널** 카드는 옵션이 켜져 있고 실행 중인 엔진이 지원할 때만 보인다. POMP에 함께 들어 있는 엔진은 지원하지
않으므로 옵션을 켜도 카드가 보이지 않는다. 승인된 명령 작업의 상태·출력·취소는 채팅의 해당 도구 카드에서 본다.
각 구역은 카드로 나뉘고 머리를 눌러 접을 수 있다(접힘 상태는 기억한다). 스크롤해도 카드 머리가 위에 붙는다.

## 8. 도구 탭

![도구 탭](media/tools-conversation.png)

하위 화면은 **대화 설정 · 권한 · 스킬 · MCP · 규칙 · 워크플로 · 지식**이다. 칩의 숫자는 그 화면 목록의 개수다. 프로젝트 훅은 에이전트 탭 › 자동화에
있다([§6](#자동화)). VS 옵션(도구 > 옵션 > Pomp > 일반)의 설명은 [설정 안내](settings.md)에 있다.

직접 만드는 항목(스킬·MCP 서버·규칙·워크플로·지식·프로젝트 정책)은 모두 화면 안에서 만들고 고치고 지운다. 파일이 원본이라 Git으로 함께 관리되고,
**VS에서 열기**는 보조로만 쓴다. 목록은 검색과 20개씩 페이지가 있고, 줄 끝 아이콘(이름은 툴팁)으로 다룬다. 지우기는 같은 자리에서 한 번 더 확인한다.
저장 범위는 **프로젝트 / 사용자** 전환으로 고른다. 편집 창을 연 사이 파일이 바뀌었으면 덮어쓰지 않고 바뀌었다고 알린다. 저장될 파일이 크기
한도(UTF-8 바이트 기준, 한글은 한 글자에 최대 3바이트)를 넘으면 저장하지 않고 "너무 커요" 오류만 보인다. 편집기가 읽을 수 없는 파일(크기 한도
초과, UTF-8 아님)도 목록에 상태와 함께 보이며 **VS에서 열기**·**삭제**만 된다. 목록에는 개수 제한이 없다. 목록 하나가 화면 메시지 한 개(약
1.75 MiB)를 넘을 만큼 크면 앞부분만 보이고, 보이지 않는 항목 수를 목록 아래에 알려 준다.

- **대화 설정**
  - **화면 입력 제어** — 머리의 **사용** 스위치로 이 대화에서 화면 조작(스크린샷·마우스·키보드)을 켜고 끈다(기본 꺼짐). 켤 때 카드 안에
    "이 대화에서 화면 입력 제어를 켤까요?"와 **취소 / 켜기**가 나온다. 쓸 수 없으면 **사용할 수 없음** 배지와 이유가 보인다. 입력창의 `/computer`도
    이 스위치를 바꾼다. 옵션의 컴퓨터 사용이 **사용 안 함**이면 카드가 보이지 않는다.
  - **사용할 도구** — 머리에 켜진 수/전체 수. 이 대화에서 모델이 쓸 도구를 묶음(파일·검색, 편집, 실행, 웹, 에이전트, VS 도구, MCP · 서버 이름, 기타)
    표로 보여 준다. 묶음 줄의 스위치는 묶음 전체를, 펼친 도구 줄의 스위치는 도구 하나를 켜고 끈다. 아래에 **변경 N개**, **기본값**, **적용**이 있다.
    도구를 켜도 승인 절차는 그대로다.
- **권한**
  - **허용한 작업** — 승인 카드의 "항상 허용"·"이 세션 동안 허용"으로 쌓인 허용(작업 · 폴더 · 범위 배지 **이 연결 / 항상**). 줄의 **허용 철회**로
    지운다. 허용은 승인 카드에서만 생기고, 철회해도 이미 실행 중인 작업을 되돌리지는 않는다. 영구 허용은 준 작업 영역에서만 적용된다(작업 영역이
    없는 이전 형식은 "모든 폴더"로 보이며 더 쓰이지 않고 철회만 된다). 실행·Git·패키지·디버거·테스트·하위 에이전트·컴퓨터 사용과 정책·에이전트
    설정 파일 수정은 기억하지 않는다. 머리에 VS 옵션 열기와 새로 고침이 있다.
  - **신뢰한 저장소** — 에이전트 설정을 신뢰한 저장소(폴더 · 설정 파일 수 · 신뢰한 날). 줄의 **신뢰 해제**로 해제한다(채팅의
    [작업 영역 신뢰](#작업-영역-신뢰)).
  - **프로젝트 정책**(`.pomp/permissions.json`) — 실제로 적용하는 규칙 표(도구 · 경로·명령 · 동작 배지 **허용 / 거부**)와 줄의 **규칙 편집 · 규칙 삭제**.
    머리의 **+ 규칙**은 규칙 양식(도구(`*`는 모든 도구), 동작, 경로·명령(한 줄에 하나, 비우면 전부))을 열고, 정책 파일이 없으면 이 규칙으로 파일을
    만든다. 스위치 **검토 후 편집**(검토를 거친 편집만 허용)과 **OS 격리**(OS 격리 실행 요구)는 바로 파일에 저장된다. 거부가 허용보다 우선하고, 맞는
    허용 규칙이 없는 도구는 막힌다. 저장하면 다음 도구 호출부터 적용된다. 편집하는 사이 파일이 바뀌면(다른 창, 에이전트, Git) 저장하지 않고
    **다시 불러오기**를 보인다. 해석할 수 없는 정책은 프로젝트 도구를 모두 막으므로 **읽을 수 없음** 배지와 이유가 보이고 **새로 작성**이나
    **VS에서 열기**로 고친다. **정책 파일 삭제**(한 번 더 확인)는 파일을 지워 일반 승인 규칙만 남긴다. 확인하는 사이 파일이 바뀌었으면 지우지 않는다.
    정책이 있으면 작업 영역 밖 작업 디렉터리 지정이 막히고 프로젝트 훅을 쓸 수 있다. 승인 모드나 허용한 작업으로 정책의 거부를 넘을 수 없다.
- **스킬** — 머리의 **가져오기** · **+ 새 스킬** · 새로 고침, 검색과 **전체 / 켜짐 / 꺼짐** 거르기. 줄마다 스위치, 이름과 설명 한 줄, 종류 배지(프로젝트 ·
  사용자 · 설정 폴더; POMP에 들어 있는 스킬은 배지 없음), 아이콘 **채팅에서 사용 · 편집 · 기본값으로 · VS에서 열기 · 삭제**(그 스킬이 할 수 있는 것만)가 있다. 직접 만든 스킬이 먼저,
  그다음 POMP에 들어 있는 스킬이 분류별로, 그 밖의 출처 순이며, 스위치를 눌러도 줄 순서는 바뀌지 않는다.
  - 켜기·끄기는 이름 기준이라 어떤 출처의 스킬에도 되고 다시 시작하지 않아도 적용된다. 끈 스킬은 목록에 남고(다시 켤 수 있다) 쓸 수 없으며 명령
    목록에서도 빠진다. 스킬을 켜면 그 스킬이 필요로 하는 스킬도 함께 켜지고(끄면 다른 스킬은 그대로), 함께 켠 스킬을 목록 위에 알린다. 켜기 상태가
    기본과 다르면 **기본값으로**가 보인다.
  - **채팅에서 사용**은 켜져 있고 사용 가능한 스킬의 명령을 입력창에 넣고 전송하지 않는다.
  - POMP에 들어 있는 스킬은 편집·삭제가 없다. 직접 만든 스킬은 **편집**(설명·본문, 화면이 다루지 않는 머리말이 있으면 파일 전체를
    글로 고친다)과 **삭제**를 쓴다.
  - **가져오기**는 신뢰하는 `SKILL.md` 전체 내용을 붙여 넣어 프로젝트 또는 사용자 범위에 저장한다. `name`·`description` 프런트매터가 필요하며
    UTF-8 32 KiB 이하만 받는다. 기존 파일을 덮어쓰지 않고, 저장만으로 실행하거나 권한을 부여하지 않는다. 다시 시작한 뒤 목록에서 사용 가능 여부를 확인한다.
- **MCP**
  - **MCP 서버** — 머리의 **가져오기** · **+ 서버 추가** · 새로 고침. 줄마다 상태 점, 이름과 범위 배지, 명령·URL과 비밀 값 이름(값은 `••••`), 연결 종류,
    도구 수(이 대화에 들어온 그 서버의 도구, 꺼져 있으면 `–`), 스위치, 아이콘 **연결 테스트 · 고치기 · 삭제**가 있다. 서버가 많으면 검색이 나온다.
    바꾸면 다시 시작해야 적용되므로 카드에 **다시 시작이 필요해요**와 **다시 시작**이 나온다.
  - 서버 편집 — 이름, 범위, 연결 종류, 명령과 인수 또는 URL, 헤더(http·sse), 환경 변수(이름·값 줄). 환경 변수와 헤더 값은 화면에 보이지 않고(••••),
    그대로 두면 저장된 값을 유지한다.
  - **가져오기** — 다른 도구(Claude·Cursor의 `mcpServers`, VS Code의 `servers`, 또는 이름별 서버 객체)의 설정 JSON을 붙여 넣으면 서버마다 상태
    (가져올 수 있음 · 같은 이름이 이미 있어 건너뜀 · 설정이 올바르지 않아 건너뜀 등)를 표로 보여 주고, 고른 범위에 저장한다(붙여 넣은 글 64 KiB까지, 서버 수 제한 없음).
    내려받거나 실행하지 않으며, 같은 이름은 덮어쓰지 않는다. `cwd`·제한 시간처럼 이 편집기가 보존할 수 없는 항목이 있는 서버는 통째로 건너뛴다.
    저장한 서버의 명령은 다시 시작할 때 실행되므로 신뢰하는 출처만 가져온다.
  - **추가할 수 있는 서버** — POMP가 고정된 버전으로 준비한 서버(GitHub, Context7)의 이름 · 버전 · **설치**(이미 들어 있으면 **설치됨**). **설치**는 아직
    비어 있는 범위와 그 서버가 필요로 하는 입력(GitHub는 토큰 필수, Context7은 API 키 선택; 비밀 값은 가려서 입력)을 묻고 설정에 등록한다. 설정만 쓸 뿐
    미리 내려받거나 실행하지 않으며, `npx` 서버는 시작될 때 고정된 버전을 받는다.
- **규칙**
  - **지금 적용 중** — 다음 프롬프트에 적용할 규칙을 태그로 보여 준다(많으면 `+N`으로 펼친다). 지금 편집 중인 파일과 규칙·대화가 바뀌면 갱신된다.
  - **규칙** — 프로젝트(`<작업 영역>/.pomp/rules/*.mdc`)와 사용자(`~/.pomp/rules/*.mdc`) 규칙 파일 표(이름과 설명 · 적용 배지 **항상** / 대상 파일 패턴 /
    **없음** · 범위 배지)와 줄의 **편집 · VS에서 열기 · 삭제**. 머리에 **가져오기**(32 KiB 이하 `.mdc` 내용)와 **+ 새 규칙**(이름 · 설명 · **항상 적용** 스위치 ·
    대상 파일 패턴(항상 적용이면 비활성) · 본문)이 있다. 편집은 같은 항목과 본문이고, 머리말이 폼으로 그대로 되쓸 수 없는 형식(주석, 여러 줄 값 등)이면
    파일 전체를 글로 고친다. 새 파일로만 저장하고 같은 이름은 덮어쓰지 않는다. 다른 프로그램이 만든 이름(대문자·`_`·공백 등)의 파일도 목록에서 고치고
    지울 수 있다. 규칙은 항상 적용이 켜져 있거나 대상 파일 패턴이 지금 편집 중인 파일과 맞을 때 다음 프롬프트부터 적용되며(한 번에 5개·본문
    24,000자까지, 같은 이름이면 프로젝트 규칙 우선), 도구 권한을 주지 않는다. 하위 폴더의 `.pomp/rules`와 `<파일>.mdc` 규칙은 파일로 관리한다.
- **워크플로** — 자주 쓰는 작업 순서를 저장한다. 표(이름과 설명 · 단계 수 · 범위)와 줄의 **편집 · 복제 · 삭제**, 머리의 **+ 새 워크플로**.
  편집 양식은 이름 · 범위 · 설명 · 작업 내용 · 단계(한 줄에 하나, 32개까지)다. 이 프로젝트(`.pomp/workflows/*.json`) 또는 내 모든 프로젝트
  (`~/.pomp/workflows`)에 저장한다. 저장한 워크플로는 작업 탭 › 진행 › 워크플로에서 시작한다. 형식이 맞지 않는 파일은 **VS에서 열기**·**삭제**만 된다.
- **지식** — 이 작업 영역의 지식을 한곳에서 관리한다. 지식 하나는 사용자가 붙이는 태그 하나(이름·색)이고 미리 정해진 태그는 없다.
  에이전트 탭의 역할·팀 편집 창과 채팅의 컨텍스트 바구니는 이 목록을 그대로 가져다 쓴다.
  - **지식** 카드 — 머리의 **+ 새 지식**과 새로 고침, 검색, 표(색 태그와 이름, 그 아래 범위·사용 형태·붙은 역할/팀 배지 · 조각 수)와 줄의
    **입력에 넣기 · 편집 · 삭제**(삭제는 한 번 더 확인). 줄을 펼치면 **변환**·**조각 추가**, 변환본, 조각마다 **편집 · 삭제**가 보인다.
  - **새 지식** — 이름(40자, 대소문자 무시하고 겹칠 수 없음; 적는 동안 같은 글자가 든 지식이 보인다)·색·범위(프로젝트 · 개인)·첫 조각 내용. 이미 있는
    이름으로 만들면 새 지식이 생기지 않고 그 지식에 조각으로 더해진다(같은 태그 → 같은 지식). 색은 아직 쓰지 않은 기본색 8개 중 하나로 시작한다.
    색 칸 16개 중에서 고르거나, 끝의 **+**(사용자 색)로 `#RRGGBB`를 적으면 그 색이 색 칸 끝에 선택된 채로 보인다.
  - 조각 — 지식에 들어간 글 하나. 편집기에서 넣은 조각은 `경로 시작–끝` 줄 위치와 상태(최신 · 이동됨 · 변경됨 · 없음)가 보인다. 줄이 옮겨졌으면 위치를
    따라가고, 내용이 바뀌었거나 찾을 수 없으면 그렇게 표시한다. 같은 지식 안에 같은 내용(줄 끝 공백·줄바꿈 차이 무시, 편집기 조각은 같은 파일)의 조각을
    넣거나 편집으로 같아지면 하나만 남는다.
  - **편집** — 이름·색·범위와 **사용 형태**: **원문**(조각을 쓴 그대로, 코드 줄과 주석 포함)과 **변환본**(보조 모델이 조각들을 중복 없이 짧게 정리한 글)
    중 하나를 지식마다 고른다. **변환**을 누르면 변환본을 만들고, 성공하면 그 지식의 사용 형태가 변환본으로 바뀐다(보조 모델 비용이 든다). 조각이 바뀐
    뒤에는 변환본이 오래됨으로 표시되고 다시 변환할 때까지 원문을 쓴다(옵션으로 자동 변환 가능, [설정 안내](settings.md)).
  - **입력에 넣기** — 지식의 쓰이는 내용을 채팅 입력창에 글로 넣는다(보내지 않음).
  - **에이전트 제안** — 에이전트가 제안한 조각이 있을 때만 위에 나오는 카드. 줄의 **수락**은 그 지식의 조각으로 만들고 **거절**은 지운다. 수락 전에는
    어디에도 쓰이지 않는다.
  - 범위는 POMP 안의 쓰임새이고 접근 제어가 아니다. **개인** 지식은 에이전트가 스스로 읽을 수 없고, 사용자가 바구니에서 고르거나 역할·팀에
    체크했을 때만 간다.
  - 편집기 줄 색 — 편집기에서 넣은 조각의 줄은 그 지식의 색으로 줄 전체 배경이 칠해진다(옵션 **지식 줄 색**으로 끔).

코드 검색 인덱스는 POMP가 자동으로 유지한다. 소스의 어휘 인덱스를 갱신하고, 로컬 임베딩 옵션이 바뀌면 벡터 인덱스를 다시 만들거나
작업을 멈춘다. 별도 관리 화면은 없다.

## 9. 계정 탭

![계정 탭](media/accounts.png)

(그림의 계정 주소는 예시다.)

공급자는 회사·서비스 이름(OpenAI, Anthropic, GitHub Copilot, Google Antigravity, Muse Code 등)과 **구독** 또는 **API 키** 배지로만 보인다.
요금제 이름이나 모델 목록은 이름에 붙이지 않는다. 공급자 이름 앞에는 그림을 두지 않는다(역할 그림과 헷갈리지 않게).

- **연결된 계정** — 계정마다 공급자, 계정 주소, **로그아웃**, 그 아래 사용량 줄(구간 · 막대 · 백분율, 막대 아래 초기화 시각). 공급자가 보고하지 않은
  구간은 숨긴다. 계정 머리를 누르면 사용량 줄을 접고 펼친다. 처음에는 현재 모델의 공급자만 펼쳐져 있고, 접힌 계정은 머리에 가장 빠듯한 한도 하나를
  (`주간 61%`) 보인다. 접고 펼친 상태는 기억한다. 머리에 새로 고침, 아래에 `HH:MM 기준`이 있다. **로그아웃**(같은 자리에서 한 번 더 확인)은 그 공급자에 저장된 로그인을 모두 지운다(같은
  공급자의 다른 계정도 함께 로그아웃된다). 저장한 API 키와 환경 변수는 그대로라, 그 방식으로 아직 인증돼 있으면 그렇다고 알려 준다. 바뀐 로그인은
  다시 시작한 뒤에 쓰인다.
- **보조 모델** — 자동완성·질문의 수정 제안·코드 캡션·지식 변환·입력 예측 문장에 쓸 모델. **빠른 모델 / 채팅 모델과 같게 / 모델 직접 선택** 중 고른
  칸에 실제로 쓰는 모델이 배지로 한 번 보인다.
- **계정 추가** — 제목 옆 **구독 플랜** 배지(여기 공급자는 모두 구독 플랜으로 로그인한다), 공급자 검색과 두 줄 타일(자주 쓰는 OpenAI · Anthropic · Muse Code · Google Antigravity가 먼저, 나머지는 이름순, 20개씩 페이지).
  타일마다 이름(쓸 수 없으면 **사용할 수 없음** 배지), 연결됐으면 체크가 있다. 누르면 로그인한다(브라우저가 열리거나, 인증 코드 입력·장치 코드·
  **터미널에서 로그인** 카드가 나온다; 카드 머리의 **로그인 취소**). 브라우저 없이 쓰는 장치 코드 로그인 타일(**장치 코드** 표시)처럼 다른 공급자의 계정으로
  저장되는 방식도 있다. 그 방식으로 로그인해도 계정은 저장된 공급자(OpenAI) 하나만 연결된 계정에 나오고, 방식 타일에는 연결됨 표시가 없다.
- **API 키로 연결** — 저장한 키와 로컬 모델 서버 표(공급자와 **API 키** 배지 · 환경 변수 이름과 저장한 날 · **저장됨** · 삭제; 로컬 서버는 이름과
  **로컬** 배지 · 주소와 저장한 날 · **저장됨** · 편집 · 삭제). 10개가 넘으면 검색과 10개씩 페이지가 붙는다. 머리의 **+ 키 추가**는 공급자 · API 키 ·
  **취소 / 저장** 양식을 연다(계정이 하나도 없는 첫 실행에서는 열린 채로 시작한다).
  - 공급자 목록 끝의 **로컬 모델 서버**는 직접 띄운 모델 서버(OpenAI 호환 `/models` 목록을 주는 어떤 서버든)를 이름 · 주소 · API 키(비워도 된다)로
    저장한다. 주소는 서버의 OpenAI 호환 주소(예: `http://127.0.0.1:8000/v1`)이고, `/v1` 없이 적으면 `<주소>/models`에 이어 `<주소>/v1/models`를 찾는다.
    POMP가 다음에 시작할 때(`⋯` › **다시 시작**) 그 서버의 모델 목록을 읽어 채팅·역할·조언자의 모델 목록에 저장한 이름 아래로 넣는다. 편집에서 API 키를 비워 두면
    저장된 키를 그대로 쓴다.

채팅 모델과 추론 단계는 채팅 입력창 아래 칩에서만 고른다.
