# POMP 에이전트·팀과 컴퓨터 사용 (계획 겸 계약)

역할을 가진 에이전트를 만들고, 둘 이상을 팀으로 묶어 역할별로 나눠 일하게 한다. 함께 컴퓨터 사용(화면·입력
제어, 브라우저 제어)의 켜고 끄기를 정한다. 이 문서는 구현 전에 정한 계약이다. 바꿀 때는 이 문서를 먼저 고친다.

## 1. 기능과 기본 동작

| 기능 | POMP |
|---|---|
| 역할마다 이름·맡은 일·설명, 자기 모델 | **에이전트**: 표준 에이전트 정의 파일(이름·설명·지시·모델·추론 단계·도구 범위) |
| 여러 역할을 묶어 역할별로 나눠 진행, 결과 보고 | **팀**: 2명 이상(상한 없음), 진행 방식(리더 판단·동시·순서대로), 메인 대화가 리더로 `task` 도구로 배분 |
| 에이전트끼리 직접 메시지·작업 넘기기 | 에이전트끼리 메시지를 주고받는 기능(`write agent://<id>`, `agent://all`)을 그대로 쓰고, 오간 메시지를 채팅과 해당 대화 상대 탭에 보여 준다 |
| 역할별 기억 | 2차: 역할별 기억 파일(승인 후 갱신) |
| 작업 진행 보기·이어받기 | 채팅 작업 카드와 대화 상대 탭: 구성원별 상태·도구 수·시간·최근 도구, 구성원 대화 보기(읽기 전용)·개별 중지 |
| 위험한 동작은 승인 | 기존 승인 + 아래 하위 에이전트 규칙 |
| 루틴(예약·이벤트) | 2차: 기존 저장·빌드 훅에서 팀 실행 |
| 컴퓨터 사용 | 사용자의 PC: 아래 "컴퓨터 사용" |

구현 전에 확인한 사실:

- 에이전트 정의: `~/.omp/agent/agents/*.md`(사용자) → `<작업 영역>/.pomp/agents/*.md`(프로젝트) → 확장 패키지 `agents/` →
  엔진 내장 역할(task·sonic·scout·reviewer·security-reviewer) 순서로 이름이 겹치면 앞이 이긴다. 프로젝트 역할은 POMP가
  `.pomp/local/engine-plugin/agents/`에 복사해 omp `--plugin-dir`로 넘긴다(omp는 플러그인 폴더를 사용자 폴더 다음에 읽는다. `.pomp`를
  그대로 넘기면 `.pomp/skills`·`.pomp/commands`까지 엔진 스킬·명령으로 읽으므로 역할 파일만 복사한다). `.claude/agents`, `.agents/`는 읽지 않는다.
  매 `task` 실행 전에 다시 읽는다.
- 앞머리(YAML): `name`·`description` 필수(`main`·`sub` 금지), `tools`(목록; 주면 `yield` 자동 추가), `spawns`, `model`(`provider/id`
  또는 `@smol` 같은 역할, 목록이면 대체 순서), `thinking-level`, `output`, `blocking`, `autoloadSkills` 등. 알 수 없는 키는 무시된다.
- `task` 도구: `{ context, tasks: [{ name?, agent, task, ... }] }`, 동시 32·깊이 2 기본. 결과는 부모에게 돌아온다.
- 하위 에이전트끼리·메인과 `write agent://<id>`로 메시지를 주고받는다(메인 대화에는 중계 메시지로 보인다).
- 하위 에이전트의 목록·대화·진행 상황은 읽을 수 있다.
  하위 에이전트를 직접 띄우거나 멈추는 명령은 없다(멈춤은 전체 중지뿐).
- **하위 에이전트는 승인 창 없이 모두 자동 승인으로 돈다**. 부모의 `task` 승인이 권한 경계다. 사용자의 도구별
  정책의 `deny`는 지켜지고, `prompt`는 하위 에이전트에서 거부된다. 그래서 POMP는 `task` 승인을 기억하지 않고("항상 허용"·"이 세션
  동안 허용" 없음) 호출마다 묻는다(architecture.md 6장 "매번 확인하는 요청").
- POMP 확장은 하위 에이전트 세션에도 붙는다. 확장이 하위 에이전트를 띄우기 전에 막을 수 있다.
- 컴퓨터 사용은 기본 꺼짐이고, 켜고 끄기와 상태 확인(`/computer`)은 모델 호출 없이 처리되며 이 세션에만 적용된다. 하위 에이전트 설정은
  부모 값을 그대로 읽는다. 화면 캡처·창 목록은 read 단계, 클릭·입력·클립보드 쓰기는 exec 단계다.
- 브라우저 제어는 **기본 켜짐**이고 실행 중 바꾸는 명령은 없다(다시 시작해야 적용).

## 2. 에이전트(역할)

- 저장: omp 표준 형식의 파일. 범위 **이 프로젝트**(`<작업 영역>/.pomp/agents/<name>.md`, 저장소로 팀과 공유) 또는
  **내 모든 프로젝트**(`~/.omp/agent/agents/<name>.md`). 이전 버전이 `<작업 영역>/.omp/agents`에 둔 역할은 처음 쓸 때 옮긴다(같은 이름이
  이미 있으면 옮기지 않는다). 엔진 내장 역할도 목록에서 편집한다: 편집 창은 엔진이 정의한 내용(`omp agents unpack`으로 받은 지시문·도구·모델)으로
  열리고, 저장하면 같은 이름의 역할 파일이 생겨 엔진이 내장 역할 대신 그 파일을 쓴다(편집 창이 다루지 않는 출력 형식·`spawns` 등은 엔진 정의 그대로
  옮겨 적는다). 그 파일을 삭제하면 내장 역할로 돌아간다.
- 파일 모양(POMP가 쓰는 키; `pomp-`로 시작하는 키는 POMP 화면용 정보이고 에이전트 실행에는 쓰이지 않는다):

```markdown
---
name: "reviewer-strict"
description: "변경된 코드의 버그·예외 처리·보안 문제를 근거와 함께 찾는다. 코드는 바꾸지 않는다."
pomp-title: "꼼꼼한 리뷰어"
pomp-job: "변경 코드 리뷰"
model: "openai-codex/gpt-6-luna"
thinking-level: "high"
tools: ["read", "find", "grep", "glob", "lsp", "yield"]
---
(지시: 일하는 방식, 지킬 것, 보고 형식)
```

- `name`: 영문 소문자·숫자·`-`, 2~40자, main·sub 금지. 엔진 내장 역할 이름(task·sonic·scout·reviewer·security-reviewer)은 그 역할을 편집해 만든 파일만 쓴다.
  화면에는 `pomp-title`(없으면 name)을 보인다. `description` ≤ 1,000자(모델이 언제 이 에이전트를 쓸지 판단하는 글),
  `pomp-title` ≤ 40자, `pomp-job` ≤ 80자, 지시 본문 ≤ 24,000자, 파일 ≤ 64 KiB, 개수 제한 없음(목록이 화면 메시지 한 개를 넘으면 앞부분만 보이고 빠진 수를 알린다).
- 모델: 채팅 모델과 같게(키 생략) / 빠른 모델(`@smol`) / 특정 모델(계정의 모델 목록에서 검색). 추론 단계: 자동(생략)·낮음·보통·높음·최대.
- 도구 범위: **모든 도구**(키 생략) / **읽기 도구**(`read, find, grep, glob, lsp, yield` + VS 도구 중 읽기 전용). 파일이 도구를 직접 지정했으면 **직접 지정 도구**로 보이며 VS에서 고친다.
- 템플릿(만들 때 미리 채움): 설계자, 구현자, 리뷰어, 테스터, 문서 작성자, 탐색자.
- 쓰기: 사용자가 저장을 누를 때만. 원자적 쓰기, 대상 폴더 밖·링크·재분석 지점 거부, 다른 사람이 바꾼 파일은
  `expectedHash`가 다르면 거부(다시 읽고 저장). 삭제는 화면에서 확인을 받은 뒤. POMP가 만들지 않은 파일도 편집·삭제할 수 있지만
  알 수 없는 앞머리 키는 그대로 둔다.
- `.pomp/agents/*.md`는 프로젝트 에이전트이고 `/recipe`로도 불러올 수 있다.

## 3. 팀

- 저장: **이 프로젝트** `<작업 영역>/.pomp/teams/<id>.json`, **내 모든 프로젝트** `%APPDATA%\Pomp\teams\<id>.json`.

```json
{ "version": 1, "id": "feature-dev", "title": "기능 개발팀", "goal": "요청한 기능을 설계·구현·검토·테스트까지",
  "members": ["architect", "implementer", "reviewer-strict", "tester"], "mode": "lead",
  "instructions": "공통 지시", "membersOnly": true }
```

- 구성원 2명 이상(상한 없음; 에이전트 name, 중복 금지, 지금 찾을 수 있는 에이전트만), `id`는 name과 같은 규칙, `title` ≤ 40자,
  `goal` ≤ 400자, `instructions` ≤ 8,000자, 파일 ≤ 32 KiB.
- 진행 방식: **리더 판단**(`lead`, 기본: 메인 대화가 나누고 필요한 구성원만 부른다) / **동시에**(`parallel`: 한 번의 `task` 묶음으로
  모두에게) / **순서대로**(`pipeline`: 목록 순서로, 앞 결과를 다음에 넘긴다).
- 실행: 입력창의 **보낼 대상** 칩(기본: 이 대화 / 팀 이름)에서 팀을 고르고 보낸다. POMP가 팀을 확인하고
  팀 파일을 다시 읽어(제한·경로 검사) 팀 안내와 사용자 메시지(+에디터 컨텍스트·첨부, 그 팀에 체크한 지식 — §9)를 함께 보낸다.
  팀 안내에는 목표·방식·구성원 이름·맡은 일·모델, 에이전트끼리 서로 조율하기, 공유 파일 편집 전 조율, 검증이 필요한 구성원(빌드·테스트·리뷰 역할, 격리 사본)에게는 할 확인을 할당에 적기 — 하위 에이전트는 시키지 않은 빌드·테스트를 하지 않는다, 끝나면 구성원별 결과·바꾼 파일·남은 문제
  보고가 들어간다. 안내 블록은 `<!-- pomp-team:<id> -->`로 시작하고 끝은 `<!-- /pomp-team -->`다. 채팅은 이 블록을 접어
  "팀: 기능 개발팀" 카드로 보인다.
- `membersOnly`(기본 켬): 이 팀 실행 중(그 턴이 끝날 때까지)에는 확장이 구성원이 아닌 에이전트를 띄우지 못하게 막는다
  (`scout`는 읽기 전용 탐색용으로 허용).
- 프로젝트 정책(`.pomp/permissions.json`)의 검토 전용 모드는 하위 에이전트를 막으므로 팀 실행을 거부하고 이유를 보인다.

### 3.1 한 에이전트에게 직접 보내기

입력창의 `@`로 에이전트·팀을 지정하거나 한 에이전트에게 직접 메시지를 보낸다(일하는 중에도 추가 지시). 두 가지 방법이 있다.

- **새 일로 보내기**(`chat/send.agent` = 역할 name): POMP가 역할을 확인하고 메시지를
  `<!-- pomp-agent:<name> -->` … `<!-- /pomp-agent -->` 안내와 함께 메인 대화에 넘긴다. 메인 대화는 `task` 도구로 그 에이전트
  하나만 실행하고(사용자 메시지를 그대로 할당) 결과를 전한다. 그 턴 동안 다른 에이전트는 띄우지 못하게 막는다.
  엔진 내장 역할(reviewer 등)도 대상이다.
- **이 대화에서 실행한 에이전트에게 이어 보내기**(`chat/send.agentInstance` = 하위 에이전트 id): POMP가 그 id가 현재 대화의
  작업 목록(실행 중·끝난 것 포함)에 있는지 확인하고 메시지를 보낸다. 메인 대화가 `write agent://<id>`로 그대로
  전하고, 답은 따로 기다리지 않아도 메시지로 들어오면 보여 준다(`wait`는 자기가 시작한 작업만 기다린다). 그 에이전트는 자기 맥락을 이어서 답한다(쉬거나 보관된 에이전트를 깨운다). 그 턴에는
  새 에이전트를 띄우지 않는다. `write agent://`도 쓰기 도구라 승인 모드에 따라 확인을 받을 수 있다.
- 입력: 보낼 대상 칩(기본(POMP) / 팀 / 에이전트 / 이 대화에서 실행한 에이전트), `@` 목록의 "에이전트·팀" 묶음(고르면 대상만 바뀌고
  글자는 지운다), `/agent 이름 메시지`·`/team id 메시지`(채팅 화면의 기본 명령), 에이전트 탭의 "메시지" 버튼. 한 메시지 대상은 기본(POMP) 탭과 에이전트·팀 탭 어디서나
  바꿀 수 있다(목록은 팀, 에이전트, 이 대화에서 실행한 에이전트 순이고 각 묶음은 이름순; 지금 대화의 상대는 자기 묶음 맨 위에 배경색으로 구분되며, 기본(POMP)는 기본·팀 탭에서는 에이전트 맨 위, 에이전트 탭에서는 그 에이전트 바로 아래. 지금 대화의 줄을 고르면 대상이 풀려 지금 대화로 이어 보내며(서브에이전트로 다시 부르지 않음), 같은 역할로 실행 중인 구성원은 빠진다).
- 대상은 한 번에 하나(team·agent·agentInstance 중 하나). 검토 전용 프로젝트에서는 거부한다. 응답 중에는 보낼 수 없다(기존 규칙):
  실행 중인 턴에 끼워 넣는 것은 중지한 뒤에도 남는 문제가 있어 하지 않는다.

### 팀 작업 카드와 승인

- 하위 에이전트는 승인 없이 돈다. 그래서 팀 실행의 권한 경계는 **`task` 호출 승인**이다. 승인 창에 구성원별 할당을 모두
  보인다. 실행이 바꾼 파일은 기존 체크포인트·변경 이력에서 보고 되돌릴 수 있다. 읽기 전용 에이전트로만 짠 팀은 파일을 바꾸지 않는다.
- 상태: 채팅의 해당 `task` 카드와 에이전트·팀 대화 상대 탭에서 구성원별 상태·도구 수·시간·최근 도구를 보인다.
  `parentToolCallId`로 호출 카드에 붙이며, 해당 카드가 없는 현재 구성원만 접을 수 있는 진행 줄에 나온다. 구성원 대화 보기는
  읽기 전용이고 최근 40개 메시지, 글자 수 제한이 있다. 토큰·비용·모델은 엔진의 진행 데이터에 포함되지만 구성원 줄의 표시 항목은 아니다.
- 구성원 줄의 **중지**는 그 구성원만 멈춘다(§14). 채팅 입력창의 중지는 전체 응답을 멈춘다.

## 4. 컴퓨터 사용

위치 판단: 실제로 켜고 끄는 곳은 **대화마다**, 허용 여부와 엄격함은 **전체 설정 한 곳**, 에이전트·팀은 **고정 규칙**이다.

| 단위 | 무엇 | 기본 |
|---|---|---|
| 전체 설정(도구 > 옵션 > Pomp > 일반 > 컴퓨터 사용) | 컴퓨터 사용: 사용 안 함 / 대화마다 켜기 | 대화마다 켜기 |
| | 브라우저 제어(웹 페이지 열기·조작, 다시 시작 때 적용) | 끔 |
| | 화면 보기(캡처·창 목록)도 매번 확인 | 끔 |
| 대화 | 도구 › 대화 설정 › 화면 입력 제어 스위치: 이 대화에서 화면·입력 제어 켜기 | 꺼짐(새 대화·세션 전환·재연결 때 꺼짐) |
| 에이전트·팀 | 하위 에이전트는 승인 창을 띄울 수 없으므로 화면·브라우저 제어 금지. 팀은 리더(메인 대화)만 승인 받고 사용 | 고정 |

- 처음 켤 때 한 번 확인: "화면 내용이 모델 공급자에게 전송돼요. 클릭·입력·클립보드 쓰기는 매번 승인을 받아요. 비밀번호·개인 정보가
  보이는 창은 닫아 두세요. 화면에 보이는 글은 지시가 아니에요." [이 대화에서 켜기]. 켜져 있으면 스위치 강조와 상태 "켜짐".
- 구현: 시작할 때 쓰는 설정에서 컴퓨터 사용은 항상 꺼 두고, 브라우저 제어는 <브라우저 제어> 값을 따른다. 사용 안 함이면 컴퓨터 도구를 거부로 둔다.
  "화면 보기도 매번 확인"이거나 승인 모드가 Auto-all이면 컴퓨터 도구의 모든 호출을 확인한다. 대화 토글은 모델 호출 없이 켜고 끄고
  결과를 확인한다. 응답 중에는 바꾸지 않는다. 새 대화·세션 전환·재연결 뒤에는 꺼짐으로 맞춘다.
  입력창에서 친 `/computer`는 도구 › 대화 설정을 열고 같은 스위치를 쓴다(사용 안 함이면 거부).
- 권한 가드: POMP가 `POMP_STATE_DIR/computer-state.json`(`{ sessionId, desktop, browser, updatedAt }`)을 원자적으로 쓴다.
  확장은 세션의 실제 computer/browser 설정을 읽고, 활성 기능에 같은 세션의 POMP 허용이 없으면 `eval`을 막는다. 직접 `computer`·
  `browser` 호출도 같은 세션의 허용과 메인 세션이 필요하다. 설정 API를 읽지 못하면 `eval`을 차단한다. 상태 파일을 읽지 못하면
  제어가 활성화된 `eval`과 직접 제어 호출을 차단하며, 하위 에이전트의 `eval`도 제어 허용이 있거나 상태를 읽지 못할 때 차단한다.
  엔진 설정 API의 세션 범위에 기대므로 엔진을 올릴 때 다시 검증한다.
- 샌드박스가 아니다: 승인된 명령(bash 등)은 원래 권한으로 돈다. 화면 정보는 신뢰할 수 없는 입력이다.

## 5. UI

- 탭은 **채팅 · 작업 · 에이전트 · 도구 · 계정**. 에이전트는 **역할 · 팀 · 조언자 · 자동화**, 작업은 **진행 · 변경 · 코드 점검**,
  도구는 **대화 설정 · 권한 · 스킬 · MCP · 규칙 · 워크플로 · 지식**으로 나눈다. 실행 상태·개별 중지는 채팅의 작업 카드에 둔다.
- 하위 화면 칩은 항목 수를 보여 주고 0개여도 흐린 채 누를 수 있다. 사용자가 고르지 않았고 현재 화면이 비어 있으면 항목이 있는
  첫 화면으로 간다. 직접 고른 화면은 이 대화 동안 유지한다. 목록은 열 이름이 있는 표(스위치·배지·줄 끝 아이콘, 검색과 20개씩 페이지)이고,
  빈 목록은 열 이름과 빈 줄만 보이며 안내 문구는 두지 않는다. 카드 머리의 생성 버튼과 파일 기반 자료의 새로 고침은 비어 있어도 남긴다.
- 역할·팀은 표에서 만들기·편집·삭제·메시지(엔진 내장 역할은 편집·복제; 맨 위의 POMP 자신은 그림과 `APPEND_SYSTEM.md` 지시만 편집, 삭제 없음), 조언자는 `WATCHDOG.yml`의 조언자를 만들기·편집·삭제·켜고 끄기,
  자동화는 이벤트 규칙(알림·채팅)과 프로젝트 훅(스크립트)을 한 표(자동화 규칙)와 실행 기록으로 다룬다. 파일 기반 목록에는 새로 고침을 둔다.
- 입력창에는 권한 모드·보낼 대상 칩이 있고 화면 입력 제어는 도구 › 대화 설정에 있다(사용 안 함이면 숨김).
- 문구는 한국어·영어(i18n), 색은 POMP 테마 변수만. 설정 분류·항목도 POMP 언어를 따르며 옵션 페이지 이름은 일반/General이다.

## 6. 프로토콜(POMP ↔ 채팅 화면)

- `agents/state`(POMP → 화면, 상태): `{ root, roles: Role[], teams: Team[], diagnostics: string[] }`
  - `Role { name, title, job, description, instructions, model?, thinkingLevel?, tools: 'all' | 'readOnly' | 'custom', scope: 'project' | 'user' | 'bundled' | 'extension', file?, hash?, editable, error? }`
  - `Team { id, title, goal, members: string[], mode: 'lead' | 'parallel' | 'pipeline', instructions, membersOnly, isolation, scope: 'project' | 'user', file, hash, missing: string[], error? }`
- `agents/command`(화면 → POMP): `{ requestId, action: 'refresh' | 'saveRole' | 'deleteRole' | 'saveTeam' | 'deleteTeam' | 'transcript' | 'exportTeam' | 'openTeamExport' | 'previewTeamImport' | 'importTeam', scope?, role?, team?, name?, expectedHash?, subagentId?, text?, previewHash? }`
  → `agents/reply` `{ requestId, ok, error?, name?, transcript?: { agent, messages: { role, text }[], truncated }, template?: string, preview?: TeamImportPreview }`
  - `exportTeam`·`openTeamExport`: `scope`·`name`(팀 id). `previewTeamImport`: `text`·`scope`(가져올 범위). `importTeam`: `text`·`scope`·`previewHash`(미리보기의 `hash`; 다르면 거부).
  - `TeamImportPreview { hash, team: { id, title, mode, members, status: 'new' | 'same' | 'conflict' }, roles: [{ name, title, status: 'new' | 'same' | 'conflict' | 'bundled' | 'existing' }], problems: string[] }`
    (`existing` = 템플릿에 없지만 이 PC에서 찾은 역할). `problems`가 비어 있고 충돌이 없을 때만 가져올 수 있다.
- `chat/send`에 `team?: string`(팀 id), `agent?: string`(역할 name, §3.1), `agentInstance?: string`(이 대화의 하위 에이전트 id, §3.1) 중
  하나. POMP가 대상을 찾지 못하면 보내지 않고 오류.
- `computer/state`(POMP → 화면, 상태): `{ policy: 'off' | 'perConversation', browser: boolean, confirmReads: boolean, desktop: boolean, pending: boolean, available: boolean, message? }`
- `computer/set`(화면 → POMP): `{ requestId, desktop: boolean }` → `computer/reply` `{ requestId, ok, error? }`
- `workspace/backgroundState`의 job에 `progress?: { toolCount, tokens, cost, durationMs, recentTools: string[], resolvedModel?, thinkingLevel? }`,
  `parentToolCallId?`, `team?`(그 턴의 팀 id) 추가.

## 7. 검증

- 공급자를 실제로 호출하지 않고, 사용자의 에이전트 설정 폴더(`%USERPROFILE%\.omp`)를 건드리지 않는 격리된 홈에서 확인한다.
- Core: 파일 검증·원자적 쓰기·해시 충돌·범위·제한, 팀 검증, 팀 메시지 변환, 컴퓨터 토글(가짜 에이전트의 응답), 시작 설정 내용,
  세션 바뀜 때 꺼짐, 상태 파일.
- 확장: 팀 안내, `membersOnly` 차단, 하위 에이전트 eval 차단(켜짐·꺼짐·파일 없음·손상).
- UI: 에이전트 탭 편집·검증 오류·190/360px·한/영, 보낼 대상 칩, 화면 토글 확인 흐름.
- 실제 VS에서: 에이전트·팀 만들기, 컴퓨터 사용 상태 확인(모델 호출 없음), 실제 모델로 팀 실행.

## 8. 대화 상대, 명령 대기열, 기록

이름: 한 명은 **에이전트**, 묶음은 **팀**.

### 8.1 화면 구성
- 탭: **채팅 · 작업 · 에이전트 · 도구 · 계정**. 세션 탭은 없앤다(대화창 상단 세션 메뉴와 중복). 상단 ▾가 **대화 목록 패널**을 연다:
  검색, 전체 목록(제목·시각·메시지 수·대화 상대 표시), 행을 누르면 열기, 행의 ⋯로 미리보기(그 행 바로 아래에 펼침/접기)·
  이름 바꾸기(현재 대화)·삭제(확인 후 대화 파일을 휴지통으로 이동, 현재 대화면 먼저 새 대화를 시작). 현재 대화는 체크 표시(버튼 아님). `/sessions`도 이 패널을 연다.
- 에이전트 탭의 하위 화면 칩은 **역할 · 팀 · 조언자 · 자동화**다.
- 채팅 상단(세션 이름 아래)에 **대화 상대 탭**: 닫을 수 없는 기본(POMP) + 고른 에이전트·팀 탭(개수 제한 없음, 많으면 탭 줄을 가로로 넘김, ×로 닫기). 활성 탭이 이 대화의
  상대다(메시지마다 초기화되지 않음). 대화 목록에도 상대가 보인다. 에이전트 탭의 역할·팀 "메시지"와 `/agent 이름`·`/team id`(메시지
  없이)는 그 탭을 연다. 기본(POMP) 탭은 대화 전체(대상 배지로 구분), 에이전트·팀 탭은 그
  상대에게 간 턴과 그 탭에서 보낸 턴을 보이며 평소에는 그 상대에게 보낸다. POMP는 에이전트별 인스턴스를 기억해 탭을 오가도 맥락이 이어진다. 메시지 하나만
  다른 곳(다른 에이전트·팀, 또는 POMP)에 보내는 대상 칩(§3.1, @멘션, 메시지가 붙은 `/agent`)은 어느 탭에서나 쓰고 그 메시지에만 적용한다. 칩은 평소 `보낼 대상`이고
  다른 대상을 골랐을 때만 그 상대를 보인다(지금 탭의 상대 자신은 칩에 나오지 않고, 목록에서 그 줄을 고르면 지금 대화로 이어서 보낸다). 에이전트·팀 탭에서 보낸 그 메시지와 답은 보낸 탭에도 남고 받은 상대의 탭과 기본 탭에도 보인다. 대화를 다시 열거나 엔진·VS를 다시 시작해도 보낸 탭에 남는다: 페이지가 보낸 탭을 `chat/send.from`으로 알리고, POMP가 그것을 프롬프트 앞(라우팅 안내 다음)에 `<!-- pomp-from:<종류>:<id> -->`로 기록해 복원할 때 되돌린다(화면에는 보이지 않는다. POMP에게 보낸 슬래시 명령만 omp가 맨 앞에서 읽어야 해서 표시하지 않는다). 그래서 한 에이전트의 결과를 다른 에이전트에게 넘겨 작업을 이어 갈 수 있다. `/goal`은 기본(POMP) 탭에서만 쓴다.
  계획 이어가기와 편집기 코드 동작은 메인 POMP로 보낸다. 작업 › 코드 점검의 **에이전트에게 해결 요청**은 지금
  보낼 대상에 메시지 하나로 보내고 편집기 컨텍스트는 끈다(최대 50개·요청 전체 12,000자).
- 채팅의 **작업 카드**: 구성원별 상태·도구 수·시간·최근 도구와 개별 중지. 해당 카드가 없는 현재 구성원만 입력창 위 접을 수 있는
  진행 줄에 나온다. 승인받은 명령 작업도 해당 호출의 도구 카드 안에 상태·출력·취소를 둔다.

### 8.2 대화 상대
- 대화마다 상대를 저장한다: `<DataDirectory>\conversations\partners.json`(세션 id → 상대, 최대 500개, 원자적 쓰기).
  새 대화는 기본. 대화 중에 바꾸면 다음 메시지부터 적용.
- 에이전트 상대: 첫 메시지는 새 일로 보낸다(§3.1, 새 인스턴스). POMP는 그 턴에 시작된 그 이름의 작업 id를 상대 인스턴스로 기억하고,
  다음 메시지부터 같은 에이전트에 이어 보낸다(§3.1, 자기 맥락 유지). 그 id가 이 대화의 작업 목록에서 사라졌으면
  (다시 시작 등) 다시 새 일로 새 인스턴스를 만들고 그렇게 알린다.
- 팀 상대: 메시지마다 팀으로 보낸다(§3). **같은 구성원으로 이어 가기**: POMP는 대화마다, 팀마다 구성원별 최근 인스턴스(역할 이름 → 작업 id)를
  기억한다(메모리만; 대화나 연결이 바뀌면 비움). 기록은 그 팀으로 보낸 턴(`chat/turnStarted.team`과 같은 promptId)에서 새로 시작된 작업 중
  역할 이름이 팀 구성원인 것만 쓴다. 다음에 그 팀으로 보낼 때(대화 상대 팀 탭이든 한 메시지 대상이든) 이 대화의 현재 작업 목록에 아직 있는
  인스턴스만 골라 "이어 가는 구성원"(`<역할>=<작업id>` 쌍의 목록)으로 함께 보낸다(역할은 `^[a-z0-9-]{2,40}$`, 작업 id는
  `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`, 구성원이 아닌 역할·형식이 틀린 항목은 버림, 최대 6개). 남은 인스턴스가 없으면 이어 가는 구성원 없이
  보내고 `conversation/partnerState.message`(팀 상대일 때)로 "이전 구성원을 찾을 수 없어 새로 시작해요"를 알린다.
  이어 가는 구성원이 있으면 팀 안내 블록에 "이어 가는 구성원" 목록(`역할 → agent://<작업id>`)과 규칙을 넣는다: 이미 있는 구성원에게는
  새로 시작하지 말고 `write agent://<id>`로 다음 일을 보내고 답은 메시지로 받는다(`wait`는 쓰지 않는다); 목록에 없거나 연결되지 않는 구성원만 `task`로 새로 시작한다.
  membersOnly 제한은 그대로다(새로 시작하는 경우에만 적용). 안내 블록 표식(`<!-- pomp-team:<id> -->`)은 바뀌지 않는다.

### 8.3 명령 대기열
- 응답 중에 보낸 메시지는 거절하지 않고 **대기열**에 넣는다(POMP가 가짐, 이 VS 창 동안만, 개수 제한 없음, 대기열 전체 1,800 KiB까지). 입력창 위에 목록:
  순서 바꾸기·고치기·지우기, 일시정지/재개, 비우기. 대상(상대·한 메시지 대상)도 항목에 같이 저장한다.
- 턴이 정상으로 끝나면 다음 항목을 보통 보내기와 같은 길로 보낸다. 오류·중지(Stop)·대화 바뀜이면 **일시정지**하고 이유를 보인다
  (항목은 지우지 않는다; 사용자가 재개하거나 비운다). 엔진 자체의 대기열은 쓰지 않는다(중지 뒤에도 남는 문제).
- 대기열은 넣을 때의 대화에 묶인다. 다른 대화에서는 재개를 거부한다: 그 대화로 돌아가 재개하거나 비운다(다른 대화로 잘못 가지 않게).

### 8.4 기록
- 팀·에이전트·직접 메시지 실행마다 기록: 대상(종류·id·제목), 요청 글(≤ 4,000자), 시작·끝, 상태, 구성원(에이전트·작업 id·상태·
  도구 수·토큰·시간). `<DataDirectory>\agent-history\<작업 영역 해시>.json`, 개수 제한 없이 화면 메시지 한 개(1.75 MiB) 크기까지, 원자적 쓰기. 프롬프트 전체·도구 결과·
  파일 내용은 저장하지 않는다.
- 위 기록은 호스트의 저장·프로토콜 계약이다. 진행과 구성원 조작은 채팅 작업 카드 및 대화 상대 탭에 있고 별도의 기록 관리 화면은 두지 않는다.

### 8.5 프로토콜 (추가)
- `conversation/partnerState`(POMP → 화면, 상태, 준비 스냅숏 포함): `{ sessionId, partner: { kind: 'main'|'agent'|'team', id? }, instance?, title?, message? }`
- `conversation/partner`(화면 → POMP): `{ requestId, partner }` → `conversation/partnerReply { requestId, ok, error? }`
- `chat/send`: 한 메시지 대상(team·agent·agentInstance)도 `main: true`도 없으면 대화 상대를 쓴다. `main: true`는 상대와 관계없이 POMP가
  받게 하며 다른 대상과 함께 쓸 수 없다. `chat/turnStarted`는 실제로 간 곳을 `team`/`agent`/`agentInstance` 또는 `main: true`로 알린다
  (다시 시도가 상대가 바뀐 뒤에도 원래 곳으로 가게). 응답 중이면 거절 대신 대기열에 넣고
  `chat/turnStarted` 대신 `chat/queued { clientMessageId, itemId }`를 보낸다.
- `chat/queueState`(상태, 스냅숏 포함): `{ items: [{ id, text, attachments?, includeEditorContext, team?, agent?, agentInstance?, createdAt }], paused, reason? }`
- `chat/queue`(화면 → POMP): `{ requestId, action: 'edit'|'remove'|'move'|'clear'|'pause'|'resume', id?, text?, index? }` → `chat/queueReply`
- `agents/historyState`(상태, 스냅숏 포함): `{ entries: [{ id, sessionId, target: { kind, id, title }, text, startedAt, endedAt?, status, pinned, label?, members: [...] }], truncated }`
- `agents/history`(화면 → POMP): `{ requestId, action: 'delete'|'clear'|'pin'|'unpin'|'label'|'rerun', id?, label?, filter? }` → `agents/historyReply`
- `session/historyState`의 항목에 `partner?`(대화 상대) 추가.

## 9. 지식(통합)

- 지식은 도구 탭 › 지식 한 곳에서 관리하고, 역할·팀 편집 창과 컨텍스트 바구니는 그 목록을 가져다 쓴다. 지식 하나 = 사용자가 정한 태그
  하나(이름·색, 미리 정한 태그 없음)이며, 같은 이름으로 넣는 글은 그 지식의 **조각**으로 더해진다.
- 저장: 작업 영역의 `.pomp\local\knowledge.json`(커밋되지 않음). 지식·조각·제안 조각의 개수 제한은 없고, 조각 8,000자,
  변환본 16,000자, 파일 4 MiB까지다. 이전 형식(`%LOCALAPPDATA%\Pomp\knowledge\`)이 있으면 처음 한 번 옮겨 오고
  이전 파일은 지운다(`.pomp`를 지운 뒤 되살아나지 않게). 옮길 때 제목 → 지식 이름, 같은 이름은 한 지식의 조각, 팀·역할 범위 → 그 팀·역할에 체크된
  프로젝트 지식이 된다.
- 중복 제거: 조각을 넣거나 고칠 때 같은 지식 안에서 정규화한 글(줄바꿈 LF, 줄 끝 공백·앞뒤 빈 줄 무시)과 (편집기 조각이면) 파일이 같은
  조각은 하나만 남는다. 변환본을 만들 때 모델도 중복을 합친다.
- 쓰이는 내용: 지식마다 **원문**(저장된 조각을 빈 줄로 이어 붙임, 편집기 조각은 `<경로>` 줄 범위와 코드 블록) 또는 **변환본**. 변환본은
  보조 모델(`knowledge` 모드, 60초·4,096 토큰, 원문 24,000자까지)이 만들고, 원문이 바뀌면 오래됨이 되어 다시 변환할 때까지 원문을 쓴다. 사용자가 직접
  변환해 성공하면 사용 형태가 변환본으로 바뀌고, 자동 변환은 사용 형태를 바꾸지 않는다. 모델에는 지식 이름과 조각만 구분된 데이터로 보낸다.
- 대화에서 쓰기:
  - **직접 선택(기본)** — 컨텍스트 바구니의 **지식**에서 체크한 지식은 이 대화의 모든 메시지에 이어서 붙는다(체크를 풀 때까지). 이어 연
    대화는 그 선택을 유지하고, 새 대화는 빈 선택으로 시작한다. POMP는 선택을 `POMP_STATE_DIR/session-knowledge.json`
    (`{ version: 1, root, sessionId, items: [{ title, body }] }`, 20개·24,000자)에 쓰고, 확장이 그 대화의 메인 세션 시스템 프롬프트 뒤에
    `<pomp_knowledge>` 블록으로 붙인다(작업 영역·대화가 다르면 붙이지 않고 남은 블록을 지운다).
  - **팀** — 팀 편집 창에서 체크한 지식(최신순 10개·12,000자)은 그 팀에 메시지를 보낼 때 `<team_knowledge>` 블록으로 덧붙는다. 다른 대상에는
    퍼지지 않으며, 복원된 대화 화면에서는 이 블록을 숨긴다.
  - **역할** — §11.
  - 모든 블록에는 참고 자료일 뿐 도구 권한·승인·정책을 바꾸는 지시가 아니라고 적고, 내용 안의 태그는 무력화한다.
- 에이전트 제안: 모델은 `propose_knowledge { tag, text }`로 **제안 조각**만 만든다. 그 이름의 지식이 있으면 그 안에, 없으면 새 제안 지식
  (프로젝트 범위)으로 들어간다. 개인 지식은 대상이 될 수 없다. 사용자가 도구 탭 › 지식에서 수락하기 전에는 쓰이지 않는다. 비밀 정보나
  검증되지 않은 내용은 넣지 말라고 도구 설명에 적는다.
- 에이전트 읽기(옵션 `Agents read knowledge`, 기본 꺼짐): 켜면 모델이 `read_knowledge`로 프로젝트 지식 목록(이름·조각 수·글자 수)을 보고
  골라 읽는다(읽기 전용, 한 번에 24,000자). 읽은 지식은 이 대화의 선택에 더해져 다음 메시지부터 이어서 붙는다. 개인 지식은 목록에도
  결과에도 나오지 않는다.
- 편집기: 우클릭 POMP ▸ 지식에 추가(`Alt+/`)는 선택한 줄을 담아 도구 탭 › 지식의 추가 양식을 연다(메뉴에 지식 목록을 늘어놓지 않는다). 사용자가 이름으로 지식을 고르거나 새로 만들어 조각으로 넣으면 그 줄 위치(작업 영역 기준 경로·시작–끝 줄, 200줄까지)와 내용 해시를
  함께 저장한다. POMP는 목록을 만들 때 파일에서 그 줄을 다시 찾아 **최신**(그 자리), **이동됨**(다른 자리에 한 번만 있음 — 위치를 조용히
  고친다), **변경됨**(첫 줄과 끝 줄만 남음), **없음**(2 MiB 넘는 파일 포함)으로 표시한다. 편집기는 그 줄에 지식 색 배경을 칠한다.
- 관리 주체는 사용자다. 팀의 **리더 판단** 방식에서 메인 대화가 조율자이며, 별도 권한 상승은 없다.

## 10. 이벤트 규칙(에이전트·팀 사이 훅)

- 저장: 작업 영역의 `.pomp\local\agent-hooks.json`(개수 제한 없음, 파일 256 KiB까지). 같은 화면(에이전트 탭 › 자동화 › 자동화 규칙)에서 할 일 **스크립트**로 만드는 훅(편집기 저장·빌드 때 도는 `.pomp/hooks` PowerShell)과는 저장 위치와 동작이 별개다.
- 이벤트: `agent.completed`·`agent.failed`(출처: 모든 에이전트 또는 역할 이름), `team.completed`·`team.failed`(출처: 모든 팀 또는 팀 ID),
  `feedback.waiting`(케이스 카드가 사용자 의견을 기다림).
- 동작(화면의 할 일): **알림**(채팅 알림) 또는 **채팅**(전달: 메인 대화·에이전트·팀에 보통 채팅 메시지를 대기열로 보냄, 편집기 컨텍스트 없음, 이벤트 요약은
  `<event_summary>` 데이터 블록). 전달은 대기열과 승인을 그대로 거친다.
- 안전장치: 전달은 자동화 규칙 카드의 **이 대화에서 사용**을 켰을 때만 한다(재연결·대화 전환 때 꺼짐, 같은 스위치가 훅 듣기도 켜고 끈다). 같은 이벤트는 한 번만 처리한다. 규칙이
  시작한 턴(과 그 턴에서 처음 본 작업)의 이벤트는 다시 전달하지 않는다(연쇄 깊이 1). 대화당 전달은 10번까지다. 실패한 턴 뒤 멈춘 대기열은
  사용자가 재개할 때까지 그대로이고, 팀 결과를 같은 팀에 되보내는 규칙은 만들 수 없다. 이미 끝나 있던 작업을 재연결 뒤 처음 본 경우에는
  이벤트를 내지 않는다.

## 11. 역할별 지식

- 엔진 자체의 기억 기능은 프로젝트 단위이고 기본 꺼짐이라 쓰지 않는다. 역할별 지식은 §9 지식에 그 역할을 체크한 것이다(역할 편집 창의 **지식**).
- 전달: POMP는 역할마다 체크된 지식의 쓰이는 내용을 `POMP_STATE_DIR/role-memory.json`
  (`{ "version": 1, "root": "<작업 영역>", "roles": { "<name>": [{ "title", "body" }] } }`, 역할당 최신 10개·8,000자, title = 지식 이름)에
  원자적으로 쓴다(지식이 바뀔 때와 작업 영역 변경 때). 확장은 하위 에이전트가 시작될 때 그 역할 이름의 항목을 시스템 프롬프트 뒤에
  `<role_memory role="…">` 블록으로 붙인다. 블록에는 참고 자료일 뿐 지시·도구 권한·승인·정책을 바꾸지 않는다고 적고, 내용 안의 태그는
  무력화한다. 파일이 없거나 손상됐거나 작업 영역이 다르면 붙이지 않는다(안전 장치가 아니라 참고 자료라서 실패해도 막지 않는다).

## 12. 루틴(파일 저장·빌드 때 규칙 실행)

- §10 이벤트 규칙에 IDE 이벤트를 더한다: `ide.saved`(파일 저장, `glob`으로 작업 영역 상대 경로를 거름, 기본 `**`, ≤ 200자),
  `ide.build.succeeded`, `ide.build.failed`. 출처는 "모두"뿐이다. 동작은 알림·전달(채팅) 그대로(전달 대상: 메인 대화·에이전트·팀).
- 이벤트 요약은 작업 영역 상대 경로 또는 빌드 결과(성공·실패)만 담는다(`<event_summary>` 데이터 블록). 파일 내용은 보내지 않는다.
- 안전장치(§10에 더함): 대화가 **쉬는 중일 때만** IDE 이벤트를 처리한다(에이전트가 고친 파일의 저장으로 다시 도는 고리를 막음). 규칙마다 60초가
  지나야 다시 보내고, 한 규칙이 보낸 메시지가 대기열에 있거나 실행 중이면 그 규칙은 기다리지 않고 건너뛴다. **이 대화에서 사용** 스위치·대화당 10번·
  연쇄 깊이 1·중복 제거는 그대로다.
- 자동화 규칙 표의 **스크립트** 항목(`.pomp/hooks` PowerShell 훅)은 바뀌지 않는다.

## 13. 격리 작업 트리

- 시작할 때 쓰는 설정에서 격리 작업을 켜고, 병합은 패치로, 적용은 끄고, 작업 트리 위치를
  작업 영역의 `.pomp\local\wt`로 둔다. 격리된 작업의 변경은 **적용하지 않고** 패치로만 남는다.
- 팀 파일의 선택 키 `isolation`(불리언, 기본 false). 켠 팀은 구성원마다 격리된 복사본에서 일한다(Git 저장소 필요, 저장되지 않은 변경도 복사됨).
  Git 저장소가 아닌 작업 영역에서는 보내기 전에 거부한다. 격리된 구성원은 나중에 이어서 쓸 수 없어서 격리 팀은 항상 새로 시작한다.
- 권한 가드: 작업 폴더가 작업 영역과 다르면 모든 도구를 막지만, 하위 에이전트가 POMP의 격리 폴더(`POMP_WORKTREE_BASE\<id>\m`) 안에서
  일할 때는 허용한다. 그때 프로젝트 정책은 복사본의 것이 아니라 작업 영역의 `.pomp/permissions.json`으로 판단한다(구성원이 복사본의 정책 파일을
  고쳐도 소용없음). 실제 VS에서 이 규칙이 없으면 격리 구성원의 모든 도구가 막히는 것을 확인하고 넣었다(2026-10-07).
- 확장: 격리 팀 안내에 "구성원 `task`는 `isolated: true`"를 넣는다. 도구 호출 가드는 격리 팀 실행이 아닌 턴의 `isolated` 요청과, 격리 팀 턴에서
  `isolated: true`가 없는 구성원 `task`를 이유와 함께 막는다(모델이 다시 호출).
- 결과 받기: 구성원이 끝나면 그 구성원 세션 파일 옆에 패치(`<세션 파일>.patch`)가 만들어진다. POMP는 그 패치를
  엄격하게 해석한다: 엄격한 UTF-8·≤ 2 MiB, 텍스트 추가·수정·삭제만(이름 바꾸기·복사·바이너리·`..`·드라이브·역슬래시·제어 문자 경로는 거부), 결과당
  파일 수 제한은 없다. 패치 경로는 Git 저장소 기준이라 저장소 루트로 풀고, 작업 영역(솔루션 폴더) 밖 파일이 하나라도 있으면 그 결과는 **막힘**으로 보인다.
  빈 패치는 "바꾼 파일 없음" 알림만 남긴다. 결과 수 제한은 없다. 메모리에 둔 패치가 합쳐 64 MiB를 넘으면 적용·실패한 오래된 결과부터 비우고, 그래도 넘치면 알림에 패치 경로만 남긴다.
- 검토·적용: 결과는 작업 탭 › 변경 › 대기 중의 **격리 실행 결과** 항목으로 기다린다(파일·종류·추가/삭제 줄 수·상태·이유, 적용·버리기·패치 열기).
  C# 셰도 검사가 있는 일반 변경 검토와 따로 둔다(그 검토는 열린 C# 문서만 다루는데 구성원은 다른 파일도 만들고 바꾸기 때문). **적용**은 프로젝트
  정책(`pomp_stage_workspace_edit` 도구 규칙)을 확인하고 승인 창(패치 내용 포함)을 연다. 저장하지 않은 편집기 변경이 있는 파일, UTF-8이 아닌 파일,
  있어야 할 파일이 없거나 새로 만들 파일이 이미 있으면 거부한다. 문맥이 정확히 맞지 않으면 거부한다(퍼지·3-way 없음). 승인 뒤 다시 계산해 그사이
  파일이 바뀌었으면 쓰지 않는다. 쓰기 전 내용은 체크포인트로 남아 변경 이력에서 되돌릴 수 있고, BOM과 줄 끝(CRLF/LF)은 원래대로 둔다.
  쓰는 중 실패하면 이미 쓴 파일을 되돌린다. 적용됐거나 실패한 결과는 최근 10개만 목록에 남는다. 버리기는 목록에서만 지우고 패치 파일은 남긴다.

## 14. 구성원 개별 중지

- 기본 기능에는 하위 에이전트 하나만 멈추는 방법이 없다.
- POMP 확장이 그 구성원만 멈춘다(그 세션을 중단하고 종료 표시로 놓아 주는 방식). 실제로 측정했고(2026-10-07) 다시 확인했다(2026-10-09): 메인
  대화가 응답 중이어도 바로 실행되며, 그 구성원만 "취소됨"으로 끝나고 다른 구성원은 계속되고, 메인 대화는 취소된 결과를 받아 이어 간다.
- 확장은 메인 대화에서만, 실행 중이고 메인 대화가 (직접 또는 다른 구성원을 거쳐) 시작한 구성원만 멈춘다. 결과는 알림으로
  POMP에 돌아가고 대화 기록에는 남지 않는다. 필요한 내부 기능이 없거나 모양이 다르면 아무것도 바꾸지 않고 "지원하지 않음"을 알린다.
- POMP는 이 기능을 쓸 수 있을 때만 켠다. 채팅의 작업 카드(에이전트·팀 대화 상대 탭에도 같은 카드)의 실행 중 구성원 줄에
  **중지**가 생기고, 그 줄에서 한 번 더 확인한 뒤 멈춘다. 쓸 수 없으면 버튼을 두지 않는다. 내부 동작에 기대므로 구성 요소를 올릴 때
  다시 측정한다.

## 15. 팀 템플릿 내보내기·가져오기

- 형식(≤ 256 KiB):
  `{ "format": "pomp-team-template", "version": 1, "team": { id, title, goal, members, mode, instructions, membersOnly, isolation },
  "roles": [{ name, title, job, description, instructions, model?, thinkingLevel?, tools }] }`.
  `roles`에는 팀이 쓰는 사용자 정의 역할만 넣고 엔진 내장 역할은 이름으로만 참조한다.
- 내보내기: 팀 카드의 **내보내기** → 글을 복사하거나 편집기에서 연다(`%LOCALAPPDATA%\Pomp\exports\`에 쓰고 VS로 열어 사용자가 원하는 곳에 저장).
- 가져오기: 붙여넣기 → 미리보기(팀과 역할마다 새로 만듦 / 같은 내용이 이미 있음 / 다른 내용과 이름이 겹침=거부) → 범위(이 프로젝트 / 내 모든 프로젝트)
  선택 → 가져오기. 새 파일만 만들고 덮어쓰지 않는다. 하나라도 실패하면 이번에 만든 파일을 지운다. 검증·한도는 §2·§3과 같다.
